# Typora 渲染对齐（2026-10-12）

用户要求：「**整套 Markdown 语法都对齐 Typora**」。这里放**对照测试集**与**结论** ——
以后每发现一条新差异，就补一个 case + 一行结论，别再从零测一遍。

## 怎么用

1. `tj-*.md` 是测试集（**48 个 case**，覆盖标题 / setext / 分隔线 / 强调 / 代码 / 链接 / 图片 /
   列表 / 引用 / 任务 / 表格 / HTML / 转义 / URL / 脚注 / 数学）。
2. 用 **Typora 打开**看渲染，再把文件拷进库用 **ZeroNote 打开**看渲染，逐条对照。
3. ZeroNote 侧的解析树可以离线拿，不用开 GUI：

   ```powershell
   node _research\typora-parity\parse-suite.mjs _research\typora-parity\tj-1.md
   ```

   ⚠️ 脚本里用的是 **`markdown({ base: markdownLanguage })`（GFM）** —— 必须与 `atomic` 一致
   （它 `AtomicCodeMirrorEditor.js:112` 就是这么建的）。用默认 `markdown()`（纯 CommonMark）
   会把"GFM 本来就支持"的表格 / 删除线 / 任务 / 自动链接**误报成差异**（踩过）。

## Typora 的规则（实测本机 Typora 1.14.10）

> **标记后面没有空格 ⇒ 一律当普通字符。**

推论（逐条实测）：

- `-` / `*` / `+`（**裸**）⇒ 字面，不是列表项
- `1.`（裸）⇒ 字面，不是有序列表项
- 段落下面一行只写**一个** `-` ⇒ 段落 + 字面 `-`（**不是** setext 标题）；`---` 则是标题
- `#` 裸 / `# `（空标题）⇒ 字面 `#`，**无标题样式**
- **其余全部一致**：斜体 / 粗体 / 三星号 / 下划线强调 / 删除线 / 行内代码 / 围栏代码 / 链接 /
  图片 / 自动链接 / 裸 URL / 表格 / 任务列表 / 列表（带空格）/ 嵌套列表 / 引用（含嵌套）/
  `***` 与 `___` / `--` 字面 / HTML 标签 / 反斜杠转义 / 未闭合强调 / 裸 `` ` ``·`**`·`[]`

## 差异清单与处理状态

| # | 场景 | Typora | 改前 ZeroNote | 处理 |
|---|---|---|---|---|
| 1 | `-`（裸） | 字面 | 圆点（空列表项） | ✅ 已对齐 |
| 2 | `*`（裸） | 字面 | 圆点 | ✅ 已对齐 |
| 3 | `+`（裸） | 字面 | 圆点 | ✅ 已对齐 |
| 4 | `1.`（裸） | 字面 | 编号 + 缩进 | ✅ 已对齐 |
| 5 | `1)`（裸） | 未测 | 编号 + 缩进 | ✅ 同 4（一条判据覆盖） |
| 6 | 段落 + 单个 `-` | 段落 + 字面 `-` | 整段变 setext H2 | ✅ 已对齐 |
| 7 | `#`（裸） | 字面 `#` | 空标题（大字号） | ✅ 已对齐 |
| 8 | `# `（空标题） | 字面 `#` | 空标题（大字号） | ✅ 已对齐 |
| 9 | 段落 + `---` | 大标题 | setext **H2** | ⚠️ **未核清**（Typora 视觉像 H1，CommonMark 是 H2） |
| 10 | 脚注 `[^1]` | 脚注 | 当引用式链接 | ❌ 功能没做（不是"对齐"问题） |
| 11 | 数学 `$x$` | 公式 | 纯文本 | ❌ 功能没做 |

**1–8 是同一条规则的推论**，所以实现上是**一条判据**（"标记后面是不是空格"），
落在 `patches/@atomic-editor__editor@0.6.2.patch`，三处：

1. 标题行 class（`LINE_CLASS_BY_BLOCK` 应用处）—— 空 ATX / 单个 `-` 的 setext 不给标题样式
2. 标题标记的隐藏（`HIDEABLE_SYNTAX` 处理处）—— 同上两种情况下**不隐藏** `#` / `-`
3. 列表标记（`ListMark` 处理）—— 标记后不是空格 ⇒ **不进渲染块**，标记原样显示

判据函数 `isBareHeadingForTypora()` 与三处 `PATCH(ZeroNote)` 注释都在补丁里。

## 为什么做不到"结构级"完全一致

Typora 的解析器是**闭源自研的**。要结构级一致 = 自己写一个 Typora 兼容的 Markdown 解析器
替换 Lezer（周级工作量，且要持续跟进 Typora 版本）。**渲染层补丁只能覆盖**
「从源码文本 + 解析树能判断出来」的差异 —— 1–8 都属于这一类。
