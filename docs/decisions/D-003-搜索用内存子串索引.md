# D-003 搜索用内存子串索引

> 状态：**accepted** ｜日期：2026-10-12 ｜重议条件：库 > 1 万篇，或单次查询 > 100 ms（用真实库测）

## 决定

自研纯内存子串索引（`src/kernel/index-api.ts`），零第三方依赖；不用 SQLite FTS5 / Tantivy / ripgrep。

## 理由（一手来源）

- 中文没有词边界，FTS5 的 tokenizer 对中文子串查询本来就要靠 LIKE 或 trigram 兜底 —— `index-api.ts` 文件头。
- 千篇 / 3 MB 语料实测毫秒级；真正的成本是 1000 次 `readText` 的 IPC 往返（按 8 篇一批并发读解决）。
- 上万篇再谈倒排/分片；现在上倒排是过早优化。

## 代价与边界

查询是 O(N·L) 最坏；每次重建要读全库（增量 upsert/remove 只重算一篇）。搜索筛选（正则/标签/目录）在 query 层做，不建二级索引。
