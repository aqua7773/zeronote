# D-009 做同步，但只做「用户自带后端」

> 状态：**accepted** ｜日期：2026-10-25（推翻 [D-002](D-002-不做云同步.md)）｜重议条件：出现「想要开箱即用的云端账号」的真实诉求，或冲突语义在真机上被证明不够用

## 背景

D-002（2026-10-17）定的是「不做账号 / 服务器 / 云同步，同步交给用户自己的网盘」。当时的顾虑是：引入同步 = 引入账号、鉴权、冲突合并、隐私边界四块新故障面，而「两台设备同时存」的语义根本还没定。

2026-10-24 用户拍板重新讨论同步（`docs/同步插件-调研与方案-2026-10-24.md`），并给出两个关键约束：**凭据走系统钥匙串**、**手机接受「前台近实时 + 切回追平」（不加前台服务）**。

## 决定

做同步，但**只做插件 + 用户自带后端**，不做账号、不做服务端、不做端到端加密：

1. **四种后端**：本地文件夹（`sync-folder`，库直接放同步目录，插件不搬文件）· WebDAV（`sync-webdav`）· S3 兼容（`sync-s3`）· Git（`sync-git`，GitHub / Gitea / Gitee 的 REST Contents API）。
2. **凭据不进库**：走 `host.secrets` → `tauri-plugin-keyring-store`（Windows 凭据管理器 / Android Keystore），`.zn/` 里不落明文。
3. **同步节奏**：插件**前台每 5 秒**同步一次 + `visibilitychange` 切回即补；不装前台服务、不做后台常驻。手机切到后台就停，切回追平。
4. **冲突语义**：先判「远端 / 本地 / 双端」；双端都改时用 `history` 的**同步点**做三方合并，**只有 0 处真冲突才自动合**；有真冲突 ⇒ **本机版留副本**（`.zn/conflicts/<平台>/`）+ 取远端版。
5. **权威索引**：网络后端以远端 `_zn/manifest.json` 为权威（fp + etag），不靠 list 全桶。

## 理由（一手来源）

- 产品定位的例外是可控的：没有账号、没有服务端、没有数据库，同步只是**把用户已有的存储当传输层**，隐私边界没有扩大（数据仍在用户自己的网盘 / 仓库 / 文件夹里）。
- 冲突语义在旧代码里其实已经存在：三方合并（`mergeLines`）原用于「磁盘变了 vs 内存脏了」，加一个**同步点**（`history` 的 `base.<后端>.sync.md`）就能覆盖「两台设备同时存」。
- 真机验收已经覆盖四个后端：WebDAV（坚果云，桌面 ↔ 云端 ↔ 手机双向 + 全自动 9 秒）· S3（`rclone serve s3` 带 SigV4 验签）· Git（真实 GitHub 私有仓库）· 本地文件夹（真实 Syncthing 2.1.7 两实例，`.sync-conflict` 文件触发三方合并成功）。详见 `HANDOFF.md` rev173.106–136。
- 凭据：`tauri-plugin-keyring-store 0.2`（桌面凭据管理器 / Android Keystore），`host.secrets` 原语在契约 §2.6.1。

## 代价与边界

- **没有开箱即用的同步**：用户必须自己有 WebDAV / S3 / Git 仓库，或自己装 Syncthing 这类工具。首次配置门槛比「登录一个账号」高。
- **没有后台同步**：手机切到后台就不同步，回到前台才追平（用户已接受）。
- **不做端到端加密**：数据在第三方存储上是明文（S3 / Git / 坚果云）。要加密需要另一条决策。
- **Gitee 分支未实测**（无账号令牌）；Cloudflare R2 / 真实 AWS 未实测（只有 rclone）。
- 每 5 秒一轮的轮询在长时间前台时是持续的磁盘 / 网络活动；静默空转轮不计入耗时历史（rev173.119），但功耗影响未量化。
