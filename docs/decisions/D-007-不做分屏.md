# D-007 不做分屏

> 状态：**accepted** ｜日期：2026-10-20 ｜重议条件：出现「同一屏内同时改两篇」的高频场景，或独立窗口并排明显碍事

## 背景

多标签页已做（rev173.50），分屏一直记为未做。桌面端已有「标签拖出 = 独立窗口」（rev173.51），两个真窗口可以并排。

## 决定

**不做应用内分屏。** 需要两篇并排时用 Windows 原生窗口并排。

## 理由（用户裁决 + 代码事实）

- **Windows 原生分屏够用**（用户 2026-10-20 原话「不做，windows原生分屏够用」）：标签拖出成独立窗口后，`Win+←/→`、拖到屏幕边缘、或 Snap Layouts 都能并排。
- **真分屏不是 UI 活**：整个文档会话是单份的 —— `content` / `dirty`（`src/App.tsx:162`）、`openNote` 的 `setContent + setActivePath`（`src/hooks/useDocSession.ts:95`）、`useDocIO` 的 refs（`src/hooks/useDocIO.ts:35`）、`docApi`、`editorRef` 全部只认一篇；分屏要把「当前文档」从单数改成「每 pane 一份、焦点决定当前」，牵动保存 / 三方合并 / 草稿快照 / `doc` 原语五条链路。
- **没有对应场景**：当前使用形态是速记 + 单篇写作，不是「对照两篇改」。

## 替代方案（用户自己就能做）

1. 标签右键「在新窗口打开」或把标签拖出窗口 → 得到第二个真窗口；
2. `Win + ←/→` 并排，或拖到屏幕边缘吸附。

## 代价与边界

- 并排的是两个**系统窗口**（各自标题栏），不是应用内分割条；
- 没有「把标签拖到另一半自动分屏」这个交互。
