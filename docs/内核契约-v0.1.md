# ZeroNote 内核契约 v0.1

> 日期 **2026-10-11** ｜ 状态：**草案，待用户过目** ｜ 上游文档：`_笔记应用选型\内核需求分析-v0.1.md`

## 0 三层结构

```
┌──────────────── 插件层（功能全在这）────────────────┐
│  灵感流 · Git 同步 · AI · 画布 · 标签 · 回收站 …      │
└──────────────────────┬──────────────────────────────┘
                       │  ← 只有这 8 个原语（本契约）
┌──────────────────────┴──────────────────────────────┐
│  内核 headless 核心：库 / 文件 / 文档 / 索引 / 事件   │
└──────────────────────┬──────────────────────────────┘
┌──────────────────────┴──────────────────────────────┐
│  默认壳：文件树 + 编辑器(CM6) + 设置页 + 命令面板     │
└─────────────────────────────────────────────────────┘
```

**术语**：**库**＝一个本地文件夹（里面全是 `.md`）｜**笔记**＝库里一个 `.md` 文件｜**插件**＝一个含 `manifest.json` + 入口脚本的目录｜**原语**＝内核暴露给插件的 API。

**ID 规则**：笔记 ID ＝ **库内相对路径**（`notes/2026-10-11/灵感.md`）。v0.2 引入独立 ID（满足「移动后引用不变」）。

## 1 数据面四原语

### 1.1 `fs` —— 文件读写（**所有写入必须原子**）

```ts
interface FsApi {
  vaultPath(): string;
  listNotes(dir?: string): Promise<NoteMeta[]>;      // 递归列 .md，跳过 .zn/ 私有目录
  readText(path: string): Promise<string>;           // 库内相对路径
  writeText(path: string, content: string): Promise<void>; // 临时文件 + rename，失败不破坏原文件
  createNote(path: string, content?: string): Promise<void>;
  rename(from: string, to: string): Promise<void>;
  delete(path: string): Promise<void>;               // 默认移入 .zn/trash/，不是物理删除
  exists(path: string): Promise<boolean>;
  watch(cb: (e: FsChange) => void): Disposable;      // 含外部编辑器改动
}
type NoteMeta = { path: string; title: string; mtime: number; size: number;
                  frontmatter: Record<string, unknown> };
type FsChange  = { kind: 'create'|'modify'|'delete'|'rename'; path: string };
```

**硬保证**：① 写入原子（temp + rename）② 失败绝不返回"已保存" ③ 磁盘上的 `.md` 是唯一真源，外部改动会被 `watch` 捕获。

### 1.2 `doc` —— 当前文档 / 选区

```ts
interface DocApi {
  active(): NoteDoc | null;
  open(path: string): Promise<void>;
  close(path?: string): void;
  save(path?: string): Promise<void>;
  selection(): { from: number; to: number; text: string } | null;
  replaceSelection(text: string): void;              // 编辑类的唯一入口
  insertAtCursor(text: string): void;
  on(ev: 'open'|'change'|'save'|'close', cb: (d: NoteDoc) => void): Disposable;
}
type NoteDoc = { path: string; content: string; frontmatter: Record<string, unknown>; dirty: boolean };
```

### 1.3 `index` —— 可删可重建的索引（SQLite FTS5）

```ts
interface IndexApi {
  query(q: string, opts?: { limit?: number; dir?: string }): Promise<SearchHit[]>;
  upsert(path: string, text: string): Promise<void>;
  remove(path: string): Promise<void>;
  rebuild(): Promise<{ count: number; ms: number }>;   // 删库重建后关系可恢复
}
type SearchHit = { path: string; title: string; excerpt: string; score: number };
```

要求：多关键词 **AND**、中文子串兜底、特殊字符不崩（对齐 F7）。

### 1.4 `event` —— 事件总线

```ts
interface EventApi {
  on(topic: string, cb: (payload: unknown) => void): Disposable;
  emit(topic: string, payload: unknown): void;       // 插件间通信用

```

**内核固定事件**（不改名）：
`app:ready` `app:quit` `vault:open` `note:created` `note:changed` `note:saved` `note:renamed` `note:deleted` `index:rebuilt`

### 2.1 `command` —— 命令 / 快捷键 / 命令面板

### 2.2 `view` —— 视图挂载（**声明式优先，风格统一**）

```ts
interface ViewApi {
  /** 主路：插件只「声明」界面，宿主用统一组件渲染 ⇒ 风格 100% 统一、框架无关 */
  registerPanel(spec: {
    id: string;
    title: string;
    icon?: string;
    location: 'sidebar' | 'main' | 'statusbar' | 'modal';
    render: (ctx: ViewCtx) => UINode;   // 纯函数，可被重复调用
  }): Disposable;

  /** 兜底：复杂交互（画布/自绘编辑器）走 WebView，宿主注入主题 token 保证风格一致 */
  registerWebView(spec: {
    id: string; title: string; location: 'sidebar' | 'main' | 'modal';
    url: string;                        // 插件目录内相对路径
  }): Disposable;

  /** 面板数据变了，请宿主重渲染 —— render 是纯函数，插件靠这个把新数据推上去 */
  refresh(panelId?: string): void;

  /** 写面板状态（输入框等 bind 值）→ 宿主重渲染。插件清空/预填输入框的标准做法 */
  setState(bind: string, value: unknown): void;
}

type UIGap  = 'sm' | 'md' | 'lg';
type UITone = 'default' | 'muted' | 'success' | 'warn' | 'danger';

type UINode =
  /* ── 布局 ── */
  | { type: 'stack';   children: UINode[]; gap?: UIGap }
  | { type: 'row';     children: UINode[]; gap?: UIGap; align?: 'start'|'center'|'end'; wrap?: boolean }
  | { type: 'divider' }
  | { type: 'spacer';  size?: UIGap }
  /* ── 文本 ── */
  | { type: 'text';    value: string; variant?: 'body'|'caption'|'title'; tone?: UITone }
  | { type: 'markdown'; value: string }
  | { type: 'code';    value: string; lang?: string }
  | { type: 'html';    value: string }                     // ⚠️ 富内容直投，见下
  | { type: 'link';    label?: string; onClick: string; payload?: Record<string, unknown> }
  /* ── 媒体 ── */
  | { type: 'image';   src: string; alt?: string; height?: number; fit?: 'contain'|'cover' }
  /* ── 交互 ── */
  | { type: 'button';  label: string; onClick: string; send?: string;
                       payload?: Record<string, unknown>;
                       variant?: 'default'|'ghost'|'danger'; disabled?: boolean }
  | { type: 'input';   bind: string; placeholder?: string; onSubmit?: string }
  | { type: 'textarea'; bind: string; placeholder?: string; rows?: number; onSubmit?: string }
  | { type: 'select';  bind: string; options: { value: string; label: string }[]; onSubmit?: string }
  | { type: 'checkbox'; bind: string; label?: string; onSubmit?: string }
  /* ── 数据展示 ── */
  | { type: 'list';    items: (UINode | { key: string; node: UINode })[]; empty?: string; onClick?: string }
  | { type: 'table';   columns: { key: string; label: string; width?: string; align?: 'left'|'right' }[];
                       rows: Record<string, UINode | string | number>[]; empty?: string }
  | { type: 'progress'; value: number; max?: number; label?: string }
  | { type: 'badge';   text: string; tone?: UITone }
  /* ── 表单 ── */
  | { type: 'field';   label: string; hint?: string; children: UINode }
  | { type: 'tabs';    bind: string; tabs: { key: string; label: string; node: UINode }[] };
```

> `onClick` / `onSubmit` 传的是**命令 id**（不传函数）⇒ 声明可序列化，便于将来跨进程/沙箱。
>
> **共 21 种节点**，够写出"记录 / 标签 / 搜索 / 图表 / 设置页 / 同步进度"这类完整功能。
> 三条使用要点：
> ① **只传语义档位**（`gap` / `tone` / `variant` / `align`）—— 不要传颜色或 px，
>    宿主会映射到 `--zn-*` token，这样换主题、切暗色自动跟随。
> ② `image.src` 指向**库内文件**时必须先过 `host.assetUrl(rel)`（相对路径直接塞 `<img>` 必然 404）；
>    `http(s):` / `data:` / `blob:` 原样传即可。
> ③ `list.items` **强烈建议给 `key`**（`{ key, node }`）：不带 key 时宿主只能用下标做 React key，
>    增删一项会让后面所有行错位（受控输入尤其明显）。旧写法（裸 UINode）仍兼容。
>
> ⚠️ **`html` 节点的风险**：宿主用 `dangerouslySetInnerHTML` 直投，插件（或它从 CDN 拉的库，
> 如 katex / mermaid）返回什么就渲染什么。v0.1 无沙箱、插件都是本机可信代码，故接受此取舍；
> **装第三方插件前请先读它的源码**。只想要代码块或纯文本时请用 `code` / `text`，别用它。
>
> 参考实现：`examples/ui-kit/` —— 把每一种节点都渲染一遍，既是示例也是渲染器的回归清单。

### 2.5 `service` —— 插件互调 / **前置插件**

```ts
interface ServiceApi {
  /** 提供一项服务。「前置插件」就是靠它 —— 名字建议带命名空间：`katex` / `git.commit` */
  provide<T>(name: string, factory: () => T | Promise<T>, opts?: { version?: string }): Disposable;
  /** 取服务（异步）。**没有就返回 null** —— 软依赖，不抛错、不阻塞加载 */
  consume<T = unknown>(name: string): Promise<T | null>;
  /** 当前已登记的服务（诊断面板/调试用） */
  list(): { name: string; pluginId: string; version?: string; loaded: boolean }[];
}
```

**为什么需要它**：`event` 是 fire-and-forget —— 没有返回值，也没有"对方在不在"。
「AI 插件调用 Git 插件的提交能力」这类需求，用事件只能靠全局变量 hack。

**「前置插件」是什么**：把**依赖环境本身**做成插件。内核只维护一张
`名字 → 懒工厂` 的表，**完全不认识** katex / mermaid / pdf / git 这些具体依赖 ——
于是"换一个公式渲染器"就是换一个插件，内核一行都不用改。

**三条刻意设计**：

| 设计 | 怎么做 | 为什么 |
|---|---|---|
| **懒工厂** | `provide` 只登记闭包；第一次 `consume` 才执行，结果缓存复用 | **按需激活**：没人用的前置插件，一次 import、一次网络请求都不会发生 |
| **软依赖** | `consume` 拿不到返回 `null`；不做拓扑排序、不拦加载 | 硬依赖会导致"一个前置装错版本，整个应用起不来"（VS Code `extensionDependencies` / SilverBullet `redirect` 同此取舍） |
| **工厂抛错不外抛** | 错误只写插件日志，`consume` 得到 `null` | 一个前置插件坏了，不该拖垮依赖它的插件 |

**加载顺序不保证**：晚到的消费者监听 `service:available`（负载 `{ name, pluginId }`）
补挂；提供者卸载时内核广播 `service:gone`，并**强制回收**它提供的服务
（不依赖插件自己 dispose —— 见 `Kernel.releaseServices`）。

**manifest 声明**：`dependencies: string[]`（只用于提示"缺前置"，不参与调度）。

**示例**：`examples/dep-katex/`（提供 katex，懒加载 CDN）·
`examples/dep-consumer/`（软依赖 + 降级显示 + 等事件补挂）。

### 2.6 `editor` —— 编辑器的**声明式标记规则**

```ts
type EditorMarkRule = {
  id: string;
  pattern: string;              // 正则源（字符串）—— 宿主自动补 g
  flags?: string;
  className?: 'link' | 'tag' | 'code' | 'highlight' | 'muted';
  onClick?: string;             // 点击时执行的命令 id（payload: { text, from }）
  title?: string;
};

interface EditorApi {
  addMark(rule: EditorMarkRule): Disposable;
  list(): { id: string; pluginId: string }[];
}
```

**它解决什么**：`[[文件名]]` 引用与跳转、`#标签` 着色、`==高亮==` 这类
**编辑器里的行内增强**。此前插件完全够不到编辑器内部（只有 `doc` 的读写与选区），
规格 §2.2 的"`[[文件名]]` 笔记引用与跳转"因此做不出来。

**为什么不让插件直接给 CM6 的 `Extension`**：
① 它是宿主依赖里的**类实例**，而插件代码是字符串（将来还要进 Worker / iframe 沙箱）—— 塞不进来；
② 一旦暴露，插件就能把编辑器改成任意样子 ⇒ 声明式主路又被绕过（§7 一直在防这件事）。
所以插件只交**可序列化规则**（正则字符串 + 语义档位 + 命令 id），
翻译成装饰器、把点击换算成文档偏移，这两件事留在宿主。

**边界（如实标注）**：

- 规则在**编辑器挂载 / 切换笔记**时被读取 ⇒ 插件要在 `apply()` 里登记；
  之后新增的规则得等下次打开笔记才可见
- **重叠匹配先到先得**：前一条规则吃掉的区间，后面的规则不再着色
- 只做**行内标记**，不改变编辑行为（不能拦截输入、不能换语言、不能加 gutter）
- 正则每次文档变化重扫全文 —— KB 级文本是微秒级（与 `index` 同一取舍，不做增量）

**示例**：`examples/editor-marks/`（`[[笔记名]]` 可点跳转 + `#标签` 着色）。

## 3 插件 manifest

```json
{
  "manifestVersion": 1,
  "id": "inspiration-flow",
  "name": "灵感流",
  "version": "0.1.0",
  "apiVersion": "^0.1.0",
  "entry": "index.js",
  "platforms": ["desktop", "android"],
  "description": "快速捕捉，一次发送 = 一篇独立 .md 落当日目录",
  "capabilities": ["fs:read", "fs:write", "doc:read", "command", "view:sidebar", "store"],
  "activationEvents": ["onStartup"],
  "contributes": {
    "commands": [{ "id": "inspiration-flow.capture", "title": "捕捉灵感", "keybinding": "Mod+Shift+I" }],
    "panels":   [{ "id": "inspiration-flow.stream", "title": "灵感流", "location": "main" }]
  }
}
```

**加载规则**：① `apiVersion` 与内核不匹配 → 拒绝加载并给出人话原因 ② 声明了未授权 capability → 拒绝 ③ 插件抛异常 → 只卸载该插件，内核继续跑 ④ `entry` 与 `styles` 至少要有一个。

### 3.0 懒激活（`activationEvents`）

**不写这个字段 ⇒ 老行为**：库一打开就 `apply()`（现有插件零影响）。
**写了 ⇒ 分两步走**：

```
① 宿主只读 manifest：把 contributes.commands 静态登记进命令表
   ⇒ 命令面板/快捷键**不用加载插件**就能列出它
② 用户真的触发那条命令 ⇒ 宿主发现它没有实现 ⇒ 激活该插件 ⇒ apply()
   ⇒ 插件用 **bind(id, run)** 补上实现（不是 register！）
```

| 触发条件 | 含义 |
|---|---|
| 不写 / `onStartup` / `onVaultOpen` | 库打开即激活（旧行为） |
| `onCommand:<命令 id>` | **那条命令被执行时**才激活 |
| `onView:<面板 id>` | 面板被打开时激活（v0.1 只登记类型，宿主暂按启动处理） |

**为什么必须用 `bind` 而不是 `register`**：`register` 会连同元数据一起登记，
而元数据已经被静态声明占了 ⇒ **id 冲突**、插件加载失败。
`bind` 只补实现，元数据保持不动。

**示例**：`examples/lazy-demo/` —— 它的 `apply()` 里有一句 `host.log`，
打开命令面板时日志里没有、点过命令后才出现，这就是懒激活的直接证据。

### 3.1 入口形态（宿主按内容嗅探，四种都吃）

插件生态里的入口写法不止一种，宿主**不要求作者改代码**，按源码内容自动判断：

| 形态 | 判定依据 | 典型来源 |
|---|---|---|
| **ESM** | 有静态 `import` / `export` | 契约标准写法 |
| **CommonJS** | 出现 `module.exports` 或 `exports.x` | Lumina-Note：`module.exports = function (api) {}` |
| **全局注册** | 出现 `registerPlugin(` | Yank Note：`window.registerPlugin({name, register})` |
| **纯样式** | 没有 `entry`，只有 `styles` | 主题类插件不必写 JS |

导出形状也做归一，四种都认：`export default { apply }` · `export function apply` ·
`module.exports = function` · `registerPlugin({ register })`。

### 3.2 多文件插件（`files`）

```json
{ "entry": "index.js", "files": ["lib/greet.js", "lib/counter.js"] }
```

`files` 里声明的文件会被宿主一并读出，与入口一起装进一个**极简的 CommonJS 运行时**
（约 40 行），`require('./lib/x.js')` 因此可用 —— v0.1 的「只能单文件」限制解除。

解析规则：相对 `require` 的基准是**当前文件所在目录**；按 `spec` → `spec + '.js'` →
`spec + '/index.js'` 依次试探；找不到时报明确错误并提示去 `manifest.files` 里声明。

> ⚠️ **只有 CommonJS 的 `require` 能被解析**。ESM 的相对导入在 Blob 里没有 base 目录，
> 需要打包器才能展开 —— 不在 v0.1 范围内。多文件插件请按 CJS 写，或自行打成单文件 ESM。

### 3.3 纯样式插件

只声明 `styles` 即可（`capabilities` 可为空数组）：宿主把 CSS 注入 `<head>`，
卸载时整块移除。改的是内核既有的 `--zn-*` token，因此不必碰任何组件。
参考实现：`examples/theme-sepia/`。

| `store` | 自己的持久化 | 需声明 |
| `net` | 访问网络 | **默认拒**（用户逐个授权） |
| `proc` | 起子进程（复用别人 CLI/server 用） | **v0.2，默认拒** |

> ⚠️ **M2 阶段没有沙箱**：capability 是**接口可见性**，**不是安全边界**。
> 进程内插件与内核跑在同一个 JS 上下文里 —— 一个 `while(true)` 会卡死整个应用。
> 沙箱（Worker + 内存/时长上限）排在 v0.2。**装插件前先问自己：这个插件是谁写的。**

---

## 5 版本与兼容承诺

1. 契约走 **semver**；插件用 `apiVersion` 声明范围
2. **同一 major 内，插件不改代码必须仍可用**（内核负责兼容）
3. 每次改契约 → 必须同步改本文件 + 升 minor，并在 `CHANGELOG` 记一条
4. 内核加载插件前校验版本，不匹配要**说人话**（不是抛栈）

## 6 分阶段实现范围

| 阶段 | 实现的原语 | 验收 |
|---|---|---|
| **M1** 桌面骨架 | `fs` `doc`（+ 内置树/编辑器/设置/命令面板，**不加载插件**） | 打开文件夹 → 编辑 → 保存，磁盘上看到自己的 `.md` 被改 |
| **M2** 插件系统 | `host` `command` `view` `store` `event`（**进程内 TS 插件**） | 装上示例插件 → 命令出现、面板出现；卸下 → 全部消失、无残留 |
| **M3** Android | 同上，跑在真机 | 真机开库 → 编辑 → 保存 |
| v0.2 | `index` + Worker / WebView / 子进程宿主 | 搜索多关键词 AND；子进程插件跑通 |

## 7 本版未决（不阻塞 M1）

1. `rename` / `delete` 的**引用重写**（`[[链接]]`、附件路径）规则
2. 独立笔记 ID（v0.2）
3. 插件间依赖与加载顺序
4. 插件签名与分发（第一版只支持本地目录）
5. 移动端专属的视图位置（底栏 tab 归属哪个 location）

> 下面 6–9 来自插件 API 横向调研（报告：`_research\插件API对比.md`，535 行，六家带证据对比）。
> 都**不进 v0.1**（成本 vs 收益不划算），先记录，免得以后忘。

6. **权限指纹**：授权记录绑定 `SHA256(id + version + contentHash)` —— 否则插件升一版就能悄悄扩大权限。
   v0.1 的「net 默认拒」是一次性开关。（NoteGen 已这么做：`PluginPermissionGrant.manifestFingerprint`）
7. **命令改静态声明**：manifest 里声明命令元数据，运行时只 `bind(id, fn)`。
   现在 `register({id,title,run})` 意味着「命令面板要列出命令 = 先把所有插件全量激活」。
8. `service.provide` / `service.consume`（插件间**带返回值**的互调）；`UINode` 补 `table` / `progress` / `badge`。
9. `registerWebView` 补三件套：**主题 token 注入** + 能力通道 + CSP 模板与 `sandbox="allow-scripts"`。
   缺了第一件，WebView 里的插件会写死颜色 —— 兜底路必然破坏「风格统一」。

> **调研给的一条反直觉结论**（值得记住）："声明式 schema 由宿主渲染"在六家成熟项目里**没有对等先例**
> （最接近的只有 VS Code `contributes.views` 与 SilverBullet `codeWidget`）。
> 风险：一旦 `UINode` 表达力不够，插件会集体转投 WebView，主路被架空。
> ⇒ 对策：**第一批真插件（灵感流）必须用 `UINode` 写完**，不许用 WebView 绕过 —— 这是对主路的压力测试。
