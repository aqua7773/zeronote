## 0. 键位裁决（可直接照抄）

| 功能 | 键位 | 依据 |
|---|---|---|
| 新建笔记 | `Ctrl+N` | Obsidian / Typora / VS Code 官方 |
| 保存 | `Ctrl+S`（自动保存产品也要响应，给「已保存」轻反馈） | VS Code / Typora 官方 |
| 本笔记查找 | `Ctrl+F` | 四家全一致，**无例外** |
| 本笔记替换 | `Ctrl+H`（mac 用 `Cmd+Opt+F`，**不要 `Cmd+H`**） | Obsidian / Typora / VS Code |
| 全库搜索 | `Ctrl+Shift+F` | Obsidian / VS Code |
| 快速打开笔记 | `Ctrl+O` | Obsidian Quick switcher |
| **命令面板** | **`Ctrl+P`（不要 `Ctrl+K`）** | `Ctrl+K` 在 Typora/Bear/Obsidian 是**插入链接** |
| 关闭当前笔记 | `Ctrl+W` | Typora / VS Code；Obsidian 社区证据 |
| 重命名 | `F2`（+ 双击 + 右键） | Obsidian 官方；Windows 惯例 |
| 删除 | 右键菜单；**默认入回收站且不弹确认** | Obsidian 三种策略；Apple HIG |
| 粘贴为纯文本 | `Ctrl+Shift+V` | Obsidian / Typora 一致 |
| **侧栏切换** | **不要 `Ctrl+B`**（那是加粗）；用 `Ctrl+\` | VS Code 用 Ctrl+B，但笔记应用必须留给加粗 |

**不可自定义的底层键**（Obsidian 明说由系统/框架提供）：`Ctrl+Z/Shift+Z`、`Ctrl+A/X/C/V`、`Ctrl+Shift+K` 删行。

## 1. 文件树 / 笔记列表

- **新建**：Obsidian 在树顶部（点后**先输入名字**再进编辑）；`Ctrl+O` 里输入不存在的名字按 Enter 直接创建。树内新建建议**先命名**，避免一堆 `untitled`
- **重命名**：`F2` / 双击 / 右键三入口，行内改名；**重名要就地内联报错**（不夺焦不弹窗）
- **删除策略**（Obsidian 官方三档 + Apple HIG 判定）：
  - 常见且可撤销的破坏操作**不要弹窗** —— 用户删文件本来就是想丢，且能撤销
  - **只有不可逆操作才弹窗**，且初始焦点落在最不具破坏性的操作上（W3C APG）
  - 回收站页要能**一键还原 + 显示删除时间**
- **右键菜单标准清单**（Obsidian 官方，取对我们有用的）：打开 / 在系统中显示 / 复制路径 / **重命名** / 移动到… / 复制 / **删除**
- **拖拽**：Obsidian 把文件拖进文件夹=移动；**文件树不做手动拖拽排序**（文件系统才是真源）
- **排序**：按钮放树上方（名称/修改时间/创建时间，各可升降）；**树上方不放常驻过滤框**（过滤交给 `Ctrl+O` 与 `Ctrl+Shift+F`）

## 2. 编辑器交互

### 自动保存（VS Code 官方 + Obsidian File recovery）
- 默认应为**显式保存**；自动保存可选 `afterDelay`（默认 1000ms）/ `onFocusChange` / `onWindowChange`
- **Hot Exit**：意外退出后未保存内容可恢复
- **File recovery 快照**：Obsidian 默认快照间隔 ≥5 分钟、保留 7 天，可看 diff、可整体恢复
- **建议三件套**：失焦/切换/关窗**立即 flush** + **崩溃恢复** + **定期快照**

### 撤销 / 重做（CodeMirror 官方论坛，关键）
- CM6 里**历史是 EditorState 的一部分**，没有 `setHistory/clearHistory`；作者明确建议**整个 state 存取**
- 结论：**每笔记独立撤销栈必须 app 层显式做**，否则切笔记会重置或串味

### 查找替换
- 做「本笔记 `Ctrl+F`/`Ctrl+H`」即可（含 Replace all、Find all）
- VS Code 值得抄：**打开查找时用选中文本预填**、查找历史跨重启保留、Match case
- **跨库替换不做**（本地文件直接落盘，误替换不可逆；Obsidian 也不做）

### 光标与滚动位置记忆
- **VS Code 默认做**（社区甚至要问"怎么关掉"）；**Obsidian 原生不做**，靠插件补 —— 说明是真实痛点
- 低成本高感知，**建议必做**：每笔记记「光标 offset + 滚动位置」，切走再切回恢复

### frontmatter
- Obsidian 升级为 **Properties**：顶部渲染可编辑属性行，`Ctrl+;` 新增，三态显示（Visible / Hidden / Source）
- 建议：Live Preview 下渲染成**可折叠属性卡片**，保留切源码的逃生口

## 3. 空态 / 加载态 / 错误态（NN/g 官方指南）

**空态三原则**：① 传达系统状态（别让用户猜"没内容/加载中/出错"）② 给学习线索（就地教学）③ 给直达关键任务的路径

**加载态**：`<1s` 不要任何指示（闪一下反而糟）；`2–10s` 骨架屏或 spinner；`>10s` 进度条 + 时长估计。**禁止**先显示空态文案再填内容。

**错误态**：靠近错误源头、不只靠颜色、说清具体问题 + **给可执行补救**、不指责用户、不过早报错；Apple HIG 明确**不要在启动时弹警告**。

四种文案模板：
1. 读不到：「无法打开 xxx.md：文件已被移动或删除。」[重新扫描库] [在系统中显示]
2. 写失败：「保存失败：磁盘可能已满或被占用。内容已保留在本地缓存。」[重试] [另存为]
3. 库打不开：「这个文件夹无法作为笔记库：没有读写权限。」[换一个文件夹]
4. 重名：「已存在同名笔记。」（内联红字，不弹窗）

## 4. 键盘可达性

- **焦点圈**（WCAG 2.4.13）：≥2px 实线 outline，聚焦/未聚焦**对比度变化 ≥3:1**；用 **`:focus-visible`**（鼠标点击不给圈）
- **重要例外**：**大型编辑区域不算 UI component**，不要求画焦点圈，但必须有插入光标
- **Tab 顺序**：`☰ → 标题栏按钮 → 侧栏树 → 编辑器 → 状态栏`；避免 `tabindex > 0`
- 树建议 **roving tabindex**（上下移动 / 左右折叠 / Enter 打开 / F2 重命名 / Delete 删除）
- 模态必须**焦点陷阱**，关闭后**焦点回到触发元素**
- **Esc 分层**（从内到外，一次吃一层）：① 行内控件（重命名框）→ 取消还原 ② 查找条 → 关闭 ③ 浮层 → 关闭最上层 ④ 普通编辑态 → 清选区（**不要用 Esc 关笔记或退应用**）

## 5. 不适用（附理由）

| 不做 | 理由 |
|---|---|
| 跨库全局替换 | 本地文件直接落盘，误替换不可逆 |
| 文件树拖拽手动排序 | 文件系统才是真源，手动序会与排序规则打架 |
| 标签页/分屏键位 | 当前是单笔记视图 + 插件面板，无多标签模型 |
| `Ctrl+B` 切侧栏 | 笔记应用里 `Ctrl+B` 必须留给加粗 |
| 为 <1s 的操作加骨架屏 | 会闪，反而降低感知性能 |
| `Esc` 关闭笔记/退出应用 | 与"Esc 逐层退出"心智冲突，且与 `Ctrl+W` 职责重复 |
| 常驻「保存」按钮 | 自动保存下永远可点，制造"没保存"错觉 |
