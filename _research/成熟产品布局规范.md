# 成熟笔记/编辑器应用布局规范（调研）

> 状态：**historical**（调研快照，带日期）｜最后核对：2026-10-17 ｜说明：结论按当时实测；引用前先看日期

> 调研时间：2026-10-11 ｜ 用途：为 ZeroNote 的 UI 布局定基准
> 方法：查官方文档 / 官方主题源码 / 官方仓库 CSS / 社区讨论，逐条附来源

## 0. 三条最关键结论

1. **正文主流是「居中限宽」**（Obsidian / Typora / Logseq / Notion 全部）——全宽只作可选模式，从不默认。
   ZeroNote 最终**没采用**这条：用户明确要「动态变化、四周留边界」（编辑器式占满），以用户要求为准。
   → 若将来要加，把它做成**可选档位**即可（`--zn-editor-pad-*` token 已就位）。
2. **折叠侧栏后正文重新居中、限宽值不变**是主流行为；Logseq 不跟随已被用户当 bug 抱怨。
   **判据：折叠前后左留白 == 右留白必须恒成立。**
3. **宽度用 px 不用 ch** —— ch 依赖 "0" 字宽，中英混排下每行字数漂移大（70ch ≈ 560–640px，偏窄）。

## 1. 六个产品的布局事实

| 产品 | 结构 | 正文宽度 | 折叠侧栏后 | 状态栏 |
|---|---|---|---|---|
| **Obsidian** | 左侧竖排 ribbon（左栏折叠后仍可见）+ 左右侧栏（可折叠、含 tab group）+ 中央 tab group + 右下状态栏 | 设置项 **Readable line length**（默认开）；CSS 变量 `--file-line-width` **默认 700px**，可按笔记覆盖 900/1200/100% | 重新居中（限宽不变） | 右下角小字：反向链接数、编辑模式、字数；Sync 项可点开日志 |
| **Typora** | 可折叠文件树侧栏 + 单文档正文 | `#write` **860px 居中**；≥1400px→1024px、≥1800px→1200px | 重新居中于剩余宽度 | 无独立状态栏 |
| **Notion** | 可折叠左边栏 + topbar + 居中正文 | 居中限宽约 **900px**；每页 **Full width** 开关；专注模式 topbar 淡出 | 重新占满并居中 | 弱 |
| **Logseq** | 左栏 + 主内容列 + 右侧栏（可折叠可拖） | `--ls-main-content-max-with: 680px`（旧 640px）；全宽 `max-width:100vw`；T W/T L/T R | **不自动跟随**（缺陷） | 无 |
| **VS Code**（IDE 参照） | Activity Bar **48px** → Side Bar **默认 300px**（最小 170）→ Editor（弹性吸收）→ Panel **300px 高**；自定义标题栏 ~30px | 不限宽（代码场景） | 编辑器吃满，不重新居中 | **22px 高 / 12px 字号** |
| **Bear** | 侧栏 + 正文 | **「行宽」是偏好设置里的一等滑杆**（字体/字号/行高/行宽/段间距/缩进） | — | — |

## 2. 自绘标题栏（Tauri `decorations: false`）

- **高度 32px**（含搜索框/头像则 48px）
- **图标 16×16，距左边框 16px**，垂直居中（32px 高 → 上下各 8px）；**标题距图标 16px**
- **窗口按钮**：官方态度是"系统保留区由系统给"（宽取 `RightInset/LeftInset`、高取 `Height`），该区域**不得放期望可交互的 UI**。Windows 11 / 100% DPI 常见实测值：**每按钮 46×32px，三按钮合计 ≈138px**（46/138 是工程惯例，官方只明文规定 32px 高）
- **☰ 菜单放全局导航/布局控制**，不放文档操作：VS Code 的 Layout Controls（侧栏/面板/全屏/Zen）、Notion 的侧栏开关、Obsidian 的 ribbon（库切换/帮助/设置，可隐藏）。重命名/删除/导出走右键菜单或命令面板
- **文件名位置**：Windows 规范是"图标 + 标题靠左"；VS Code 放标题栏中央命令中心。**二选一，别既居中又靠左**
- 别漏的窗口行为：空白可拖、双击最大化、右键系统菜单、**按钮区排除出拖动区**、失活时降透明度
- ⚠️ Tauri 官方教程的示例是 **30px 高 / 30px 方形按钮** —— 那是跨平台最小示例（偏 macOS），**不是 Windows 规范**

## 3. 空态与状态栏

- **空态**（Obsidian 最贴合笔记应用）：编辑区中央卡片，文案 "No file is open"，三个动作 **Create new note / Go to file / See recent files**；空态卡片**不受阅读限宽约束**，可放宽到 900–1100px
- **VS Code 的空编辑器**是另一种范式：直接列快捷键（教用户怎么开始）
- **状态栏**：**22–24px 高 / 12px 字号**、padding 5px、项间距 3px
  - 该放：当前文档即时信息（字数/保存状态/同步状态）+ 库/环境状态（库路径/索引状态）+ 少量可点入口
  - **不该放**：配置类计数（如"插件 0/0"）——那是设置页信息，放状态栏是噪音

## 5. 对 ZeroNote 的建议

**照做**
1. 状态栏降到 22–24px / 12px；左放统计、右放保存状态与库路径；**"插件 0/0" 移到设置页**
2. 标题栏对齐 Windows 规范：32px 高、图标距左 16px、标题距图标 16px、右侧按钮 46×32、预留 ~138px、按钮区不设拖动区
3. 空态做成"最近 + 新建 + 打开"三动作卡（列宽放宽到 900–1100px）

**调整**
1. `70ch` 改 px 档位（ZeroNote 现按用户要求改成"占满 + 四周留白"，不再限宽）
2. 「插件管理独立页」——成熟产品主区永远留给文档（设置/插件管理放模态）；**ZeroNote 按用户要求保留主区页面**
3. **侧栏折叠按钮与 ☰ 别功能重叠**（留一个就够）

**不要照抄**
- VS Code 的正文不限宽（代码场景）
- Notion 的全宽优先作为默认
- Logseq 的"折叠侧栏后宽度不跟随"
- Tauri 官方示例的 30px 方形窗口按钮

## 6. 未验证项（别当结论用）

- "46px/按钮、138px 合计"是工程惯例；微软官方明文只有 32px 标准高、48px（含搜索）和"用系统 `RightInset`/`Height`"
- Craft 正文宽度、Apple Notes 具体栏宽未取到官方数值
- Obsidian/Typora 折叠后"重新居中"由其居中容器 CSS 结构推得，官方未逐字写明
