## 0 一句话结论

**一条规则管所有文件**：≤ 1 MiB 复制进库，> 1 MiB 只记路径；图片额外给「压到 1 MiB 以下再入库」的开关。
笔记里永远只写一条路径，渲染层按扩展名决定显示成图片 / 音频 / 视频 / 文件卡片；被引用的库外文件登记进**引用台账**，同步时才搬运。

阈值统一带来一个自洽：**压缩的目标就是「降到我愿意复制入库的阈值以下」**，所以压缩后必然走引入路径，不存在「压缩了却仍然引用」的怪状态。

## 1 规则表

| 文件 | 大小 | 落点 | 笔记里写什么 |
|---|---|---|---|
| 任意附件 | ≤ 1 MiB | 复制到笔记同目录 | `![](相对路径)` |
| 任意附件 | > 1 MiB | **不复制** | 绝对路径 |
| 图片 · 模式 A（默认） | ≤ 1 MiB | 复制原图 —— **预览就是原图、点开也是原图** | 相对路径 |
| 图片 · 模式 A（默认） | > 1 MiB | 引用原图（不复制）+ **生成预览图入库** | 绝对路径（预览图另有相对路径） |
| 图片 · 模式 B | 任意 | 压到 ≤ 1 MiB 后复制，**正文与点开默认都是压缩版** | 相对路径（压缩版） |
| 图片 · 模式 B | 任意 | 原图路径记进台账 + 提供「同步原图」 | 台账里，不进正文 |

判定顺序（伪代码，实现时照抄）：

```js
if (isImage(file) && mode === 'compress') {
  const out = compressToUnder1MB(file)        // 目标 = 引入阈值，天然 ≤1 MiB
  copyIntoVault(out); write(relPath(out))
  ledger.record({ original: file, stored: relPath(out) })
} else {
  if (size(file) <= 1 * 1024 * 1024) {
    copyIntoVault(file); write(relPath(file))
  } else {
    write(absPath(file)); ledger.record({ original: file })
  }
}
```

## 2 图片的两种模式

| 模式 | 行为 | 默认 |
|---|---|---|
| **A 引入原图** | ≤1 MiB：复制原图（**预览=原图、点开=原图**）；>1 MiB：引用原图 + 生成预览图 | ✅ 默认 |
| **B 引入压缩预览图** | 压到 ≤1 MiB 作为**正式版本**入库；**正文与点开默认都是压缩版**；另给「同步原图」入口 | 可选 |

压缩参数（实现时按此，实测可调）：
- 先降质量：0.85 → 0.7 → 0.6，直到 ≤1 MiB
- 还不够再缩长边：最长边 2560 → 1920 → 1280
- **GIF 不压**（动图压缩会丢帧或变静图）→ 按 A 模式规则处理
- PNG 带透明：优先 WebP / 保留 PNG 但降色深，不做「透明变黑」

**模式 B 的原图与「升级」路径**：原图不复制进库，路径进台账。正文与点开**默认都是压缩版**；笔记里提供「同步原图」——
主动同步成功后，点开**默认改看原图**（台账记 `originalLocal`）。不同步也能正常用：压缩版是正式版本，原图是可选的「高清补充」。

## 3 渲染 / 存储分工

| 层 | 职责 | 不做什么 |
|---|---|---|
| 渲染层（编辑器 / 预览） | 把路径变成能看的东西：库内相对路径 → `convertFileSrc(vault + rel)`；库外绝对路径 → `convertFileSrc(abs)`；按扩展名选 `<img>` / `<audio>` / `<video>` / 文件卡片 | 不判断「该不该复制」 |
| 存储层（内核 `import_attachment`） | 按 §1 规则决定复制或只记路径；写台账 | 不做压缩之外的格式转换 |

「只负责渲染、不负责存储」= 渲染组件不认识「引入 / 引用」这个概念，它只看到一条路径。

## 4 引用台账 `<库>/.zn/assets/manifest.json`

```json
{
  "version": 1,
  "entries": [
    {
      "id": "sha256:9f2c…",
      "original": "D:/Music/专辑/a.mp3",
      "size": 5242880,
      "storedInVault": null,
      "devices": { "aqua-pc": "D:/Music/专辑/a.mp3", "phone": null }
    }
  ]
}
```

- **为什么必须有**：笔记里写死 `D:\Music\a.mp3`，换一台设备就是坏链接。台账把「文件身份（哈希）」和「每台设备的本地路径」分开存。
- **位置**：`.zn/` 默认被同步工具整目录排除（`examples/sync-folder/index.js:42`）⇒ 台账放 `.zn/assets/` 需要在同步插件的放行清单里**显式加一条**（与 `secrets/security/private` 同一套机制）。
- 文件被删 / 移动时：台账条目保留，渲染时明确提示「文件已不在 <路径>」，**不静默显示破图**。

## 5 同步流程（用户定的链路）

`本地 → 云端临时 → 另一端本地同步完成 → 引用本地原文件 → 云端删除`

状态机：`local` → `staged`（已上传临时区）→ `landed`（对端已落地并改写引用）→ `cleaned`（云端临时文件已删）

**触发方式：用户主动调用 + 每次确认**（2026-10-28 用户定）。三个入口：

| 入口 | 何时出现 | 确认文案 |
|---|---|---|
| 笔记里点音频 / 视频（原文件不在本机） | 播放器位置显示「原文件不在本机 · 同步」 | 「即将同步大文件「a.mp4」（52 MiB），继续？」 |
| 模式 B 图片的「同步原图」 | 点开图片的浮层里 | 同上 |
| 附件面板「同步到其他设备」 | 面板列出待搬清单 | 「即将同步 N 个文件，共 X MB，继续？」 |

确认后才开始搬。启动 / 保存 / 定时 / 打开笔记都**不自动搬**。

1. 本地扫台账：找出 `devices[本机] != null` 且 `devices[对端] == null` 的条目
2. 上传到 `<云端>/.zn-asset-staging/<hash>/<文件名>`
3. 对端拉清单 → 下载到暂存目录 → 校验 sha256
4. 对端写 `devices[对端] = <落地路径>` → 改写笔记里的引用为对端路径
5. 删除云端 `<hash>/` 目录（**只在 landed 之后删**，否则对端还没拿到）

| 后端 | 做不做 | 理由 |
|---|---|---|
| 本地同步文件夹 | ✅ 先做 | 无依赖、可测 |
| WebDAV | ✅ 第二个 | 有临时目录概念 |
| S3 | ⏳ 次之 | 同理，但配置成本高 |
| Git（sync-git） | ❌ 不做 | 大文件会炸历史，且 git 没有「临时区」语义 |

失败处理：源文件不存在 → **明确报错**，不静默；对端磁盘不够 / 同名冲突 → 提示用户选「覆盖 / 改名 / 跳过」。

## 6 已定（2026-10-28 用户拍板）

1. **阈值口径**：`1 MiB = 1,048,576` 字节，与系统文件属性一致。
2. **显示策略**：
   - **A**：≤1 MiB 原图复制进库 —— **预览就是原图、点开也是原图**；>1 MiB 引用原图 + 生成预览图，点开看原图，原图不在本机时显示预览 + 角标「原图未同步」。
   - **B**：正文与点开**默认都是压缩版**；提供「同步原图」，主动同步成功后**点开默认显示原图**。
3. **落地目录**：`<库>/.zn/assets/external/`；**不主动同步这些大文件** —— 触发点是「笔记里点音频/视频」「图片的同步原图」「附件面板」（见 §5），且每次触发前都要确认。

## 7 分期（每期可独立验收）

| 期 | 内容 | 验收判据 |
|---|---|---|
| **1** | 规则 + 阈值判断 + 台账骨架（只记不搬） | 插 2 MiB 附件 → 不复制、写绝对路径、台账有条目；插 800 KiB 附件 → 复制；单测覆盖阈值边界（1 MiB ± 1 字节） |
| **2** | 图片两模式 + 压缩 | 10 MiB 图 → 模式 A 引用原图（≤1 MiB 的则直接复制原图）；模式 B → ≤1 MiB 入库且肉眼可辨；GIF 走 A |
| **3** | 渲染：库外路径能显示（图片 / 音频 / 视频 / 文件卡片） | 本地绝对路径的视频能在正文内联播放；文件不存在时明确提示 |
| **4** | 同步搬运（本地文件夹 → WebDAV，**手动触发**） | 两台机：A 点「同步到其他设备」→ B 落地 → 引用改写 → 云端清空 |

> 期 3 与之前讨论的「媒体播放」是同一件事，合成一个 rev 更省。

## 8 不做什么

- **不做云端永久存储**：临时区只在搬运窗口存在（用户明确要求）
- **Git 后端不做**（见 §5）
- **引用文件不进索引**：库外引用不参与 `list_notes` / 全局搜索 / 时间流，避免路径失效污染搜索
- **不改变文档（pdf/epub）现有行为**：仍引用原文件
