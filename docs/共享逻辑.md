# 共享逻辑（一份实现，多处接入）

> 状态：**active** ｜ 建立：2026-11-03（审计 5.1）｜ 权威范围：**同一逻辑只允许一份实现** —— 本表登记「唯一实现」与「禁止写法」
> 背景：附件路径解析曾在**渲染 / 点击查看原图 / 导出**各写一套，修一处漏三处（rev173.335、rev173.336 连修两轮，用户两次报同一个 bug）。

## 怎么用

1. 动这类逻辑前先查本表：要改的是「唯一实现」，还是某个调用点？
2. 新增调用点 → **复用唯一实现**，不复制函数体、不在调用点现场补兜底。
3. 发现新的一份重复 → 先收口到唯一实现，再补一行登记；「禁止写法」写具体（让 `check-docs` 能 grep）。
4. `check-docs` 会按本表「禁止写法」列对 `src/` 全量 grep，命中即红（规则写在 `scripts/check-docs.mjs` 的 `SHARED_RULES`，与表同步维护）。
5. **跨端两份**（前端 ↔ 脚本 / 前端 ↔ Rust）必须有「同一组输入 → 同样输出」的一致性测试，只测「格式长这样」不算。

## 加一条的格式

1. 「能力」= 一句话说清是什么判断 / 什么数据流。
2. 「唯一实现」= `文件#函数名`（函数必须 export，能被 grep 到）。
3. 「已接入调用点」= 列全；漏一个就在旁边标「**已知第二份**」并写原因。
4. 「禁止写法」= 能被 `check-docs` 正则命中的**具体串**（不写「不要重复」这种空话）。
