# 个人笔记软件最终需求文档

## 一、产品定位

### 1.1 用途
自用笔记软件，覆盖：

- 日常写作
- 生活记录
- 学习笔记
- 个人信息管理
- 随手记录需要保存的信息
- 写简单安排
- 记录突然想到的句子

### 1.2 平台
- 安卓手机
- Windows 电脑
- 双端使用，需要同步

### 1.3 核心体验
- 打开软件后直接进入输入状态，光标停在输入框，可直接开始输入。
- 打开软件本身不需要身份验证。
- 整体风格：极简纯文字风格，信息干净，不采用卡片式或高密度文件管理器风格。

---

## 二、总体架构：本体 + 多插件

### 2.1 本体核心能力
本体只保留最小核心：

- 编辑
- 存储
- 搜索

以下能力全部做成插件：

- 分类 / 文件夹
- AI 分类与标签
- 同步
- 身份验证与加密
- 计划打卡
- 私密文件夹
- 绝密账号管理
- 桌面组件
- 历史版本
- 回收站
- 备份与恢复
- 导入
- 通知 / 提醒
- 标签
- 笔记关联
- 普通待办

### 2.2 插件形式
- 插件由自己开发，不考虑第三方插件生态。
- 插件动态加载，不编译进本体。
- 技术形式：混合模式。
  - 本体用 Web 技术。
  - 插件主要用 JS/TS。
  - 需要系统能力时通过桥接调用原生。
- 插件打包分发采用混合形式：
  - 开发时用文件夹。
  - 分发时打包成压缩包。
  - 本体两种都支持。
- 插件依赖第三方 JS 库时，两种方式都支持：
  - 插件自己打包依赖。
  - 引用本体公共库。
  - 由插件自选。

### 2.3 插件运行环境
采用混合模式：

- UI 插件：iframe sandbox。
- 逻辑 / 后台插件：Web Worker。
- 敏感插件：QuickJS / WASM。
- 高权限插件：可申请与本体同上下文运行。
- 默认独立沙箱。
- 插件 UI 默认隔离。
- 插件可申请“全局样式权限”影响本体。
- 插件可自由决定 UI 入口位置，可添加悬浮按钮、覆盖层，往主界面任意位置塞元素。
- 允许插件覆盖 / 替换核心界面，但需要申请高权限，安装时明确授权。

### 2.4 插件加载与更新
- 插件来源：自己开发。
- 加载方式：独立文件 / 文件夹放在插件目录，由本体运行时动态加载。
- 安装方式：
  - 把插件文件夹放进本体插件目录，启动时自动扫描加载。
  - 支持从私有仓库或 URL 下载安装。
  - 默认：插件目录自动扫描。
- 更新检查：
  - 启动时自动检查你为每个插件配置的远程更新源。
- 插件源形式：
  - 支持 JSON 清单 URL。
  - 支持 Git 仓库地址。
- 插件源维护：
  - 完全由你手动添加 / 删除源，本体不内置任何源。
- 插件启用 / 禁用 / 更新：
  - 支持热插拔，需要重启时明确提示。
- 插件崩溃：
  - 自动禁用该插件，并提示原因。
  - 本体不崩。

### 2.5 插件权限
- 所有 API 都开放，但按权限分级。
- 权限产生方式：
  - 插件自己声明。
  - 本体自动扫描实际调用的 API。
  - 两者结合，最后给你确认。
- 安装 / 启用插件时：
  - 普通权限统一列出，你确认即可。
  - 高权限单独列出，默认不勾选，必须明确同意。
- 插件更新后新增高权限：
  - 重新弹窗确认。
- 设置里可随时查看每个插件的权限，也能随时关闭。
- 高权限被关闭后，插件对应功能失效或标记不可用，但不应导致本体崩溃。
- 开发者模式下可批量授权高权限。

建议高权限包括：

- 调用安全插件 / 身份验证插件的服务
- 调用绝密账号管理插件的数据服务
- 读取 / 修改私密笔记
- 获取或使用主密码、加密密钥
- 读取剪贴板
- 文件系统访问
- 网络请求
- 后台任务 / 定时任务 / 开机自启
- 覆盖 / 替换核心界面
- 与本体同上下文运行
- 修改本体核心设置或插件系统本身

普通权限包括：

- 公开笔记读写
- 分类、标签、公开搜索
- 事件订阅
- UI 注册（非覆盖核心界面）
- 插件自有存储
- 调用普通插件服务
- 通知、提醒
- 剪贴板写入
- 桌面组件注册

### 2.6 插件依赖
- 允许插件互相依赖。
- 采用“依赖注入 + 按服务名解析”。
- 插件声明所需服务，本体按服务名找到提供者并注入。
- 插件依赖服务时，默认声明“服务名 + 兼容版本范围”，特殊情况下可锁定具体版本。
- 当插件 A 依赖插件 B，而 B 未安装、被禁用或版本不匹配时：
  - 提示你手动安装 / 启用 / 更新 B，否则 A 不可用。
- 当插件 B 被禁用或卸载，而插件 A 依赖它时：
  - 自动禁用 A，并提示原因。
- 循环依赖：
  - 默认直接阻止，检测到就拒绝加载相关插件，并明确提示环路。
  - 不自动强制加载。
  - 开发者模式可留“强制加载”选项，默认关闭，并标记为不稳定。

### 2.7 插件服务与事件
- 通信机制：事件总线 + 服务调用。
- 插件可监听事件，也可主动调用本体 API。
- 多个插件注册同一服务名时：
  - 按插件声明的优先级自动选择。
  - 优先级相同则弹窗让你选择，并记住选择。
- 插件被禁用或卸载时：
  - 保留其服务注册信息和事件监听，但标记为不可用。
  - 重新启用后自动恢复。

### 2.8 插件扩展点
- 允许插件定义新扩展点，其他插件可注册。
- 发现与注册机制采用混合方式，以“本体统一注册表”为主：
  - 本体提供扩展点注册表。
  - 插件在 manifest 里声明自己定义了哪些扩展点。
  - 其他插件默认通过本体注册表查询并注册。
  - 允许插件额外暴露服务或事件，作为特殊场景补充。
- 优先级和冲突：
  - 插件声明优先级。
  - 相同优先级弹窗让你选并记住。
- 定义扩展点的插件被禁用时：
  - 注册信息保留但标记不可用。
  - 重新启用后恢复。

### 2.9 插件数据
- 插件可申请直接访问自己的独立存储文件。
- 普通数据走本体存储 API。
- 插件自有数据可申请直接访问自己的独立存储文件。
- 插件通过本体存储 API 写入扩展字段时，本体自动判断该字段是否被声明为可搜索，并立即更新索引。
- 默认不纳入统一搜索；插件可声明“独立存储也参与统一搜索”，并自己负责通知本体更新索引。
- 插件数据在同步和备份时，采用混合声明：
  - 插件清单 manifest 给默认值。
  - 每个存储容器可覆盖。
  - 调用时还能临时指定。
- manifest 默认值包括：
  - 插件 ID
  - 存储命名空间
  - 数据版本
  - 默认是否加密
  - 默认是否参与同步
  - 默认是否参与备份
  - 默认是否启用软删除
  - 默认是否启用版本快照
  - 默认哪些字段可搜索
  - 默认是否属于敏感数据
  - 迁移脚本
- 容器级可覆盖上述策略。
- 调用时可临时指定是否同步、备份、留版本、软删除、更新索引。

### 2.10 插件数据生命周期
- 插件被禁用时：
  - 保留数据，界面上不再显示，重新启用后恢复。
  - 默认继续参与同步和备份。
  - 插件可声明暂停同步 / 备份。
  - 敏感数据强制暂停。
- 插件被彻底卸载时：
  - 它写在笔记里的扩展字段和它自己的存储数据直接删除，不留残留。

### 2.11 插件配置与多设备
- 插件文件：各设备通过插件源分别安装，允许平台差异，不直接同步插件文件。
- 插件配置：普通配置同步；设备相关配置本地化。
- 启用 / 禁用状态：同步，但按设备实际安装和授权情况校正。
- 高权限：不同步，每台设备单独授权。
- 缺少插件：同步下来的配置保留，标记“待安装”，装好后自动恢复。
- 备份：默认含配置、状态、插件数据，插件文件可选备份。

### 2.12 插件分组
- 支持插件分组 / 集合。
- 混合模式：
  - 分组默认只做管理标签。
  - 可标记为“合集包”，安装 / 卸载时整体处理。
  - 日常启用 / 禁用仍逐个控制。
- 组可一键启用 / 禁用 / 更新，但不是默认行为。
- 组可声明组内依赖，本体统一检查。
- 组内插件权限统一确认。

### 2.13 插件开发调试
本体提供：

- 插件日志：每个插件独立日志，可在开发者面板查看。
- 错误堆栈：完整堆栈，定位到文件和行号。
- 热重载：改完插件代码，不重启本体即可重新加载该插件。
- 调试面板：查看已加载插件、注册服务、事件监听、权限、依赖关系。
- 模拟触发：手动触发事件，测试插件响应。
- 插件沙箱控制台：在插件上下文执行 JS。
- 开发者模式：跳过部分权限确认、显示更多调试信息、批量授权高权限。
- 资源监控：记录各插件存储、内存、CPU、网络占用，但不强制限制。

### 2.14 插件版本回滚
- 混合模式。
- 默认每个插件保留最近 3 个版本用于回滚。
- 回滚前自动备份当前插件数据。
- 尝试反向迁移。
- 反向迁移失败则提示你选择：
  - 仍要回滚并接受数据可能不可用。
  - 取消回滚。

### 2.15 核心能力接管
- 编辑、存储、搜索都可以被插件接管。
- 接管关系跟随插件启用状态自动决定：
  - 插件启用则自动接管。
  - 禁用则自动回退到本体。
- 多个插件冲突时：
  - 按优先级自动选择。
  - 优先级相同弹窗让你选并记住。
- 接管核心能力的插件被禁用或卸载时：
  - 自动回退到本体内置默认实现，继续可用。

### 2.16 插件系统核心机制
以下机制为本体内置核心，不可被插件替换：

- 插件加载器
- 权限系统
- 事件总线
- 服务注册表

但允许插件扩展：

- 事件总线：插件可注册新事件类型，不能替换总线。
- 服务注册表：插件可注册服务，不能替换注册表。
- 权限系统：插件可声明权限，不能修改校验逻辑。
- 加载器：插件不能替换。

## 三、信息架构与分类

### 3.1 公开笔记预设分类
- 写作
- 学习笔记
- 计划

生活记录、个人信息管理等内容，不预先建分类；遇到相关内容时由 AI 推荐新分类。

### 3.2 AI 分类规则
- 公开笔记保存后，AI 立即分类。
- AI 优先放入已有分类。
- 若不属于已有分类，或拿不准，则推荐一个新分类名。
- 推荐后弹出确认窗口：
  - 窗口内直接给出推荐分类名。
  - 允许用户自己修改。
  - 用户确认后创建 / 归档。
- AI 同时推荐父分类。
- 若推荐的父分类不存在，用户确认后，父分类和子分类一并创建。
- 分类文件夹允许嵌套。
- 一条笔记只归入一个分类文件夹。

### 3.3 私密内容
- 输入时由用户手动切换“公开 / 私密”。
- 默认公开。
- 私密内容不经过 AI。
- 私密笔记统一放进“私密文件夹”下。
- 私密笔记不需要标签。
- 私密文件夹有独立入口，进入需身份验证。
- 私密文件夹内有独立搜索入口。
- 私密文件夹有独立回收站，进入回收站也需验证。

## 四、笔记编辑与展示

### 4.1 编辑能力
支持内容形式：

- Markdown
- 富文本
- 图片
- 附件
- 表格

编辑模式：

- 富文本所见即所得模式。
- Markdown 源码模式。
- 两种模式可随时切换。
- 默认打开为所见即所得模式。

### 4.2 存储格式
- 笔记正文以 Markdown 为主要存储格式。
- 搜索时从 Markdown 提取纯文本，使用 FTS5 索引。
- 富文本模式：Lexical 解析 Markdown 渲染。
- 源码模式：直接编辑 Markdown。
- 不长期存两份 Lexical JSON 和 Markdown。
- 历史版本：存 Markdown 快照，差异对比用文本 diff。
- 导入导出：以 Markdown 为落点。

### 4.3 标题与列表展示
- 不单独设置标题。
- 列表里直接显示正文开头。
- 首页按日期分组。
- 同一天一个日期标题。
- 当天内按时间从新到旧排列。
- 每条笔记显示具体时间，例如：`09:12 买牛奶`。

### 4.4 普通待办
- 普通笔记内支持简单勾选待办。
- 待办项不设截止日期、提醒。
- 勾选后保持原位，加删除线。
- 不需要统一查看所有未完成待办，只在各自笔记内查看和勾选。

### 4.5 笔记关联
- 笔记可互相引用。
- 引用显示标题和摘要。
- 被引用笔记标题 / 摘要变化时，引用自动更新。
- 被引用笔记能看到反向链接。

### 4.6 附件与图片
- 采用混合存储：
  - 小文件直接存进 SQLite 数据库。
  - 大文件存文件系统，数据库存预览或链接。
  - 由本体设定大小阈值，或由插件 / 用户按容器声明。
- 大文件同步：
  - 按需同步。
  - 明确点击才下载。
- 公开笔记附件在云盘中明文存放。
- 私密 / 绝密附件加密后同步。

## 五、AI 能力

- 使用云端 AI。
- 软件内置多种 AI 服务商供选择。
- 用户只需要配置：
  - API Key
  - 模型名
- 公开笔记保存后立即进行 AI 分类。
- 公开笔记标签由 AI 自动添加。
- AI 想使用新标签时，直接创建并使用，不需要用户确认。
- 私密内容不经过 AI。
- 当 AI 将公开笔记归入“计划”文件夹时：
  - 自动把它转为计划笔记。
  - 随后弹窗让用户填写频率、提醒、每日打卡次数上限。
  - 允许跳过，稍后再补。

---

## 六、标签与搜索

### 6.1 标签
- 公开笔记支持标签。
- 标签由 AI 自动打。
- 新标签直接创建。
- 标签默认不在笔记列表中显示，打开笔记后显示。
- 点击标签后跳转到“所有带这个标签的笔记”列表。
- 该列表可以包含私密笔记，但私密笔记只显示标题。
- 点击私密标题时，先进行身份验证，验证通过后打开。
- 私密笔记不需要标签。

### 6.2 搜索
- 公开搜索不包含私密内容。
- 私密搜索有单独入口，位于私密文件夹内部。
- 查找顺序：
  1. 较新的内容按时间看。
  2. 再按分类找。
  3. 没找到再搜索。
- 搜索采用混合模式：
  - 本体搜核心字段。
  - 插件声明可搜索字段并纳入统一索引。
  - 插件也可提供独立的高级搜索入口。
- 中文全文搜索：SQLite FTS5 + n-gram 索引，默认 2-gram。
- 插件通过本体存储 API 写入扩展字段时，本体自动判断该字段是否可搜索，并立即更新索引。
- 插件独立存储默认不纳入统一搜索；插件可声明参与，并自己负责通知本体更新索引。

## 七、计划与打卡

### 7.1 计划的形式
- “计划”是计划文件夹里的一种特殊笔记。
- 打开后除了正文，还有：
  - 打卡按钮
  - 提醒设置
  - 打卡日历
  - 频率设置

### 7.2 频率与提醒
- 频率可自定义，支持：
  - 每天
  - 每周固定星期几
  - 每月固定日期
  - 每隔 N 天
- 提醒支持一天多个。
- 计划提醒触发后，点击通知打开对应计划笔记。
- 打开后不自动定位打卡按钮，由用户自己找。

### 7.3 打卡规则
- 一个计划一个打卡按钮。
- 一天可以点击多次。
- 每天打卡次数上限由用户自己设定。
- 一天内至少打卡一次，就算当天完成一天。
- 连续打卡天数按“计划应打卡日”计算：
  - 非打卡日自动跳过，不算中断。
  - 例如每周一三五打卡，周二周四没打不影响连续。
- 统计同时展示：
  - 连续打卡天数
  - 累计打卡天数
- 累计天数按“有打卡的天数”计算，不按实际打卡次数计算。
- 打卡日历：
  - 显示当天是否已完成。
  - 显示当天打卡次数。
- 可手动补打卡或修改某天记录。
- 只能修改最近 7 天内的记录。

## 八、绝密账号管理

### 8.1 入口与界面
- 独立于笔记系统的专门模块。
- 有独立入口、列表和编辑界面。
- 进入需身份验证。
- 数据加密同步，复用绝密账号管理的主密码。

### 8.2 记录结构
每条记录包含：

- 平台名
- 网站
- 账号
- 密码
- 备注

同一平台可以有多个账号。

### 8.3 列表展示
- 列表按平台名展示。
- 展开某个平台后，显示该平台下的多个账号。
- 每条账号默认显示除密码外的其他信息。
- 密码默认隐藏。
- 需要点击“显示 / 复制”才可见或复制。
- 复制密码后，剪贴板 1 分钟后自动清空。

### 8.4 搜索
- 提供搜索框。
- 搜索范围：平台名、账号名、备注。
- 密码不参与搜索。

### 8.5 密码生成器
- 支持手动输入密码。
- 也支持随机密码生成器。
- 生成前允许调整长度和字符规则。
- 默认使用“兼容最广泛”的格式：
  - 16 位
  - 大小写字母 + 数字
  - 排除易混淆字符，如 `0/O`、`1/l/I`
  - 不含符号

### 8.6 验证与恢复
- 进入验证方式：
  - 生物识别作为快捷方式。
  - 生物识别可用时，不需要输入主密码。
  - 生物识别失败或不可用时，才要求输入主密码。
- 主密码忘记后允许恢复。
- 恢复方式：
  - 设置 1 道自定义安全问题。
  - 答案宽松匹配，忽略大小写、忽略前后空格。
  - 答对后可重置主密码，保住数据。

### 8.7 回收站
- 绝密账号管理有独立回收站。
- 进入回收站需验证身份。
- 删除内容先进回收站，7 天后删除。

## 九、安全与锁定

### 9.1 验证边界
- 打开软件主界面不需要验证。
- 进入“私密文件夹”和“绝密账号管理”时验证。
- 两者验证方式一致：
  - 优先生物识别。
  - 失败或不可用时输入主密码。
- 生物识别采用混合可选项：
  - 首次输入主密码后可勾选“在本设备记住”。
  - 默认记住。
  - 允许按设备关闭。

### 9.2 自动锁定
- 进入私密文件夹或绝密账号管理后：
  - 切到后台、锁屏或离开 3 分钟自动锁定。
  - 锁定后页面盖上遮罩。
  - 自动弹出生物识别。
  - 失败或取消后显示手动验证按钮。
  - 验证通过后继续看原来的内容。

### 9.3 加密方案
- 对称加密：XChaCha20-Poly1305。
- 密钥派生：Argon2id。
- 数据密钥：每个加密容器随机生成独立数据密钥，用主密钥包裹后存储。
- 主密码只用于派生主密钥，不直接加密业务数据。
- 完整性：所有密文都带认证标签，解密失败直接拒绝，不返回部分明文。
- 恢复：安全问题验证通过后，只重置主密码、重新派生主密钥，再用主密钥重新包裹各容器数据密钥，数据本身不变。

### 9.4 主密码与密钥管理
- 主密码只由安全插件持有。
- 主密钥不落盘、不传给其他插件，只保留在安全插件内存中，锁定后清空。
- 安全插件为每个需要加密的插件或加密容器派生独立数据密钥。
- 其他插件不直接拿密钥，通过服务调用加解密：
  - `crypto.encrypt(containerId, data)`
  - `crypto.decrypt(containerId, data)`
  - `crypto.sign(...)`
  - `crypto.verify(...)`
- 只有极少数场景，才允许插件申请“获取派生密钥”的高权限：
  - 同步插件需要在没有安全插件在线时独立加密 / 解密。
  - 备份插件需要独立处理大批量加密数据。
  - 离线恢复工具需要直接解密备份。
- 即使这样，也只暴露“某个容器的数据密钥”，不暴露主密钥，且需要高权限、安装时单独确认。

## 十、同步与冲突

### 10.1 同步方式
- 安卓 + Windows 双向同步。
- 使用第三方云盘同步。
- 支持多种云盘，由用户自己配置，例如 OneDrive、坚果云、WebDAV 等。
- 公开笔记：
  - 云盘中明文存储。
  - 保存为数据库文件。
  - 小附件入库；大附件文件系统存储，数据库存预览或链接。
- 私密文件夹和绝密账号管理：
  - 加密后同步。
  - 加密复用绝密账号管理的主密码。

### 10.2 同步后端
采用混合方案：

- 同步插件定义统一的“存储后端”接口。
- 具体后端可以是本地同步文件夹、WebDAV、具体云盘 API。
- 优先实现顺序：
  1. 本地同步文件夹
  2. WebDAV
  3. 具体云盘 API

### 10.3 同步机制
记录级同步：

- 每设备变更日志 + 定期快照。
- 不同步整个数据库文件，把每条笔记的变更作为同步单元。
- 每条笔记带版本号 / 修改时间，同步时逐条比对、合并。
- 冲突时按规则把两个版本插入同一篇笔记。

文件结构示例：

```
/sync
  /devices
    android.jsonl
    windows.jsonl
  /snapshots
    snapshot-android-2026-10-16T10-00-00.db
    snapshot-windows-2026-10-16T10-00-00.db
  /meta
    device-registry.json
    sync-state.json
```

变更日志格式：JSON Lines。

关键字段：

- `device`
- `ts`
- `noteId`
- `op`：create / update / delete
- `field`
- `baseVersion`
- `newVersion`
- `value`

同步流程：

1. 本机保存笔记，追加变更到自己的日志，更新本地数据库。
2. 同步时，先上传自己的变更日志，再读取其他设备的变更日志。
3. 对每条对方变更，检查本地是否也有同一笔记的变更：
   - 对方改了，本地没改：直接应用。
   - 对方改了，本地也改了，但基于同一 baseVersion：合并或按规则处理。
   - 对方改了，本地也改了，且 baseVersion 不同：触发冲突。
4. 应用完变更后，更新 `sync-state.json`。
5. 定期生成完整快照，上传到 `/snapshots`。
6. 快照生成后，可安全截断变更日志中已被快照覆盖的部分。

### 10.4 冲突检测
采用版本向量（Version Vector）：

- 每条笔记维护 `versionVector`，例如 `{ android: 3, windows: 2 }`。
- 每次本设备修改笔记，对应设备计数 +1。
- 同步时比较本地和远程版本向量：
  - 远程向量 ≤ 本地向量：远程没有新变更，跳过。
  - 本地向量 ≤ 远程向量：本地没有新变更，直接应用远程版本。
  - 双方各有对方没有的增量：判定为并发冲突。
- 冲突时：
  - 在同一个笔记里按时间显示冲突。
  - 将两个版本内容都插入当前笔记。
  - 分别标注时间和来源设备。
  - 用户手动删改合并。
  - 用户编辑保存过这篇笔记后，软件自动认为冲突已处理，恢复正常同步。

### 10.5 同步触发时机
混合模式：

- 普通笔记保存：只写入本地变更日志，标记“待同步”。
- 定时同步：默认每 10 分钟一次，可调。
- 启动 / 退出同步：打开软件拉取一次，关闭软件推送一次。
- 手动同步：保留同步按钮。
- 重要操作立即同步：
  - 新建 / 修改计划
  - 打卡
  - 私密笔记保存
  - 绝密账号管理改动
  - 冲突合并完成
  - 导入完成
  - AI 分类确认
  - 插件配置 / 权限变更
  - 备份 / 恢复操作

## 十一、历史版本

- 每次关闭笔记时，如果本次有修改，则生成一个历史版本。
- 如果没有修改，不生成版本。
- 按时间分层精简：
  - 最近 7 天：保留每次关闭的版本。
  - 8～30 天：每天只保留最后一个版本。
  - 30 天以上：每周只保留一个版本。
  - 超过 1 年：每月只保留一个版本。
- 支持回滚到历史版本。
- 支持差异对比。
- 可任选两个版本进行对比，也可以选择当前版本。
- 差异对比高亮显示增删改。

## 十七、技术选型

### 17.1 跨平台外壳
- Tauri 2.x。
- 一套 Web 前端 + Rust 核心，覆盖 Windows 和 Android。
- 利用 Tauri IPC、Capabilities / Scopes、iframe 沙箱、QuickJS Runtime 隔离。
- 原生能力通过 Rust 桥接；特殊能力允许插件自带原生模块。

### 17.2 前端框架
- SolidJS。
- 细粒度响应式，运行时小，性能好，和 iframe 沙箱配合好。

### 17.3 编辑器
- Lexical。
- 运行时约 30KB。
- 原生插件化设计。
- 官方 `@lexical/markdown` 支持 Markdown 双向转换。
- 社区有 SolidJS 适配层。

### 17.4 存储
- SQLite 为主数据库。
- 文件系统存放大文件附件。
- 键值存储层存放应用级配置和用户偏好。
- 公开笔记保存为数据库文件，云盘明文同步。
- 附件混合存储：小文件入库，大文件文件系统，数据库存预览 / 链接。

### 17.5 数据访问层
- 混合：
  - 本体核心表用 `sea-orm` 管理迁移和实体。
  - 插件数据走统一存储 API，底层动态 SQL。
  - 复杂搜索、同步合并等关键路径手写 SQL 优化。

### 17.6 状态管理
- 混合：
  - 本体内部用 SolidJS 原生方案：`createSignal` + `createStore`。
  - 插件读取 / 监听本体状态走“状态中心 + 事件”。
  - 插件自己的状态自己管。

### 17.7 中文全文搜索
- SQLite FTS5 + n-gram 索引。
- 默认 2-gram。
- 后续搜索插件可调。

### 17.8 ID 生成
- UUIDv7 / ULID。
- 时间有序，全局唯一，适合按时间排序、分页和同步。
- 核心笔记、插件数据、设备都用 UUIDv7 / ULID。
- 插件内部临时数据可自己决定。

### 17.9 插件沙箱
- 混合：
  - UI 插件：iframe sandbox。
  - 逻辑 / 后台插件：Web Worker。
  - 敏感插件：QuickJS / WASM。
  - 高权限插件：按需申请同上下文。
- 插件在 manifest 里声明期望 runtime，本体校验。
- 如果声明与申请的权限 / 注册的扩展点不匹配，本体自动升级到更严格的沙箱，或要求你确认。

### 17.10 原生桥接
- 混合：
  - 常用能力（文件、通知、剪贴板、生物识别、数据库）走本体统一实现。
  - 特殊能力通过桥接协议支持插件自带原生模块。
- 插件自带原生模块加载方式：
  - 默认编译进本体，保持简单稳定。
  - 确实需要独立分发的插件，才考虑平台动态库或外置原生服务进程。

### 17.11 项目组织
- 单仓库（Monorepo）。
- 结构：
  - `/core`：本体
  - `/plugins/*`：各插件
  - `/shared`：共享类型和工具
  - `/native`：平台桥接
- 用 pnpm workspace 或 Turborepo 管理。
- 统一构建、统一版本、共享依赖方便。

### 17.12 工具链
- 包管理器：pnpm。
- 构建工具：Vite。
- 测试框架：Vitest。
- 端到端测试：可选 Playwright。

## 十八、开发计划与阶段验收标准

### 阶段 0：技术验证

目标：确认 Tauri 2.x 在 Android + Windows 都能跑通关键路径。

验收标准：

- Android 端：
  - Tauri 2.x 项目能构建、安装、启动。
  - WebView 正常加载前端页面。
  - SQLite 能创建表、写入一条笔记、读出来。
  - Lexical 能输入文字、保存成 Markdown、重新加载后内容还在。
  - 能从插件文件夹加载一个 Hello World 插件，并显示一个入口。
- Windows 端：
  - 同样的构建、启动、SQLite 读写、Lexical 输入保存、插件加载流程都能跑通。
- 插件骨架最小验证：
  - 插件 manifest 能被解析。
  - 插件能注册一个侧边栏入口。
  - 插件能调用一个本体 API，并在插件 UI 里显示。
- IPC 与文件系统：
  - 前端能通过 Tauri IPC 调用 Rust 命令。
  - 能读写应用数据目录下的一个文件。

不要求：

- 权限系统完整实现。
- 事件总线完整实现。
- 服务注册表完整实现。
- QuickJS / Web Worker 沙箱。
- 同步、加密、AI 分类、计划打卡等业务插件。
- 桌面组件。

风险重点：Android 端。

### 阶段 1：最小可用闭环

目标：能真实用起来，同时验证插件架构。

验收标准：

- 快速输入闭环：
  - 打开软件直接进入输入状态，光标在输入框。
  - 输入后保存，立即写入本地 SQLite。
  - 首页按日期分组展示，同一天按时间从新到旧排列，每条显示时间和正文开头。
- 编辑闭环：
  - 富文本所见即所得模式可用。
  - Markdown 源码模式可切换。
  - 输入、保存、关闭、重新打开后内容不丢。
  - 图片、附件、表格至少各验证一种能正常保存和显示。
- 搜索闭环：
  - 能对公开笔记正文做搜索。
  - 搜索结果能跳转到对应笔记。
  - 中文搜索至少能搜到，不要求排序完美。
- 插件骨架闭环：
  - 插件加载器、manifest、基础权限、事件总线、服务注册表最小可用。
  - 能加载一个真实插件（AI 分类插件）并正常工作。
  - 插件崩溃时本体不崩，能自动禁用并提示。
- AI 分类闭环：
  - 公开笔记保存后，AI 分类插件能拿到“笔记已保存”事件。
  - 能调用配置好的云端 AI。
  - 能放入预设分类，或推荐新分类并弹窗让你确认。
  - 确认后分类生效，列表和搜索能按分类筛选。
- 数据落盘与重启：
  - 关闭软件再打开，笔记、分类、插件状态都还在。
  - SQLite 文件位置明确，便于后续同步和备份。

不要求：

- 私密文件夹
- 绝密账号管理
- 计划打卡
- 同步
- 加密
- 自动备份
- 桌面组件
- 历史版本差异对比
- 回收站
- 导入

### 阶段 2：高频日常功能

验收标准：

- 计划打卡插件：
  - 能把一条笔记转为计划，设置频率、提醒、每日打卡次数上限。
  - 计划笔记里有打卡按钮，一天可点多次，达到上限后提示。
  - 打卡日历能显示已完成和当天次数。
  - 能补打卡或修改最近 7 天的记录。
  - 连续打卡天数按计划应打卡日计算，累计按天计算。
  - 提醒到点能通知，点击后打开对应计划笔记。
  - 允许跳过设置，稍后再补。
- 私密文件夹插件：
  - 输入时可手动切换公开 / 私密，默认公开。
  - 私密内容不经过 AI，统一存入私密文件夹。
  - 私密文件夹有独立入口，进入需身份验证。
  - 私密文件夹内有独立搜索入口。
  - 私密文件夹有独立回收站，进入也需验证。
  - 公开搜索和公开列表不出现私密内容。
  - 标签结果中私密笔记只显示标题，点击需验证。
- 绝密账号管理插件：
  - 独立入口、列表和编辑界面。
  - 进入需生物识别，失败或不可用时输主密码。
  - 记录包含平台名、网站、账号、密码、备注。
  - 同一平台可多个账号，展开显示。
  - 密码默认隐藏，可显示 / 复制，复制后 1 分钟清空剪贴板。
  - 支持搜索平台名、账号名、备注，不搜密码。
  - 支持随机密码生成器，默认 16 位、大小写 + 数字、排除易混淆字符、不含符号。
  - 有独立回收站，进入需验证，7 天删除。
  - 支持 1 道自定义安全问题恢复主密码，宽松匹配。
- 标签插件：
  - 公开笔记保存后，AI 自动打标签，新标签直接创建。
  - 标签在打开笔记后显示，可点击跳转。
  - 跳转列表包含公开笔记和私密笔记；私密笔记只显示标题，点击需验证。
  - 私密笔记不需要标签。
- 锁定与安全：
  - 进入私密文件夹或绝密账号管理后，切后台 / 锁屏 / 离开 3 分钟自动锁定。
  - 锁定后盖遮罩，自动弹出生物识别，失败或取消显示手动验证按钮。
  - 验证通过后继续看原来的内容。
- 可日常使用：
  - 连续几天真实使用：记录、打卡、存账号。
  - 没有严重崩溃、数据丢失、明显卡顿。

不要求：

- 多设备同步
- 自动备份
- 冲突合并
- 历史版本差异对比
- 导入
- 桌面组件
- 插件更新、回滚、开发调试面板

### 阶段 3：同步与安全

验收标准：

- 同步插件：
  - 同步后端：本地同步文件夹、WebDAV 至少各跑通一种，另一种可后补。
  - 公开笔记明文同步，数据库文件 + 附件按需同步。
  - 私密文件夹、绝密账号管理加密同步，复用主密码。
  - 记录级同步：每设备变更日志 + 定期快照。
  - 版本向量冲突检测：能正确区分“单边修改”和“双边并发修改”。
  - 冲突时同一笔记插入两个版本，标注时间和来源设备，手动合并后自动解决。
  - 启动 / 退出同步、定时同步（默认 10 分钟）、手动同步、重要操作立即同步都能正常工作。
  - 同步状态可见：上次同步时间、待同步数量、冲突提示。
- 安全插件：
  - XChaCha20-Poly1305 + Argon2id 加密方案落地。
  - 每个加密容器独立数据密钥，主密钥包裹，主密码只用于派生主密钥。
  - 生物识别快捷方式：首次输入主密码后可勾选“在本设备记住”，默认记住，可按设备关闭。
  - 3 分钟自动锁定、遮罩、自动生物识别、失败后手动验证。
  - 锁定后内存中主密钥和数据密钥清空。
  - 安全问题恢复：只重置主密码，数据密钥不变，数据可解密。
- 备份插件：
  - 自动备份到本地，默认每天，固定档位可选。
  - 保留最近 30 份。
  - 备份包含公开笔记、私密文件夹、绝密账号管理。
  - 公开部分明文，私密和绝密部分加密，复用主密码。
  - 恢复整体覆盖，恢复前自动备份，快照不占 30 份限额。
  - 能验证：备份文件可用于恢复，恢复后数据完整。
- 多设备真实验证：
  - 安卓和 Windows 各装一份，通过云盘同步。
  - 两端分别新增、修改、删除笔记，能正确同步。
  - 两端同时改同一条笔记，能触发冲突并手动合并。
  - 私密和绝密数据加密同步，另一端能正确解密。
  - 备份文件能在另一台设备恢复。

不要求：

- 桌面组件
- 导入
- 历史版本差异对比
- 回收站界面完善
- 插件更新、回滚、开发调试面板

### 阶段 4：完善与扩展

验收标准：

- 桌面组件：
  - 快速输入组件：点击弹出轻量输入框，不打开主应用；保存后消失；内容进入临时收件箱；固定公开；由你主动触发整理。
  - 计划打卡组件：显示今日需要打卡的计划列表；点击直接完成一次打卡。
  - 最近笔记组件：只显示公开笔记；默认 5 条；可调 1 / 3 / 5 / 7 条。
  - 组件在多设备、重启、主题切换后显示正常。
- 导入：
  - 支持 Markdown、纯文本、Word、印象笔记、Notion、Obsidian 等来源。
  - 导入内容统一放入“日期导入”文件夹，内部按原分类名保存。
  - 同一天多次导入合并到同一个日期文件夹。
  - 导入后不立即 AI 整理，等你主动触发。
  - 导入时尽量保留原分类、创建时间等元数据。
- 历史版本与差异对比：
  - 每次关闭有修改的笔记时生成历史版本。
  - 按时间分层精简：最近 7 天保留每次关闭版本；8～30 天每天留最后一个；30 天以上每周留一个；超过 1 年每月留一个。
  - 可回滚到任意保留的历史版本。
  - 可任选两个版本做差异对比，高亮显示增删改，也可选当前版本。
- 回收站：
  - 普通笔记、私密文件夹、绝密账号管理各自独立回收站。
  - 删除内容先进回收站，7 天后删除。
  - 私密和绝密回收站进入需身份验证。
  - 支持恢复、彻底删除、清空回收站。
- 笔记关联与普通待办：
  - 笔记可互相引用，引用显示标题和摘要。
  - 被引用笔记标题 / 摘要变化时，引用自动更新。
  - 被引用笔记能看到反向链接。
  - 普通笔记内支持简单勾选待办；勾选后原位加删除线；不需要统一待办入口。
- 插件系统完善：
  - 插件启用 / 禁用 / 更新支持热插拔，需要重启时明确提示。
  - 插件崩溃自动禁用并提示原因，本体不崩。
  - 插件权限管理：普通权限统一确认；高权限单独列出、默认不勾选、明确同意；更新新增高权限重新确认。
  - 插件分组 / 合集包：默认只做管理标签；可标记为合集包，支持整体安装 / 卸载；日常仍可逐个启用 / 禁用。
  - 插件更新检查：启动时检查你配置的插件源，有更新提示你。
  - 插件版本回滚：默认保留最近 3 个版本；回滚前自动备份，尝试反向迁移，失败时提示你选择。
  - 核心能力接管：编辑、存储、搜索可被插件接管；插件启用自动接管，禁用自动回退本体；冲突按优先级选择，相同优先级弹窗让你选并记住。
- 开发者调试面板：
  - 插件日志：每个插件独立日志，可在面板查看。
  - 错误堆栈：完整堆栈，定位到文件和行号。
  - 热重载：改完插件代码，不重启本体即可重新加载该插件。
  - 调试面板：查看已加载插件、注册服务、事件监听、权限、依赖关系。
  - 模拟触发：手动触发事件，测试插件响应。
  - 插件沙箱控制台：在插件上下文执行 JS。
  - 开发者模式：跳过部分权限确认、显示更多调试信息、批量授权高权限。
  - 资源监控：记录各插件存储、内存、CPU、网络占用，但不强制限制。
- 体验与稳定性：
  - 连续多天真实使用，覆盖写作、学习、计划、生活记录、账号管理。
  - 无明显卡顿、崩溃、数据丢失。
  - 同步、备份、恢复、加密、锁定都能稳定工作。
  - 插件卸载后数据清理干净，不留残留。

不要求：

- 新插件类型的大规模扩展
- 多人协作
- 发布到应用商店
- 第三方插件生态
