> 状态：**active** ｜最后核对：2026-10-20 ｜权威范围：运行时长什么样、三条主流程怎么走、模块怎么分层
> 「为什么这样设计」见 [`架构原则`](架构原则-2026-10-13.md)；接口见 [`内核契约`](内核契约-v0.2.md)；数据落点见 [`数据与存储`](数据与存储.md)。

## 1 运行时拓扑

```
桌面（Tauri 进程）
┌─────────────────────────────────────────────────────────────┐
│ Rust（src-tauri/src/lib.rs）                                 │
│  文件命令 / 原子写 / 回收站 / ids.json / 看门狗              │
│  自定义插件：statusbar · notification-capture · androidperm  │
│              · uri-reader                                    │
└──────────────▲──────────────────────────────┬────────────────┘
               │ invoke / event                │ WebView2
┌──────────────┴──────────────────────────────▼────────────────┐
│ 前端（同一个 JS 上下文）                                      │
│   main.tsx → App.tsx（编排）                                  │
│     hooks（状态域） → kernel（契约实现 + 插件宿主） → lib（纯逻辑）│
│     components（只收 props）                                  │
│   插件：全局目录 .zn/plugins/<id>，Blob 动态 import           │
└──────────────────────────────────────────────────────────────┘
```

窗口类型（`src-tauri/capabilities/default.json` 的 `windows` glob）：

| label | 来源 | 内容 |
|---|---|---|
| `main` | 启动 | 完整 App（侧栏 / 时间流 / 标签 / 编辑器） |
| `note-*` | 标签拖出或右键「在新窗口打开」 | **完整 App**，但只画编辑器（`?note=`） |
| `plugin-*` | 插件 `view.openWindow` | 插件独立窗口 |
| 手机 | 无系统窗口 | 单 webview，整窗接管 |

## 2 前端分层与依赖方向

```
lib ← kernel ← hooks ← App
components → kernel / lib（只收 props）
```

| 层 | 职责 | 禁止 |
|---|---|---|
| `src/lib/` | 纯函数 / 路径 / 错误文案 / 启动自愈 | React、kernel、DOM |
| `src/kernel/` | 契约、插件宿主、命令表、索引、编辑器接线 | hooks、components、App |
| `src/hooks/` | 状态域（一个域一个文件） | components、App |
| `src/components/` | 视图，只收 props | hooks、App |
| `src/App.tsx` | 编排：state、接线、JSX | — |

> 这条方向由 `scripts/check-arch.mjs` 在每次 verify 校验（条数与结果以 verify 输出为准）。

## 3 启动序列

1. `index.html` 内联脚本设 `data-theme`（防首屏闪烁）。
2. `main.tsx` → `App.tsx`。
3. `createKernel`（`src/kernel/kernel.ts`：**唯一的原语组装点**）。
4. 插件宿主（`usePluginHost`）：
   `ensureBuiltinPlugins`（内置插件写全局根）→ 扫描全局目录 → 读 manifest →
   平台门（`platforms`）→ 版本门（`apiVersion` major）→ 懒激活判定 → 命令登记 / `apply()`。
5. 恢复上次的库（`localStorage` `zeronote.vault`）；Android 无库时落到公共 `Documents/ZeroNote`。
6. 首屏：有打开的笔记 → 编辑器；否则起始页。
7. 索引**不**在启动时重建：首次打开搜索面板才 `index.rebuild()`（`SearchPanel.tsx`）。

## 4 主流程 A：编辑 → 保存 → 合并 → 原子写

```
输入 → onEditorChange → 800ms 防抖 ─┐
Ctrl+S / 关窗 / 切标签 ──────────────┤→ saveNow()
                                     │
saveNow（src/hooks/useDocIO.ts）     │
 ① 读盘：磁盘变了 → merge3 行级合并（冲突：手写优先）
 ② fs.save → Rust atomic_write：tmp → rename；失败走 .zn-bak 三步
 ③ index.upsert + 事件 note:saved
```

- **真正的防线在 `saveNow` 写盘前那次合并**；`fs.watch` 只让画面早点跟上（实测会迟到几秒）。
- 关窗：`close-requested` → `saveNow` → `close()`（`closingRef` 防死循环）。
- 崩溃 / HMR 全量重载：未落盘输入会丢（会话恢复未做，见 `docs/decisions/` 与对标方案）。

## 5 主流程 B：插件生命周期

```
启动 ── ensureBuiltinPlugins（内置插件写全局根；内容同则跳过）
     ── collectPluginDirs → readManifest
     ── 门：platforms / apiVersion（只看 major）
     ── activationEvents 不含 onStartup/onVaultOpen ⇒ 只登记命令元数据（懒激活）
     ── 否则 loadPlugin：命令 / 面板 / 事件 / 样式 / service
用户执行命令 ── 懒激活 ⇒ activator 载入（幂等）
重载 / 卸载 ── 串行链：先卸旧代（命令 / service / editor marks）再装新代
卡死兜底 ── 加载前写 localStorage 标记 → Rust 看门狗无心跳 → 退出码 101
          → 下次启动 boot-heal 禁用该插件并提示
```

- 插件代码**全局唯一**（`<appData>/.zn/plugins/<id>/`）；`store` 按库隔离。
- 每个 `note-*` 窗口都会重新跑一遍上面的宿主（已知代价，见 `docs/decisions/D-005-多窗口每窗口重跑App.md`）。

## 6 主流程 C：标签 → 独立窗口 → 收回

```
拖标签出界 / 右键「新窗口」→ noteWindowLabel() + ?note= → 新 WebviewWindow（完整 App）
主窗口账本 noteWindowsRef：同一篇同时只在一个窗口（再点 ⇒ 聚焦 + 提示）
收回：标题条 ⤺ 或拖出界 → saveNow → emit('zn:note-return') → close()
主窗口 listen('zn:note-return') → 标签回来
```

## 7 事件与数据流

| 事件 | 方向 | 用途 |
|---|---|---|
| `note:saved` / `note:created` / `note:renamed` / `note:deleted` / `note:changed` | 内核 → 订阅方 | 索引增量、插件刷新 |
| `index:rebuilt` | 内核 | 搜索 / 标签统计刷新 |
| `app:ready` / `vault:open` | 内核 | 插件初始化、切库 |
| `service:available` / `service:gone` | 内核 | 插件互调 |
| `zn:note-return` | 前端 emit | 独立窗口收回 |
| `zn://fs-change` | Rust → 前端 | 外部文件改动（**桌面**：Rust `notify` watcher，只报库内 `.md`；**移动端**：前端 3 秒轮询兜底） |

写入路径统一包了一层 `fs-events`：所有写操作（save/create/rename/move/delete/restore）都会更新索引并派发事件，插件不用自己扫。

## 8 关键不变量

1. 内核只做四件事（`.md` 读写 / 编辑 / 本地存储 / 插件宿主）；功能在插件。
2. 所有写入原子；删除进 `.zn/trash/`，物理删除是第二步。
3. 只接受库内相对路径；越界直接拒绝。
4. 契约与 `src/kernel/contract.ts` 一致；改契约必须同步文档并升版本。
5. 插件代码全局唯一；store 按库。
6. 文档单一事实源：状态头 + 权威矩阵 + 生成物（事实块 / 功能目录 / 键位表）。

## 10 排障入口

| 症状 | 先看 |
|---|---|
| 启动白屏 / HMR 失败 | 先 `am force-stop` 重开；桌面看 stdout 与 `_self-logs/desktop-dev.log` |
| 插件莫名消失 | 插件页 `pluginError`；内置插件写盘失败会 toast |
| 卡死 | `<库>/.zn/watchdog.log`；重启后 boot-heal 禁用并提示 |
| 内核坏了 | `修复内核.cmd` / `scripts/kernel-restore.mjs` / `_kernel-snapshots/` |
| 验收 | `pwsh -File scripts\verify.ps1`（6 步 + 5 门） |
| 当前事实 | `HANDOFF-CARD.md` 顶部 FACTS 块（自动生成） |
