# D-011 不预装任何插件：原来预装的 9 个改为「推荐优先安装」

> 状态：**accepted** ｜日期：2026-10-30（rev173.259）
> 来源：用户原话「**不设置内置插件，之前预装的改为推荐优先安装**」（B3 收尾后，2026-10-30）
> 关系：**取代 [D-010](D-010-预装范围.md)** 的「核心体验预装」结论；D-010 的逐插件归类留作历史参考。

## 决定

- 应用**不再预装任何插件**：删掉 `src/kernel/builtin-plugins.ts` 与启动写盘（`ensureBuiltinPlugins`）。
- **第一次启动 = 零插件**：内核只做四件事 —— `.md` 读写 / 编辑 / 本地存储 / 插件宿主。
- 原来的预装 9 个（标签 · 反向链接 · 历史版本 · 导入导出 · 备份 · 同步 ×4）改为**推荐优先安装**：
  - 插件中心空态列全 9 条，分两组（基础体验 5 / 多设备同步 4），每条「去安装」跳到市场；
  - 插件市场顶部一条「推荐优先安装」提示 + 条目上「推荐」标。
- 装插件只有两条路：**插件市场（需要联网）** 或 **手动装 `.znp`**。
- **已装环境不受影响**：已有插件目录不删，只是不再自动写回内置版。

## 为什么改

- 预装 = 代替用户做选择。插件与内核**同权限运行**（D-001 无沙箱），装什么应当由用户知情决定。
- 空态已经能引导（B3 的「安装 + 浏览市场 + 推荐」），不再需要「先塞进去再说」。

## 代价（如实写）

1. **离线 / 首次启动没有任何插件** —— 市场拉不到索引时只能装 `.znp`，标签 / 反链 / 历史 / 同步 / 备份都要自己装一次。
2. 新用户第一眼是空态，多一步「去装推荐」。
3. 「开箱即用」降级为「开箱 + 装推荐」；包体积确实变小（9 个插件的源码不再 `?raw` 进前端包）。

## 执行（rev173.259）

- 删 `src/kernel/builtin-plugins.ts`、`usePluginHost` 的预装调用与失败提示、`tests/builtin-plugins.test.ts`。
- `compareVersions` 迁到 `src/kernel/version.ts`（插件市场仍在用）。
- 新增 `src/lib/recommended-plugins.ts`（9 条推荐，插件中心与市场共用，避免两个组件互相 import 成环）。
- `scripts/gen-catalog.mjs` / `scripts/facts.mjs` 去掉内置清单来源；功能目录不再有「内置插件」节。
- 预装数 **9 → 0**；`HANDOFF-CARD` 的事实块改为「插件 · 市场 17 · 示例 42」。

### 已排除的兜底（用户 2026-10-30 明确「不用」）

曾提议「把 9 个已签名的 `.znp` 包随安装包分发，市场拉不到时零插件空态给『从本地包安装』按钮」——**不做**。
离线首启仍只能自己找 `.znp` 手动装。若将来离线安装转化被证明是真问题，重议入口是这条（不是恢复预装）。

### 修订：推荐清单也撤掉（rev173.280 · 2026-10-30）

用户当天又拍板「**不做推荐了**」：零插件空态里那 9 条「推荐优先安装」**移除**。

理由：清单本身是噪音 —— 用户既不知道这些插件干什么，也不知道自己需不需要；
真要装的时候进市场看条目，比看一份「推荐名单」更直接。
空态只留两个动作：**安装插件包（.znp）…** 与 **浏览插件市场**。
市场页顶部的「推荐优先安装」提示与条目上的「推荐」标一并删除
（`src/lib/recommended-plugins.ts` 与其 CSS 规则同时删掉）。

⚠️ 同轮还否掉了「装完插件弹一次入口提示」（用户：「先不，入口要找更方便的办法解决」）——
入口问题转由 J 批解决：环形快捷菜单自定义（#9）与文件树 / 时间流的右键·长按菜单（#18）。
