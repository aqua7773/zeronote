## 0 三条总原则

1. **小步可回退**：一次改动 = 一个可独立验证的单元 = 一个提交。批量合并会让「哪里坏的」无法定位。
2. **重构只搬移**：函数体、注释、分支顺序原样；改行为走功能流程（新 rev + 测试 + 证据）。
3. **先有护栏再动刀**：测试先写（或同一提交内补齐），没有测试的抽取不算完成。

## 1 目录职责与依赖方向

| 目录 | 职责 | 允许依赖 | 禁止 |
|---|---|---|---|
| `src/lib/` | 纯逻辑 / 路径 / 错误话术 / 启动自愈 | 仅标准库与其它 lib | React、kernel、DOM 渲染 |
| `src/kernel/` | 内核：契约、插件宿主、命令表、编辑器接线 | `lib` | `hooks`、`components`、`App` |
| `src/hooks/` | 状态域 hook（一个域一个文件） | `kernel`（类型或实例，经参数传入）、`lib` | `components`、`App` |
| `src/components/` | 视图组件（只收 props） | `kernel`（类型 / 少量无状态工具）、`lib` | `hooks`、`App` |
| `src/App.tsx` | 编排层：state、接线、JSX | 全部 | — |

**单向依赖**：`lib ← kernel ← hooks ← App`；`components → kernel/lib`。反方向 import 一律视为错误（当前实测无违规，grep 可查）：

```powershell
rg -n "from '\.\./hooks|from '\.\./components" src\kernel src\lib
```

**判定口诀**：这段代码**读不读 React state / ref**？
- 读 → 留在 `App`（或组件）；
- 不读、只是纯函数 → `lib`；
- 读、但属于某个可命名的域 → `hooks`。

## 2 hook 编写约定（rev123–128 的教训）

### 2.1 参数形态：refs + setters，不新增全局 state

```ts
export type UseXxxArgs = {
  kernel: Kernel | null
  refs: { activeRef: MutableRefObject<...>; ... }
  setContent: Dispatch<SetStateAction<string>>
}
```

- **state 留在 `App`**（它是渲染来源）；hook 只接收 `refs`（事件里读最新值）与 setters。
- `editorRef` 这类被其它组件 / 命令使用的 ref **必须留在 App**，只作参数传入。
- 跨 hook 共享的东西用 ref，不用模块级变量（模块级变量在热重载 / 多窗口下会串）。

### 2.2 稳定引用：供 kernel 使用的对象必须引用稳定

`docApi` 会被 `createKernel` 持有。凡是进入 kernel 的对象（docApi、host 回调）：

- `useMemo` / `useCallback` 的依赖链**只能到 ref 与 setState setter**；
- **禁止**把 `someRef.current` 写进依赖数组 —— 它一变就重建对象 ⇒ kernel 重建 ⇒ 命令表清空 / 插件重载；
- 传给接缝的 setter 类型用 `Dispatch<SetStateAction<T>>`（支持函数式更新），不要用窄类型 `(v: T) => void`。

### 2.3 依赖数组：能写全就写全；要豁免必须写原因

```ts
// 依赖只到 ref（xxxRef 是 useRef 的稳定对象）。
// 写成 `.current` 会让 xxxx 随数据变化重建 ⇒ docApi 重建 ⇒ kernel 重建，方向是错的。
// eslint-disable-next-line react-hooks/exhaustive-deps
[fireDoc, flushDocChange]
```

- 豁免注释必须满足三条：**相邻行**、说明「为什么不列」、说明「列了会坏什么」。
- 当前基线：`oxlint src` **4 warnings**（`CommandPalette` 2 + `FileTree` 2，既知）。提交后 warning 数**不得增加**。

### 2.4 `useState` 顺序

state 必须声明在**引用它的 `useCallback` 之前**（rev123 的 `undoDelete` 踩过：顺序反了会产生 `react(immutability)` warning，且回调读到旧引用）。

### 2.5 effect 顺序即执行顺序

同一轮 commit 里 effect 按声明顺序执行。依赖「另一个 effect 已同步好 ref」的 effect **必须排在后面**，并在注释里写明依赖谁（例：`useExternalFile` 的「待打开」effect 必须排在 `useDocSession` 的 `openNoteRef` 同步 effect 之后）。跨 hook 的顺序由 `App` 里的调用顺序保证。

### 2.6 文件与命名

- `src/hooks/use<Domain>.ts`，一个 hook 一个域，导出显式类型（`UseXxxArgs` / `Xxx`）。
- 注释保留原语义：为什么这么做、踩过什么坑；不要迁移时顺手删注释。
- hook 里**不写 `useState`**（状态归 App）；需要内部临时状态时先讨论是否该拆。

## 3 重构流程（每刀 checklist）

| 步 | 动作 | 判据 |
|---|---|---|
| 1 | 读 `HANDOFF-CARD.md` + 用 `rg` 重新定位目标段 | **不信任卡片里的行号**（行号会漂移） |
| 2 | 先写测试（`tests/use-xxx.test.tsx`） | 至少覆盖：正常路径 / 失败路径 / 顺序或竞态语义 |
| 3 | 记基线 | `App.tsx` 的 SHA256 + 行数 |
| 4 | 迁出：整段复制到新文件，`App` 换成 hook 调用 | 一次只动一个域；不碰无关格式 |
| 5 | 大段删除用行号脚本时 | 脚本内**断言**首尾行内容；**先改大行号段**；改完 `git diff` 逐段核对 |
| 6 | 删无用 import（tsc 会报） | `tsc -b` 0 错误 |
| 7 | 跑 `scripts\verify.ps1` | 五步全过 + warning 数不增 |
| 8 | 提交 + HANDOFF 新 rev + 卡片更新 | 一 rev 一 commit |

**禁止**：

- 用「读文件 → 字符串替换」盲删大段（先说清起止行，再用脚本 + 断言）；
- 在一个提交里同时做「搬移」和「顺手修」（review 无法区分行为变化）；
- 凭卡片行号直接 `edit`（rev122 因此误删过 `DOC_CHANGE_DEBOUNCE_MS`，tsc `TS1128`）。

## 4 测试约定

- 位置 `tests/<域>.test.ts(x)`；组件 / hook 测试**首行** `// @vitest-environment happy-dom`。
- 不碰真实 Tauri / 文件系统 / 网络：用 `vi.hoisted` + `vi.mock` 替换 `@tauri-apps/api/*`、`plugin-host`、`plugin-roots` 等。
- 每个 hook 的最低覆盖：
  1. 主流程（成功路径）；
  2. 失败 / 取消路径（错误提示、不污染状态）；
  3. 该域最贵的语义（去抖 / 去重 / 串行 / 取消 / 平台门 / 清空顺序）。
- 断言**行为**不实现：优先断言外部可观察的调用与状态（setter 收到什么、execute 参数、ref 回写），不断言内部结构。
- 测试数字以 `verify.ps1` 输出为准，不手写进文档。

## 5 验收门（提交前必跑）

```powershell
pwsh -File scripts\verify.ps1
```

五步：tsc 0 错误 · oxlint 0 error 且 warning 不增 · cargo test --lib 全过 · check-docs 全过 · vitest 全过。

- 改了 `HANDOFF.md` / `docs/` ⇒ 必须含第 4 步（`check-docs`）。
- 改了 `.ps1` ⇒ 另跑 `fix-bom.ps1 -Check`（本机规约）。
- 数字（行数 / 测试数 / warning 数）**从输出抄**，不估算。

## 6 文档约定（摘要，详见 `文档编写规范.md`）

- HANDOFF：新 rev 段**插在旧段之前**；**不替换** `> ## 📌 revN` 标题行（check-docs 靠它核对索引）。
- 每次新 rev 同时改三处：文首 `revision:` / 更新时间、索引表行、正文段。
- `HANDOFF-CARD.md` ≤ 120 行，只放现状 / 未决 / 下一步；细节回 `HANDOFF.md`。
- 新文档必须带状态头，并进 `docs/README.md` 权威矩阵。

## 7 提交与回退

- 提交信息：`refactor(revNN): 一句话（数字变化）` / `feat(revNN): …` / `fix(revNN): …`。
- 回退：`git revert <sha>`（每 rev 一个提交，天然可回退）。
- 大改前可打 tag；不要求每个 rev 都打。
