# 私密笔记改造方案（真人测试12 #1）

> 状态：**accepted**（2026-11-05 用户拍板「开工」并选择「嵌进文件树 = 改内核」）
> 权威范围：私密笔记从「独立面板」改为「开关 + 文件树虚拟分组」的实现路线
> 相关：`docs/私密文件夹-方案-2026-10-26.md`（旧方案，本文取代其入口形态）、`docs/内核契约-v0.2.md`

## 1 用户需求（原文要点）

1. 现在是一个**独立页面**：独立创建、打开（且打开无效）、删除。
2. 要改成**一个开关**：打开显示私密笔记，关闭只显示公开笔记。
3. 以**「私密笔记」文件夹**的形式显示在**文件树栏**。
4. 私密状态下其他笔记**移入就是私密**，移出就变公开。
5. 操作范围 = 普通笔记的全部行为（用户举例：检索、时间流卡片），**开启时显示、关闭时不显示**。
6. **未开启私密模式时无法被探知**。

用户已拍板的 5 项（2026-11-05）：

| 问题 | 决定 |
|---|---|
| 放哪 | **真正嵌进文件树**（改内核，约 2–3 天） |
| 范围 | **先做核心 4 项**：文件树显示 + 打开/编辑/保存 + 全局搜索 + 时间流卡片；标签/双链/导出/备份/AI 列后续 |
| 锁定后 | **整组消失**，点入口重新输密码（锁 = 关） |
| 移入/移出 | 拖拽（`FileTree` src/ 已有触摸拖拽 rev173.317）+ 菜单兜底 |
| 原生解锁 | 复用 `security` 的 `notes` 环（密码 / 指纹） |

## 3 目标行为

1. 侧栏（桌面）/ 左抽屉（手机）里多一个 **「🔒 私密笔记」虚拟分组**：关闭时不存在；解锁后出现，里面是解密后的标题列表。
2. 点击条目 → 打开编辑器（与普通笔记同一条编辑器、同一个标签条）。
3. 组内新建 / 改名 / 删除 / 拖入 / 拖出。
4. 关闭开关、空闲锁定、退出应用 → **整组消失**（同时从搜索与时间流里消失）。
5. 未开启时：文件树无节点、搜索无命中、时间流无卡片、AI 不读。

## 4 实现方案

### 4.1 内核新增一个通用原语（一次通用，不为私密单开洞）

```ts
// src/kernel/contract.ts（PluginContext 上）
notes: {
  /** 插件注册一个「额外笔记源」。宿主把它并进 FileTree / 时间流 / 搜索。 */
  registerSource(src: NoteSource): Disposable
}
type NoteSource = {
  id: string
  /** 当前条目（同步返回，宿主可随时读；解锁/锁定变化后自己 refresh） */
  list(): NoteMeta[]
  /** 分组名与图标（FileTree 用）：{ label: '私密笔记', icon: '🔒', group: 'private' } */
  group: { key: string; label: string; icon?: string }
  /** 宿主在这些变化后重新 list(): 用 `refresh()` 主动通知代替 */
  refresh(): void        // 宿主订阅 onSourceChange 重渲染
  onSourceChange(cb: () => void): Disposable
}
```

- `NoteMeta` 增加可选 `group?: string`（虚拟分组归属）+ `virtualGroupLabel?`。
- 条目 `path` **就用真实路径** `.zn/private/notes/<id>.zn`（避免再做一层 path 映射；
  打开链路 `core.openNote` 已经能读它，这正是现在插件用的方式）。
- ⚠️ 必须先验证 `core.openNote` 对 `.zn/` 路径的校验是否放行 —— 这正是现状「打开无效」的高概率原因。

### 4.2 FileTree

- `buildTree` 末尾追加：`group` 非空的条目收进对应虚拟分组（照抄「文档/附件」的写法，`virtual: true`，排在附件之后）。
- 分组行加锁图标；分组支持拖拽落点（拖入 = 调插件 `moveIn`）。

### 4.3 App

- 订阅所有 `NoteSource`，`notes` 合并后传给 FileTree / MobileNoteCards / Timeline。
- 关闭/锁定 = source 返回空数组 → 自动全部消失。
- 搜索：把 source 的条目并进索引（内存，不落盘）。

### 4.4 private-notes 插件

- 删除独立面板与列表视图（保留解锁/搜索/回收站的数据逻辑）。
- `apply()` 里 `notes.registerSource(...)`；解锁成功 → `refresh()`。
- 开关入口：桌面侧栏锁形按钮、手机「更多 → 私密笔记」保留，但行为从「打开面板」改为「开关组」。
- 空闲 3 分钟锁定 → source 返回空 → 整组消失。

## 6 风险（先写下来，动手时逐条核）

1. **`.zn` 路径的打开校验**：`core.openNote` 可能拒绝 `.zn/` 路径（现状「打开无效」的嫌疑点）。若拒 → 改走「虚拟路径 + 源提供 reader」路线，成本 +2 h。
2. **虚拟路径波及按 path 找笔记的所有地方**：重命名 / 删除 / 同步 / 标签都认 `path`。按 `docs/共享逻辑.md`，先把「path → 是否私密」收成一份纯函数再改调用点（§8 同一逻辑多处实现）。
3. **索引落盘**：搜索索引若持久化，明文标题会落盘 ⇒ 违背隐私。必须确认索引只在内存。
4. **同步**：`.zn/private` 已由四个后端放行；新链路不能破坏。
5. **AI**：需求 §3.3 明确私密内容不经过 AI —— 合并进 `notes` 后要检查 AI 插件的读取入口是否只认「公开笔记」。

## 7 验收点（G2）

1. 关闭状态：文件树无「私密笔记」组、搜索无命中、时间流无卡片。
2. 解锁后：组出现，条目可打开、可编辑、可保存。
3. 拖一篇公开笔记进组 → 公开列表消失、组内出现；拖出 → 反向。
4. 空闲锁定 → 组立刻消失。
5. 重启应用 → 默认关闭。

### 9.1 现状（代码事实，2026-11-06 核）

| 交互 | 普通笔记 | 私密笔记（现在） | 位置 |

### 9.2 目标

**同一套手势 + 同一套菜单**：私密条目长按/右键 = 弹菜单（不直接改名）；菜单项凡是"有对应语义"的都做，
只有真正无意义 / 会破坏加密边界的才不出现（§9.6 逐条写理由）。

| 剪切 / 复制 / 创建副本 / 粘贴 | **不出现**（理由 §9.6） | — |
| 重命名 | ✅ **同一套** `RenameDialog`（改显示标题，文件名仍随机） | 已有 `notes.rename` → 插件 `rename` |

| 详细… | ✅ 标题 + 密文大小 + 修改时间（不读正文） | 宿主 `entry_info`（Rust `resolve()` 已放行 `.zn/`，需实测确认 `entry_info` 同一校验） |

### 9.4 长按 / 右键 / 拖拽（移动端重点）

1. **长按 = 弹菜单**（与普通笔记一致）：触摸链 `onEnd` 允许源条目 `setMenu`；Android 派发的 `contextmenu`
   只在**没有在拖拽**时转成菜单。
2. **拖拽优先**：长按后移动 > 8px ⇒ 进入拖拽，`contextmenu` 忽略；松手执行拖出（已有 `planTreeDrop`）。
3. 桌面右键 = 同一套菜单（删除/改名/移出/详细），不再直连重命名。

### 9.5 契约与插件改动

```ts
// src/kernel/contract.ts · NoteSource 新增可选
/** 删除条目（进源自己的回收站；宿主菜单「删除」调它） */
remove?(path: string): Promise<void>
```

- `NoteSources` 加 `remove(path): Promise<boolean>`（与 `rename` 同一 `ownerOf` 口径）。
- `App` 菜单回调：源条目 → `kernel.notes.rename` / `kernel.notes.remove` / `runCore('private.move-out', { path, dir })`。
- 插件：`private.trash` 支持 `{ path }`（`idOfNotePath`）；删除后若正在打开该条目 ⇒ 关标签（避免保存到已删路径）。

### 9.6 为什么这几项**不**对齐（必须保持差异）

- **剪切 / 复制 / 创建副本 / 粘贴**：剪贴板是「公开库内搬文件」的语义。
  复制私密条目 = 明文落进公开库（直接违背需求 §3.3）；粘贴公开笔记进组 = 绕过加密进目录（应走「移入」）。
  硬做只能造出一个「看起来能用、实际泄露」的入口。
- **在文件夹中打开**：`.zn/private/notes/<id>.zn` 是密文，系统文件管理器打开没有任何意义。

### 9.7 风险

1. `private.trash` 现在只认 `id` —— 加 `path` 要处理非法/非本源路径（返回 false，不静默）。
2. 删除/移出**正在打开的那篇** ⇒ 标签要跟着关或改指，否则下次自动保存写失败。
3. `entry_info` 对 `.zn/` 是否放行未实测（`read_note` 已放行，但 `entry_info` 是另一条命令）。
4. 改动同时波及**桌面右键 / 手机长按 / 触摸拖拽**三条链 —— 一起改，别只改一条（AGENTS §8.8）。
5. 菜单项从 1 项涨到 4–5 项：手机长按菜单高度可接受，但「删除」要 `danger` + 分隔线。

### 9.8 验收点（G2 双端）

1. 桌面右键私密条目 ⇒ **弹菜单**（不再直接改名）；点「重命名」才弹对话框。
2. 手机长按私密条目 ⇒ **松手弹同一套菜单**。
3. 长按并移动 ⇒ 拖拽（可拖出到公开目录），不弹菜单。
4. 菜单「删除」⇒ 进私密回收站、可恢复；「移出」⇒ 落当前目录。
5. 「详细」显示标题 + 密文大小 + 时间。
6. 锁定 ⇒ 组消失、所有入口不可达。
7. **普通笔记菜单零变化**（回归）。

### 9.9 拍板结果（2026-11-06，用户确认）

1. **剪切/复制/创建副本/粘贴**：**隐藏**（不灰显 —— 不摆点了没反应的项）。
2. **删除后的撤销条**：**要**，与普通笔记一致（撤销 = 调插件 `restore`，把条目从私密回收站拿回来）。
3. **多选**：**保持强制单选**（跨源批量会绕过插件逻辑）。
4. 「在文件夹中打开」：隐藏（推荐项，未单独提问，按推荐执行）。
5. 「详细」：显示标题 + 密文大小 + 时间（未单独提问，按推荐执行）。
6. 「移出为公开笔记…」与「私密回收站」作为源特有项加在管理组。
7. **范围 = 只做宿主操作**（2026-11-06 追加拍板）：本轮**不碰任何插件**；标签 / 双链 / 历史版本 / 导出分享 / 桌面组件 / AI 读取单列（见 §9.11）。
8. **组内新建**：**要** —— 私密分组行右键 / 长按加「新建私密笔记」（`private.new`）。
9. **快捷键**：**要** —— F2 改名（走 RenameDialog）、Delete 进私密回收站（与普通一致）；私密条目仍强制单选。

11. **桌面组件**：**保持不显示私密**（隐私优先）。

### 9.12 实现要点（施工时照着做，别再漏）

1. **删除/改名的路由必须收口**：现在 `FileTree` 的 `onDeleteMany` / 内联 `startRename` 对源条目会走**磁盘**逻辑 ——
   快捷键（F2/Delete）与菜单必须都走 `onRenameSource` / 新增的 `onRemoveSource`，不能各写一份。

5. 三条手势链（右键 / 触摸长按 / contextmenu）与快捷键一起改，单测锁「源条目删除不走磁盘」。
