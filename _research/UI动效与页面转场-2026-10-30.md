# UI 动效与页面转场调研（2026-10-30）

## 0 结论（1 分钟版）

1. **动效只做三件事**：反馈（操作被接收）、空间关系（从哪来、到哪去）、连续性（同一个东西没被替换）。装饰性动画一律不加。
2. **常用越短**：Apple HIG 明确「应用内一般**避免**给高频 UI 交互加动画」；NN/g 的区间是 **100–500ms**，越常用越短越弱。
3. **ZeroNote 现状最大问题不是「没动画」，是「该有的没有、不该有的太长」**：
   - 标签切换 / 主区面板切换 / 设置打开：**硬切，零过渡**；
   - 标题栏显隐：**450ms**（高频，且每次鼠标离开顶部都触发）；
   - 侧栏展开 / 收起**没有过渡**（宽度直接跳变）；
   - `prefers-reduced-motion` **只覆盖标题栏**一处，其余 21 处 transition + 1 处 animation 不受控。
4. **建议数值**（三套体系交叉后的收敛值）：微交互 80–120ms、浮层 140–180ms、侧栏/抽屉 200–240ms、钻入/返回 250–300ms；**高频切换 0–80ms**。
5. **页面转场语义四种**（Windows 官方 Page transitions 的划分最贴桌面应用）：
   - **Page refresh**（同级切换：底部 tab / 图标栏视图）→ 淡入 + 极轻上移；
   - **Drill**（进入更深层级：列表 → 编辑器）→ 水平推入，返回反向；
   - **Overlay**（设置 / 命令面板 / 菜单）→ 遮罩淡入 + 面板轻微放大；
   - **Suppress**（高频：标签页切换）→ 不做，或 ≤80ms 淡入。
6. **必须全局支持 reduce-motion**：`@media (prefers-reduced-motion: reduce)` 把所有时长降到 0–80ms，且侧栏/抽屉/页面推入改为直接切换。

## 2 数值 token（三套对照 → 收敛值）

| 用途 | M3 token | Fluent | 收敛值（ZeroNote） | 缓动 |
|---|---|---|---|---|
| hover / 按压 | 50–100ms | 83ms | **80ms** | linear 或 standard |
| 开关 / 勾选 / 小反馈 | 100–150ms | 167ms | **120ms** | standard |
| 浮层出现（菜单/命令面板） | 150–200ms | 167ms | **140ms** | emphasized-decelerate |
| 浮层消失 | 100–150ms | 83ms | **110ms** | emphasized-accelerate |
| 侧栏展开 / 抽屉 | 200–250ms | 250ms | **220ms** | emphasized |
| 同级页面切换（tab/视图） | 150–200ms（fade through） | 167ms（page refresh） | **160ms** | standard |
| 钻入 / 返回（列表→详情） | 250–300ms（shared axis） | 250ms（drill） | **260ms** | emphasized |
| 标签切换（高频） | — | — | **0–80ms**（默认 0） | linear |
| 标题栏显隐（高频） | — | — | **200ms**（现状 450） | standard |
| 大范围（窗口级/整页） | 300–400ms | 250ms | **300ms** | emphasized |

**四条硬规则**：

1. 只动 `transform` / `opacity`（必要时 `width`，但拖拽时禁用 transition）。
2. 同一时刻只允许一层在做「大动作」（页面推入 + 抽屉 + 浮层不叠加）。
3. 高频交互（标签切换、标题栏、hover）默认 **0–120ms**；超过 200ms 就删掉。
4. `prefers-reduced-motion: reduce` 下：**所有过渡 ≤80ms 或 0**，页面推入改为直接切换。

## 4 目标：转场语义（对号入座）

| 语义 | 用在 | 运动 | 时长 | 缓动 |
|---|---|---|---|---|
| **同级切换**（Sibling） | 底部 tab、图标栏视图（文件/搜索/时间流）、设置内 tab | 内容交叉淡入 + 2px 上移 | 160ms | standard |
| **钻入**（Drill） | 手机列表 → 编辑器；桌面文件树 → 笔记（可选） | 新内容从右滑入 24px + 淡入，旧内容左移 8px 淡出；返回反向 | 260ms | emphasized |
| **浮层**（Overlay） | 设置、命令面板、搜索、菜单、QuickLaunch | 遮罩淡入 120ms；面板 opacity 0→1 + scale .98→1 | 140ms | emphasized-decelerate |
| **高频**（Suppress） | 标签页切换、标题栏显隐、hover | 0 或 ≤80ms 淡入 | 0–80ms | linear |
| **连续**（Container） | 卡片 → 编辑器（共享元素） | v1 不做（需 FLIP/View Transitions，收益低于成本） | — | — |

**方向规则**：只有「钻入/返回」有方向（水平）；同级切换**不用水平滑动**（避免用户以为有前后顺序）。

## 6 实现建议（不写代码，只定结构）

1. **token 化**（`styles.css` `:root`）：
   ```css
   --zn-dur-hover: 80ms;
   --zn-dur-fast: 120ms;
   --zn-dur-base: 160ms;
   --zn-dur-panel: 220ms;
   --zn-dur-drill: 260ms;
   --zn-ease-standard: cubic-bezier(0.2, 0, 0, 1);        /* M3 standard */
   --zn-ease-decel: cubic-bezier(0, 0, 0, 1);             /* Fluent 进入 */
   --zn-ease-accel: cubic-bezier(0.3, 0, 1, 1);           /* 退出 */
   --zn-ease-emph: cubic-bezier(0.2, 0, 0, 1);
   ```
2. **全局降级**：
   ```css
   @media (prefers-reduced-motion: reduce) {
     *, *::before, *::after {
       animation-duration: 1ms !important;
       transition-duration: 1ms !important;
     }
   }
   ```
   JS 侧：`matchMedia('(prefers-reduced-motion: reduce)').matches` 决定是否走「钻入」。
3. **页面切换的实现路径**：React 条件渲染 + CSS `@starting-style`（Chromium 117+，WebView2/Android WebView 均满足）或 keyframes；不引入动画库。
4. **拖拽类**（侧栏宽度、抽屉跟手）：拖动中 `transition: none`，松手后再启用过渡；**不要**用 `transition` 做跟手。
5. **禁止**：`will-change` 长驻、`height: auto` 过渡、同时动画 3 个以上属性、页面切换用 `left/top`。
