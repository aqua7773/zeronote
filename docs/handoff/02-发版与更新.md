# 发版与更新

> 状态：**active** ｜最后核对：2026-11-04 ｜权威范围：从版本号到两渠道 Release 的完整流程
> 从 `HANDOFF-CARD.md` 拆出并首次成文（2026-11-04，0.9.29 发错包之后）。**发版前逐条对照本文。**

## 0 一条铁律

**不发布 universal APK**（4 个 ABI 各 31 MB ⇒ 121 MB）。README 与历史一致口径：安卓包按 CPU 架构分开发。
0.9.25 的 121 MB 是唯一例外（修卡顿专用），0.9.26–0.9.28 都是 33 MB 的 arm64 包。

## 0.1 发版前置：双端验收（2026-11-06 用户拍板）

**除非本次改动确实只涉及单端**（HANDOFF 段写明「仅桌面」/「仅 Android」，且另一端二进制与资源未变），否则发版前必须**双端验收通过**：桌面 G2 + 手机真机 G2，再走 G3。

- ⛔ 不许用「Rust 改动要新包」当先发版的理由 —— 先 `android-dev.cmd` 重编 dev 包在真机验。
- 验收清单写在 HANDOFF 段里，「未验」项必须先清掉或明确标「仅单端改动，另一端不适用」。

## 1 版本号怎么定 + 改哪三处

**口径（语义化版本 `MAJOR.MINOR.PATCH`，2026-11-04 用户确认）**：

| 位 | 含义 | 项目实际用法 |
|---|---|---|
| **MAJOR**（第一位） | 不兼容的大改 | 至今是 **0** —— 意思是「别把它当稳定 API 依赖」；到 1.0 才承诺接口稳定 |
| **MINOR**（第二位） | 成批新功能 / 里程碑 | 0.8.0 = UI 重布局 B1–B7 · 0.9.0 = 真人测试 20 条全修 |
| **PATCH**（第三位） | 修复与小改进 | 0.9.x 里绝大多数（0.9.30 = 插件市场 / 同步三处修复） |

**口诀**：这次发版有没有「用户可感知的新功能面」？有 ⇒ MINOR+1、PATCH 归零；只有修 bug / 小改 ⇒ PATCH+1；动了不兼容的协议或数据格式 ⇒ MAJOR+1。
⚠️ 插件版本（`examples/*/manifest.json` 的 `version`）与契约版本（`apiVersion`）是另外两套号，别和应用版本混。

改这三处 + lock：

```
package.json          "version"
src-tauri/tauri.conf.json  "version"
src-tauri/Cargo.toml  [package] version
src-tauri/Cargo.lock  跟随（cargo 自动）
```

另有：`CHANGELOG.md` 新段 + 版本表、`README.md` 现状行、`docs/ROADMAP.md` §0。

## 2 构建

```powershell
node scripts/build-release.mjs          # 双端，约 8 分钟
node scripts/build-release.mjs --android # 只编 Android
```

产物：

- 桌面 `src-tauri/target/release/bundle/nsis/ZeroNote_<ver>_x64-setup.exe` + `.sig`（15 MB 级）
- Android `src-tauri/gen/android/app/build/outputs/apk/<abi>/release/app-<abi>-release.apk`

## 3 APK 必须改名 + 确认架构

Gradle 产物名**不含版本号**（`app-arm64-release.apk` / `app-universal-release.apk`），必须复制成：

```
ZeroNote_<ver>_arm64.apk        # 默认发布这个（33 MB）
```

**发版前核对**（这一步漏了就是 0.9.29 那样）：

```powershell
# 预期 ≈33 MB；≈121 MB 说明是 4 ABI 的 universal，不许发
Get-ChildItem *_arm64.apk | Select-Object Name,@{n='MB';e={[math]::Round($_.Length/1MB,2)}}
```

命名约定见 HANDOFF rev173.299「踩坑」段。

## 4 生成更新清单（必做，否则应用内收不到新版）

```powershell
node scripts/gen-update-manifest.mjs --write
```

产出两个文件，**随本次发版一起提交**：

| 文件 | 用途 |
|---|---|
| `update/latest.json` | 桌面（Tauri static JSON，`platforms.windows-x86_64`） |
| `update/android.json` | Android（`version` / `apk.url` / `apk.sha256` / `apk.size`） |

⚠️ 0.9.29 就是漏了这步：tag 发了，清单还停在 0.9.28 ⇒ 应用内看不到新版。

## 5 发布

**GitHub**（gh CLI 已登录，token 在 keyring，不用每次输入）：

```powershell
gh release create v<ver> <exe> <sig> ZeroNote_<ver>_arm64.apk --title "..." --notes "..."
```

**Gitee**（走 API，令牌在用户级环境变量）：

```powershell
$t = [Environment]::GetEnvironmentVariable('GITEE_TOKEN','User')   # 本会话 $env: 读不到
# 建 release
POST https://gitee.com/api/v5/repos/legendary-bird-lin/zeronote/releases
# 传附件（access_token 放 query，放表单会 401）
POST .../releases/{id}/attach_files?access_token=$t   -Form @{ file = $item }
```

**限制**：Gitee 单文件 ≤ **100 MB**；universal 传不上，只有 arm64 能上。上传后等几秒再查附件列表。

## 6 发版后自检（缺一不可）

1. 两个 Release 页面的资产：**arm64 + 33 MB 量级**，不是 universal
2. `update/android.json` 的 `version` == 本次版本，`apk.sha256` 与本地文件一致
3. 手机「关于 → 更新」切渠道检查，能看到新版本
4. `git push` 两个远端都通（GitHub 偶发 500，重试即可；push 成功前不算发完）
