## 5. 明确不做（附理由）

- **跨库全局替换** —— 本地文件直接落盘，误替换不可逆
- **文件树拖拽手动排序** —— 文件系统才是真源，会与排序规则打架
- **`Ctrl+B` 切侧栏** —— 笔记应用里必须留给加粗
- **为 <1s 的操作加骨架屏** —— 会闪，反而降低感知性能
- **`Esc` 关闭笔记 / 退出应用** —— 与「Esc 逐层退出」心智冲突，且与 `Ctrl+W` 重复
- **常驻「保存」按钮** —— 自动保存下永远可点，制造"没保存"错觉
- **崩溃恢复（Hot Exit 等价）** —— 800ms 自动保存 + 失焦/切换/关窗 flush 已把最坏损失压到 800ms，再建 recovery 体系属过度工程
- **定期快照（File recovery 等价）** —— 版本历史属插件题材，不进内核

## 7. 建议顺序

1. **第一批（P0 的 1–3）**：键位修正 → 删除策略 → 撤销栈
   —— 这三项是「交互规则完善」的核心，且都是**用户能立刻感知**的
2. **第二批（P0 的 4–7）**：位置记忆 → 自动保存兜底 → 焦点圈/Esc → 错误文案
3. **第三批（P1）**：标题栏尺寸 → 侧栏入口 → `Ctrl+O` → 查找替换 → 面板增强
