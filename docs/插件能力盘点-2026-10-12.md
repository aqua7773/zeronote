### 1.8 CSP（2026-10-12 从 `null` 落地；同日按用户裁决**放宽 `connect-src`**）

> ⚠️ **rev2 更正（2026-10-12 下午，本段初版有错，连带 §3.3 的「领先 L4」与 §2.6 的结论一起作废）**
>
> 初版写「白名单外 `fetch(example.com)` 被 **CSP** 拦掉」——**归因错误**。插件侧报的
> `TypeError: Failed to fetch` **CORS 与 CSP 都会产生**，要分辨只能看 `adb logcat`：
> · CORS → `Access to fetch at … has been blocked by CORS policy`
> · CSP → `Refused to connect to … because it violates … Content Security Policy directive`
>
> 真机 logcat 显示那次是 **CORS**（`baidu.com` 不返回 `Access-Control-Allow-Origin`）。
> ⇒ 两条结论作废：①「CSP 实测把随手联网升级为改配置重打包」；②「唯一比 Obsidian/Yank Note
> 强的硬事实是 CSP 实测」。**CORS 才是插件作者第一道撞上的墙。**
> 用户随后裁决**放宽** `connect-src`，新配置与新实测见下。

`src-tauri/tauri.conf.json` 当前实际值：

| 指令 | 值（原文） |
|---|---|
| `default-src` | `'self'` |
| `connect-src` | `'self' ipc: http://ipc.localhost https: http: ws: wss:` ← **2026-10-12 按用户裁决放宽** |
| `img-src` | `'self' asset: http://asset.localhost data: blob:` |
| `style-src` | `'self' 'unsafe-inline' https://cdn.jsdelivr.net` |
| `font-src` | `'self' data: https://cdn.jsdelivr.net` |
| `script-src` | `'self' 'unsafe-inline' 'unsafe-eval' blob: https://esm.sh`（**未放宽**：远端模块仍限 `esm.sh`） |
| `frame-src` | `'self' data: blob: asset: http://asset.localhost http: https:` |
| `object-src` / `base-uri` / `form-action` | `'none'` / `'self'` / `'none'` |

**真机三重对照（`examples/net-demo/` 三个按钮，2026-10-12）**：

| 靶子 | 过几关 | 结果 |
|---|---|---|
| ① `https://esm.sh/…`（有 CORS） | CORS ✅ + CSP ✅ | HTTP 200 |
| ② `https://www.baidu.com/`（**无** CORS 头） | CORS ❌ | 被拦；logcat 明写 `blocked by CORS policy` |
| ③ `https://registry.npmmirror.com/vue/latest`（有 CORS、**原本不在白名单**） | 两关都过 | **HTTP 200（7184 字节）** ⇒ 放宽生效 |

**精确读法**：CSP 是**整应用级**、不是逐插件级；`script-src` **仍受限**（远端模块只能来自 `esm.sh`）；
`invoke` 路径完全不受 CSP 约束（契约 §4.2）。**未验证**：白名单期是否真的拦过某次 `fetch`（本轮无回测）。

**ZeroNote 的位置**：**声明字段有、强制没有** ⇒ 相对 NoteGen（会拒载）和 VS Code（Web 端直接忽略）**落后**；但**双端跑通这件事本身**在笔记应用里不算普遍（SilverBullet/Yank Note 的插件面主要是桌面/浏览器），ZeroNote 的"同一份 JS 插件在 Android 真机加载"有实测证据（HANDOFF:435、`docs/evidence/m4-android-plugin-first-run.png`）。
