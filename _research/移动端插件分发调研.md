## 0. 结论速览

| 项目 | 库/工作区放哪（Android） | 用户怎么装插件 | 用 SAF 吗 | 移动端插件有差异吗 |
|---|---|---|---|---|
| **Obsidian** | 启动时二选一：**device storage（共享、推荐）** 或 app storage（私有）。共享模式需 "All files" 权限 | 应用内 Community plugins → Browse → Install；也可手动拷到 `<vault>/.obsidian/plugins/` | **不用 SAF**，用 **All files access**（官方明说） | 官方未写移动端功能差异；插件安全声明「无法限制插件权限」 |
| **Logseq** | 用户用系统选择器**自选任意目录**当 graph（SAF） | **移动端不支持插件**（社区+官方推文转述）；桌面有 marketplace | **用 SAF**（源码处理 content:// 与 DocumentsContract） | 有大差异：插件组件系统未就绪 |
| **Joplin** | 未核实具体默认路径 | **桌面 + 移动都支持插件**；Android 配置里还能 "Install from file"（.jpl）；**iOS 只能装推荐插件**（App Store 指南） | 未核实 | 有：插件跑在 WebView `<iframe>`，manifest 必须声明 `platforms` 含 `mobile` |
| **SiYuan** | **应用私有目录**（app-specific）；社区 fork 才改成共享存储 | **移动端没有市场入口**；官方答复：开 Network serving，用电脑浏览器连手机装 | 不涉及（私有目录）；fork 实现未核实 | 官方把这当已知限制，非技术不可能 |
| **Anytype** | 未核实 | **无插件体系**；扩展走 **Local API，仅桌面**（localhost） | 未核实 | 无移动端扩展能力 |
| **AppFlowy** | 未核实 | **没有用户可装插件市场**（FR #718 自 2022-07 至今 open）；只有编辑器代码级插件 | 未核实 | — |
| **Notesnook** | 未核实 | **无扩展 API**：官方 roadmap 列 "Notesnook Extensions API — Planned" | 未核实 | — |
| **Anki / AnkiDroid** | AnkiDroid 默认在**用户存储区**（照片/下载同级），设置里可改 | **AnkiDroid 不支持 add-ons**（官方 FAQ 给理由）；桌面 Anki 支持 Python add-ons | 未核实（官方称外置 SD 卡不受支持） | **有明确先例 + 明确理由**（见 §3e） |
| **KOReader** | Android 上 `koreader` 文件夹在 **SD 卡（公共存储）** | user patch：放 `koreader/patches/数字-名字.lua`；FDroid 版不生效 | 未核实 | 无差异，靠 Lua 补丁 |
| **Kiwi Browser**（横向先例） | — | Android 浏览器**跑 Chrome 扩展**；2025-01 归档，能力移交 Edge Canary | — | 证明 Android 平台本身允许扩展 |

**一句话**：成熟项目里，**把库放公共存储（或让用户自选目录）是主流**；私有目录只有 SiYuan 这么做，而它正是因为这一点被社区 fork 掉、并且在「移动端装插件」上只能给局域网变通方案。**「移动端不能有插件」不是 Android 平台铁律**——Obsidian 和 Joplin 都在 Android 上装第三方插件，限制主要来自 **iOS 商店政策**与**插件运行沙箱**（只能跑 HTML/JS）。

## 1. Obsidian

### 1.1 官方文档：库位置是**启动时让用户选**

来源：`obsidianmd/obsidian-help` 仓库 `en/Obsidian/Obsidian for Android.md`（对应网页 <https://obsidian.md/help/android>）**[官方]**

- 原文要点："When you launch Obsidian on Android, you'll be asked to choose where your vault data should be stored. You can choose **device storage** (recommended) or **app storage**."
- **device storage**：数据放在设备的**共享位置**，"allows your Obsidian vault to be accessed by other apps and services, such as third-party sync tools"；是推荐项，因为与同步工具兼容、**卸载应用数据仍在**；代价是 "requires additional permissions"。
- **App storage**：放在 Obsidian 的**私有应用存储**；官方警告：用这个选项**卸载 Obsidian 会删掉本地笔记**；且不能用 Syncthing 这类依赖共享存储的工具。
- 权限做法（关键）："Due to limitations with Android, Obsidian will request **"All files" access** to function reliably. Google recommends this for apps like Obsidian which are considered "document management apps"." 并链接 <https://developer.android.com/training/data-storage/manage-all-files>。

> 对 ZeroNote 的意义：Obsidian **没有用 SAF** 去解决「访问用户可见目录」，而是走 `MANAGE_EXTERNAL_STORAGE`（All files access），并用「document management app」这一 Google 认可的分类来申请。SAF 的 content:// 语义和「直接路径」模型的冲突，被它绕开了。

### 1.2 插件分发

- **应用内安装**（官方）：`en/Extending Obsidian/Community plugins.md` **[官方]** —— 打开设置 → **Turn on community plugins**（关闭 Restricted mode）→ **Browse** → Install。也可在浏览器上逛 <https://community.obsidian.md>。
- **手动安装**（社区，安卓实操）：PKMer 教程《PKMer 插件安卓端安装手把手教程》 <https://pkmer.cn/Pkmer-Docs/10-obsidian/obsidian社区插件/pkmer-market/pkmer插件安卓端安装手把手教程/> **[社区]**：
  - 明确写了前提："由于移动端 Obsidian 本体并不向桌面端一样，在「设置」→「第三方插件」中存在一键进入 Ob 插件文件夹的入口"；
  - 流程：用**能看隐藏文件的文件管理器**进到库文件夹 → 进 `.obsidian` → 新建/进入 `plugins` → 把解压出的插件文件夹粘进去 → 回 Obsidian「第三方插件」点刷新。
  - 这意味着：**只要库在共享存储，用户用手机自带文件管理器就能装插件**——不需要电脑、不需要 USB。
- **插件权限模型**（官方）：`en/Extending Obsidian/Plugin security.md` **[官方]** —— "Due to technical limitations, Obsidian cannot reliably restrict plugins to specific permissions or access levels. This means that plugins will inherit Obsidian's access levels."，并列出插件能读文件、联网、装程序。
- 该页 frontmatter 含 `mobile: false` —— **含义未核实**（可能是帮助站点的导航标记，不能据此推断移动端不支持插件；事实是移动端能装社区插件）。
- **iOS**：本次未找到 Obsidian 官方关于 iOS 插件安装限制的页面 → **[未核实]**。

## 2. Logseq

### 2.1 图库（graph）位置：用户自选目录，走 SAF

- 社区论坛（官方人员回复）：<https://discuss.logseq.com/t/where-do-i-find-my-vault-on-mobile-how-to-create-a-button-with-a-function-on-android/29531> **[社区]** —— 在 `☰` → "Logseq" 下拉 → "All graphs" → **"Open a local directory"**，其位置由用户选；移动位置要在应用外把文件搬走再重新添加。
- **源码级证据**：`logseq/logseq` 的 `android/app/src/main/java/com/logseq/app/FileUtil.java`（<https://github.com/logseq/logseq/blob/master/android/app/src/main/java/com/logseq/app/FileUtil.java>）**[源码]**：
  - 文件头注释直接引用了 *"how to get the real path with ACTION_OPEN_DOCUMENT_TREE intent"* 的 StackOverflow 答案；
  - 代码处理 `DocumentsContract.isDocumentUri`、authority `com.android.externalstorage.documents`、`content://` scheme，把 SAF 返回的 URI 换算成真实路径；
  - 代码里显式映射 `Documents/`、`Download/`、`/storage/<type>/...`；
  - 注释写着："NOTE: It's not a good idea to use storage root as Graph root."

> 结论：Logseq Android **使用 SAF（ACTION_OPEN_DOCUMENT_TREE）选目录**，然后把 URI 转成真实路径去读写——库在公共存储，用户可见。

### 2.2 插件分发：移动端不支持

- 论坛主题《What are barriers to mobile plugin support?》 <https://discuss.logseq.com/t/what-are-barriers-to-mobile-plugin-support-seeking-context-before-fr/16092> **[社区]**：
  - 2023-03 提问；版主引用**团队推文**（<https://mobile.twitter.com/DerScheinriese/status/1613907121266999300>）作为答复；提问者总结"mobile plugin support would need to be enabled explicitly by Logseq, and they intend to do so after releasing their plugin component system"；
  - 版主 2023-03-20 回复：跟踪 GitHub PR <https://github.com/logseq/logseq/pull/8787>，"has no mention of this so I think it still remains an internal project"；并给了变通办法——不涉及移动不兼容 UI 的插件，可以**通过导入自定义 js/css** 碰运气（举例 logseq-awesome-content 的 CSS for mobile）。
  - 2023-08 仍无进展。
- **未找到** Logseq 官方文档里「移动端不支持插件」的正式声明页 → 该结论是**社区+官方推文转述**级别，不是官方文档。

## 3. Joplin（**重要反例：移动端是支持插件的**）

- 官方文档《Plugins》 <https://joplinapp.org/help/apps/plugins/> **[官方]**，第一句就是：
  > "The **desktop** and **mobile** apps have the ability to extend beyond their standard functionality by the way of plugins."
- 安装方式（同一页）**[官方]**：
  - 应用内 Plugins 页搜索 + Install（插件托管在 <https://github.com/joplin/plugins>），也支持手动装 `.jpl` 文件；
  - **Android**：`Install from file` 按钮位于配置界面 Plugins 标签的 **"Advanced settings"** 下；
  - **iOS 限制**（原文）："To adhere to AppStore guidelines, the iOS app only allows installing recommended plugins."
- 移动端插件的运行方式与差异（官方开发者文档《Debugging mobile plugins》 <https://joplinapp.org/help/api/references/mobile_plugin_debugging/>）**[官方]**：
  - "On mobile, all plugins run in `iframe`s within a `WebView`."（Android 可用 Chrome DevTools 远程调试这个 WebView）
  - 插件若报 **"incompatible with Joplin mobile"**，需要在插件 `manifest.json` 里加 `"platforms": ["mobile", "desktop"]`；
  - 还有专门的 web 构建（`app.joplincloud.com`）可直接从 `.jpl` 安装插件，便于开发。
- 佐证「移动端插件仍在持续适配」的上游 PR（未逐条读全文，仅标题级证据）**[第三方/GitHub]**：`#12890 Mobile: Fixes #12880: Fix plugin support`、`#13077 Mobile: Plugin API: Fix compatibility with certain plugins targetting the desktop app`、`#15095 Mobile: Load plugin scripts directly from filesystem instead of passing through bridge`。
- **Joplin 的库（profile/notes）在 Android 上默认放哪：未核实**（本次未取到官方说明页）。

> 对 ZeroNote 的意义：**「移动端插件」有成熟的商业化实现路径** —— 插件跑在 WebView/JS 沙箱里，插件声明自己支持哪些平台，商店政策只在 iOS 上施加白名单限制。

## 4. SiYuan 思源笔记（**与 ZeroNote 同病相怜的案例**）

### 4.1 官方 issue：移动端装不了插件

- issue [#14509 "Allow installing plugins on mobile"](https://github.com/siyuan-note/siyuan/issues/14509)（2025-04-04 提出，同日 closed/completed，已锁定）**[官方回复]**：
  - 提议者原文："Currently, it isn't possible to use the marketplace on mobile devices, which makes it impossible to install plugins on mobile unless you have sync enabled and have already installed the plugins on a desktop device."，并建议至少支持**从 zip 安装**。
  - **官方维护者（88250, MEMBER）答复**："Please turn on the `Network serving` function, and then use the browser on your computer to access SiYuan on mobile to install the marketplace package."
  - 后续评论里有人反馈这样访问市场看不到包，另一位贡献者说重启 App 后正常；最终提问者"装了 GitHub 版（而非 F-Droid 版）就好了"。
  - 2026-02 又有用户报告 F-Droid 版同样问题（<https://github.com/siyuan-note/siyuan/issues/14509#issuecomment-3887645277>）**[社区]**。

> 官方立场 = 「移动端不提供市场，用局域网网络伺服从电脑装」。这是个**回避型方案**，不是不可能。

### 4.2 工作空间在**应用私有目录** —— 社区 fork 才修好

- 第三方 fork `vufly/siyuan-fork` README <https://github.com/vufly/siyuan-fork> **[社区]**，原文：
  > "The original Siyuan Android app **stores workspaces in an app-specific directory, which prevents third-party apps from accessing the data.** This limits the ability to use third-party synchronization services. This fork addresses this issue by: Allowing users to choose a folder in shared storage as the home directory for their workspaces..."
  - fork 还加了警告：放共享存储意味着数据对其他有权限的 App 可见，有安全风险。
  - 该 fork 的目录转换代码借鉴了 **Logseq** 的 `FileUtil.java`（同一 SAF 思路）。
- 另见数据损坏 issue [#9588](https://github.com/siyuan-note/siyuan/issues/9588)（Android 上嵌套文件被删）**[社区]** —— 与目录模型相关的风险线索，但不构成本次结论，仅记录。

> 这就是 ZeroNote 的镜像处境：**库在私有目录 ⇒ 第三方工具（同步/文件管理器）看不到、用户放不进插件**，社区只能 fork。

## 6. Anki / AnkiDroid（**最完整的「不支持」先例与理由**）

### 6.1 AnkiDroid 官方 FAQ 原文（关键段落）

来源：`ankidroid/Anki-Android` wiki FAQ，`# I want Add-Ons in AnkiDroid` 一节
<https://github.com/ankidroid/Anki-Android/wiki/FAQ>（raw: <https://raw.githubusercontent.com/wiki/ankidroid/Anki-Android/FAQ.md>）**[官方]**：

> "We understand AnkiDesktop supports Add-Ons. However, **AnkiDroid does not and cannot support Add-Ons in the same way. Mobile operating systems do not let applications download and run code that was not packaged with the application. Neither iOS nor Android allow this**, and if you think about the disaster that is desktop security (with viruses and crypto-ransoms etc), you will understand. **The only exception is HTML and Javascript, so AnkiDroid is working on support for Javascript Add-Ons.**"
>
> 后续给了两条路：(a) 用 genanki + pyodide 把 add-on 写成**网页应用**（举例 image-occlusion-in-browser、ocloze）；(b) 在 **Termux 里装 Anki Desktop** 用真 add-ons（"highly technical"，无支持）。

### 6.2 AnkiDroid 库位置：**用户存储区**

同一 FAQ 的 "Change in device storage configuration" 一节 **[官方]**：

> "By default, AnkiDroid stores its data in your device's **default user storage area (the same place where your photos and downloads go)**. Note that this location is different from where your applications are installed, so **uninstalling and reinstalling AnkiDroid will generally not have any effect on your flashcard data**."

- 用户可在 `AnkiDroid settings > Advanced > AnkiDroid directory` 看到/改当前目录；官方**不建议**改；**外置 SD 卡不被官方支持**（"External SD cards are not officially supported"）。
- 桌面 Anki 的 add-ons：官方手册 <https://docs.ankiweb.net/manual/addons> —— Tools > Add-ons > Get Add-ons，或 ankiweb.net/shared/addons **[官方]**。
- AnkiMobile（iOS）手册目录里**没有** add-ons 章节（<https://docs.ankiweb.net/ankimobile/intro>）**[官方]**；但本次未取到"AnkiMobile 不支持 add-ons"的逐字官方原句 → 该点 **[未核实]**。

## 7. KOReader（Android 上的 user patch 机制）

来源：KOReader 官方 wiki《User patches》 <https://github.com/koreader/koreader/wiki/User-patches> **[官方]**：

- "It is necessary to create a subfolder named `patches` in the `koreader` folder. **(On Android this folder is located on the SD-card.)**"
- patch 文件：Lua 代码，扩展名 `.lua`，文件名**必须以数字 + 短横线开头**（`1234-name-of-the-patch.lua`），首位数字决定执行时机：
  - `0` 更新后仅执行一次；`1` 每次启动很早执行；`2` UIManager 就绪后；`3–7` 保留；`8` 退出前、设置保存前；`9` 退出前。
- **已知限制**：Android 上 **FDroid 版不支持 user patch**（包名 `org.koreader.launcher.fdroid`），必须装官方 release 版（包名 `org.koreader.launcher`）——
  > "On Android user patches don't work in the FDroid version of KOReader."
- 开发者态度："only limited support _might_ be given by the KOReader developers."；社区有专门的 patch 收集仓库（如 `chiahsien/KOReader.Patches`）**[社区]**。

> 对 ZeroNote 的意义：**「把补丁/插件放进用户可见的目录」是 Android 上最省事、最经得起时间考验的分发方式**（KOReader 一直这么做）；而且**包名/安装渠道会决定插件能不能被加载**（FDroid 版沙箱不同）——ZeroNote 若走「共享目录 + 直接路径」，也要注意多渠道包（Google Play / F-Droid）的存储权限差异。

## 8. 其它「移动端有扩展机制」的先例

- **Kiwi Browser（Android）**：官方仓库 README（<https://github.com/kiwibrowser/src.next>）**[官方]** 说明它支持在 Android 上跑 Chrome 扩展；但 **2025 年 1 月起已归档**，能力迁移到 **Microsoft Edge Canary**（"The extensions code for Kiwi Browser also has been integrated into the development version of Microsoft Edge"，并给出 "Extension install by id" 的开发者选项步骤）。→ Android 平台**能**跑第三方扩展（浏览器是 WebView/Chromium 体系）。
- **Firefox for Android**：2023-12 起开放扩展支持（据报道 450+ add-ons）**[第三方]** —— 来源为 Gigazine 报道 <https://gigazine.net/gsc_news/en/20231215-android-firefox-addon-debut/>，官方博客未逐字核实。Firefox 仍是「扩展需经 Mozilla 审核/推荐列表」的模型。
- **Android 上的 Termux**（AnkiDroid FAQ 提及）：不是插件体系，但证明 Android 能跑任意解释型代码 —— 代价是「极技术、无支持」。

## 9. 必答问题逐条结论

### a. 库（vault / graph / notebook）在 Android 上放哪？用户文件管理器能看到吗？

| 项目 | 结论 | 证据 |
|---|---|---|
| Obsidian | **两种都支持，官方推荐共享存储**：device storage（共享，需 All files 权限）或 app storage（私有，卸载即删） | [官方] <https://obsidian.md/help/android> |
| Logseq | **用户自选目录（共享存储）**，用 SAF 选 | [源码] `FileUtil.java` + [社区] 论坛 29531 |
| SiYuan | **应用私有目录**（app-specific），第三方 App 与文件管理器访问不到 | [社区] vufly/siyuan-fork README |
| AnkiDroid | **用户存储区**（与照片/下载同级），可在设置里查看/更改 | [官方] AnkiDroid wiki FAQ |
| KOReader | **SD 卡（公共存储）** 上的 `koreader` 文件夹 | [官方] KOReader wiki User patches |
| Joplin / Anytype / AppFlowy / Notesnook | **未核实** | — |

**总结**：能查到的主流项目，**没有一个把「用户数据」锁在应用私有目录里当默认**；私有目录只在 Obsidian 作为**可选项**（并明确警告卸载即删）、在 SiYuan 作为**默认（被社区 fork 修正）**出现。

### b. 用户怎么把插件装进去？

- **应用内市场/搜索安装**：Obsidian（Community plugins → Browse）[官方]；Joplin（Plugins 页搜索，Android 额外支持 Install from file 装 `.jpl`）[官方]。
- **手动放文件夹**：Obsidian Android（PKMer 教程：文件管理器 → `<vault>/.obsidian/plugins/`）[社区]；KOReader（`koreader/patches/`）[官方]。
- **从系统文件选择器导入**：Joplin Android 的 "Install from file"（`.jpl`）[官方]；SiYuan 用户请求 zip 导入但**未实现**（官方只给网络伺服变通）[官方回复]。
- **完全不支持**：Logseq 移动端 [社区]；AnkiDroid（原生 add-ons）[官方]；Anytype（无插件体系）[官方]；Notesnook（Extensions API 仅 Planned）[官方]；AppFlowy（无市场）[官方]。

### c. 用没用 SAF？

- **用了 SAF**：Logseq（[源码] `FileUtil.java` 处理 `ACTION_OPEN_DOCUMENT_TREE` / `content://` / `DocumentsContract` 并换算真实路径）；SiYuan fork 借用了同一套代码（[社区]）。
- **没用 SAF，改用 All files access**：Obsidian（[官方] 明说 "will request "All files" access"，引 Google 的 manage-all-files 文档）。
- **Tauri 侧现状（对 ZeroNote 直接相关）**：
  - 官方 **没有**内建 SAF 支持。issue <https://github.com/tauri-apps/tauri/issues/11733> "[docs] Android File System Access"（2024-11 开，**至 2026 仍 open**，2 评论）[社区/GitHub]：
    - 2025-03 评论（skorphil）："TLDR: **Tauri can access file only in limited number of directories without asking permissions. There is still no plugin to request storage access.**"（他还写了实验项目 `skorphil/tauri-fs-android-starter`）；
    - 2025-09 评论给出**第三方**解决方案：`tauri-plugin-android-fs`（<https://github.com/aiueo13/tauri-plugin-android-fs>）。
  - 该第三方插件 README（<https://raw.githubusercontent.com/aiueo13/tauri-plugin-android-fs/main/README.md>）**[第三方]**：提供 `AndroidFs`（读写/元数据）、**`Picker`（文件/目录选择、保存对话框、所选条目的权限管理）**、`Opener`、`PublicStorage`（公共目录）、`PrivateStorage`（应用私有目录）、`AppStorage`、`CustomFileProvider`；**API 以 URI（`FsUri`）为中心而不是路径**；默认不引入需 Google Play 额外审查的权限。→ 这基本就是把 SAF（含持久化 URI）包成了 Tauri 插件。
- Android 官方 SAF/持久化权限的规范页：<https://developer.android.com/training/data-storage/shared/documents-files> **[官方]**（本次抓取被截断/回退到德语版，**未逐字核实**，仅作规范出处；核心语义：`ACTION_OPEN_DOCUMENT_TREE` + `takePersistableUriPermission` 可跨重启持久访问所选目录）。
- Joplin / AnkiDroid / KOReader 是否用 SAF：**未核实**（AnkiDroid 官方仅表示外置 SD 卡不受支持）。

### d. 移动端插件能力与桌面端有差异吗？为什么？

有差异，原因分两类：

1. **技术/沙箱限制（真实存在）**
   - AnkiDroid [官方]：移动 OS 不允许应用下载并执行**未随包打包的代码**，唯一例外是 **HTML/JavaScript** ——所以它只能做 JS add-ons。桌面 Anki 的 Python add-ons 无法照搬。
   - Joplin [官方]：移动端插件跑在 **WebView 的 `iframe`** 里（不是 Electron/Node 环境），插件必须在 manifest 里声明 `platforms` 含 `mobile`，否则报 "incompatible with Joplin mobile"。
   - Obsidian [官方]：插件权限无法细分，插件继承宿主权限（桌面移动同理）。
2. **商店政策限制（iOS 独有）**
   - Joplin [官方]：**"To adhere to AppStore guidelines, the iOS app only allows installing recommended plugins."**
   - 同一现象在 Obsidian iOS 上存在与否：**未核实**。

### e. 有没有「插件不支持移动端」的明确先例？官方给的理由是什么？

| 项目 | 是否明确不支持 | 官方理由（原文/转述） | 证据级别 |
|---|---|---|---|
| **AnkiDroid** | ✅ 明确 | "Mobile operating systems do not let applications download and run code that was not packaged with the application. Neither iOS nor Android allow this... The only exception is HTML and Javascript" | [官方] wiki FAQ |
| **SiYuan** | ✅ 明确（无市场入口） | 维护者：开 Network serving，用电脑浏览器访问手机上的 SiYuan 装市场包 | [官方回复] issue #14509 |
| **Logseq** | ✅ 事实如此 | 需显式启用，等插件组件系统；PR 未提及（版主转述团队推文） | [社区] 论坛 + 推文链接 |
| **Notesnook** | ✅（尚未有） | Extensions API 仍在 Planned | [官方] roadmap |
| **AppFlowy** | ✅（尚未有） | 插件市场 FR 自 2022 open 未实现 | [官方] issue #718 |
| **Joplin** | ❌ **反例，支持移动端插件** | iOS 因 App Store 指南仅允许推荐插件 | [官方] Plugins 文档 |

## 10. 对 ZeroNote 的建议

> 现状证据（本地）：`README.md:50` 写「Android 的默认库 = 应用数据目录（`<appDataDir>/vault`）…… 也拿不到任意文件夹（SAF 限制）」；`HANDOFF.md:29,37` 实测库路径 `/data/user/0/com.aqua.zeronote.debug/files/vault`；插件目录在库内：`src-tauri/src/lib.rs:19`（`const PRIVATE_DIR: &str = ".zn"`）、`:236-247`（`<库>/.zn/plugins/<pluginId>/`）、`:265-266`（`list_plugins`）。

### 建议 1：库默认改放**公共存储**（`/storage/emulated/0/Documents/ZeroNote`），私有目录降级为可选（并保留"隐私模式"）
- 理由：Obsidian 官方把共享存储列为**推荐**、私有存储明确警告"卸载即删"；AnkiDroid 默认就在用户存储区；SiYuan 用私有目录的结果是被社区 fork 修正（[官方] obsidian.md/help/android、AnkiDroid FAQ、[社区] vufly/siyuan-fork README）。
- 补充：放共享存储后，用户能用手机自带文件管理器直接看到 `.md`，也能被 Syncthing/本地同步工具接管——这正是「一切可见」的前提。

### 建议 2：插件目录**继续留在库内 `.zn/plugins/`**（不要另起私有目录），并补上「应用内导入」入口
- 理由：Obsidian Android 的实践是「应用内 Browse 安装 + 手动拷进 `<vault>/.obsidian/plugins/` 两条路并存」（[官方] Community plugins、[社区] PKMer 教程）；一旦库在共享存储，`.zn/plugins/` 天然对用户可见可拷——ZeroNote 的目录设计本来就对，错的是库的位置。
- 具体做法：加一个「从文件导入插件（.zip）」按钮，走系统文件选择器选 zip → 解压到 `.zn/plugins/<id>/` → 刷新插件列表（对标 Joplin Android 的 "Install from file"，[官方] Joplin Plugins 文档）。

### 建议 3：Tauri 层引入 **SAF 目录选择 + 持久化 URI**（第三方 `tauri-plugin-android-fs`），把「All files access」留作可选高级模式
- 理由：Tauri 官方至今没有内建 storage-access 插件（issue #11733 自 2024-11 open，评论原文 "There is still no plugin to request storage access"）；`tauri-plugin-android-fs` 已提供 `Picker`（目录选择 + 权限管理）与 `PublicStorage`/`PrivateStorage`，并且以 URI 为中心 —— 这正是 SAF 的正确用法（[社区] tauri issue #11733 + [第三方] 插件 README）。
- 若不想依赖第三方插件：按 Obsidian 的做法申请 `MANAGE_EXTERNAL_STORAGE`（"All files"），对「文档管理类应用」Google 是认可的，但商店审核更严、且必须向用户解释用途（[官方] obsidian.md/help/android）。
- 关键提醒：**先选库，再决定插件路径**；两者必须同源（库在哪，`.zn/plugins` 就在哪），否则会出现「库放共享、插件仍在私有」的分裂状态。

### 建议 4：插件宿主坚持 **JS/声明式 UI**，并让每个插件显式声明支持的平台
- 理由：AnkiDroid 官方给出的平台约束是"唯一例外是 HTML/JavaScript"（[官方] FAQ）；Joplin 正是靠 manifest 里的 `platforms: ["mobile","desktop"]` 做兼容性判定，不匹配时给用户明确报错 "incompatible with Joplin mobile"（[官方] mobile plugin debugging）。
- 落地：在 ZeroNote 的 `manifest.json` 里加 `platforms`（或 `mobile: true/false`），插件列表里用徽章显示，装到不支持的插件时不要静默失败。

### 建议 5：iOS 端按 Joplin 模式预留「白名单/推荐插件」机制，不要假设插件商店能自由分发
- 理由：Joplin 官方写明 iOS 因 App Store 指南**只能安装 recommended plugins**（[官方] Joplin Plugins 文档）；Android 无此限制。ZeroNote 若是同一套插件体系，需要在数据模型里区分"可自由安装"与"iOS 白名单"两类，避免上架后才发现插件装不上。
- Obsidian iOS 是否有同类限制：**未核实**，做 iOS 前建议单独核实。
