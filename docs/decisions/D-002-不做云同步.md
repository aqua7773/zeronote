# D-002 不做云同步 / 账号

> 状态：**superseded**（2026-10-25 被 [D-009](D-009-做同步但自带后端.md) 取代：仍不做账号 / 服务端，但已做「用户自带后端」的同步插件）｜日期：2026-10-17 ｜原重议条件：多设备冲突成为真实痛点，且明确接受「冲突文件」语义

## 背景

需求文档要求「安卓 + Windows 双端，需要同步」；2026-10-17 用户裁定需求 2 暂不采用，同步 / AI 标签 / 密级均未开工。

## 决定

> ⚠️ **2026-10-25 更正：本条已被 [D-009](D-009-做同步但自带后端.md) 取代。** 仍然成立的只有「不做账号 / 不做服务端」；
> 「不做同步」这一半已推翻 —— 现在有四个「用户自带后端」的同步插件（本地文件夹 / WebDAV / S3 / Git，rev173.106–136）。
> 下面原文保留作设计史。

不做账号、服务器、云同步。数据就是用户文件夹里的 `.md`，同步交给用户自己的网盘/文件夹同步。

## 理由

- 产品定位是「没有数据库、没有服务器、没有账号」；引入同步就要引入账号、鉴权、冲突合并、隐私边界，全部是新的故障面。
- 双端并发改同一篇的语义没定：现有三方合并只覆盖「磁盘变了 vs 内存脏了」，不覆盖「两台设备同时存」。
- 自用阶段，网盘同步 + 冲突副本已经够用。

## 代价与边界

跨设备要手动/依赖第三方同步；没有版本历史（只有内核快照与回收站）。
