## 2 重点问题（只给方案，不开工）

### 2.1 P1：插件在每个窗口都加载（A）

**证据**（代码事实）：`App` 无条件调 `usePluginHost`，其中会跑 `ensureBuiltinPlugins`（写盘检查）+ 扫描 + 加载全部插件
（`src/hooks/usePluginHost.ts:196` 附近）。VS Code 是多窗口共享一个 extension host（[#133445](https://api.github.com/repos/microsoft/vscode/commits/18cde6954293e68337f15ae14eccb798f52677ee)）。

**风险**：插件的全局副作用随窗口数成倍（记账的通知监听、store 写入、命令重复注册）；每个独立窗口启动都要扫一遍插件目录。

**方案 A（推荐，低成本）**：笔记窗口**不加载插件** —— 给 `usePluginHost` 加 `noteWindowPath` 条件跳过。
编辑器 / Markdown 渲染 / 搜索都在内核，不依赖插件；插件窗口（`?pluginWindow=`）保持加载。
**成本**：~20 行 + 回归（窗口里 Markdown 渲染、粘贴图片、`[[链接]]` 不受影响）。**验收**：拆出窗口后插件列表为空、窗口里编辑/保存正常、主窗口插件不受影响。

**方案 B（彻底，高成本）**：插件宿主搬到 Rust / 独立进程，窗口只做视图（VS Code 模式）。
**成本**：架构级（命令表、面板、事件总线都要跨进程），**不建议现在做**。

### 2.2 P1：窗口位置 / 尺寸不持久化（A）

**现状**：主窗口每次按 conf 默认尺寸打开，用户调过的大小和位置不保留；独立窗口固定 900×700。
**现成方案**：官方 [`tauri-plugin-window-state`](https://v2.tauri.app/plugin/window-state/) —— 保存 position/size（含最大化），启动恢复，全平台。
**方案**：接入插件（Cargo + JS + capabilities），`tauri add window-state` 即可；注意 `note-*` 窗口也要纳入（可配 `skip` 或只恢复主窗口）。
**成本**：~30 分钟（含权限）。
**验收**：调窗口大小/位置 → 重启 → 恢复；独立窗口不恢复（或恢复同一位置，二选一，定了再写）。

### 2.3 P2：多窗口占用账本在主窗口内存（A）

**现状**：`noteWindowsRef` 在主窗口 JS 内存；主窗口 reload（dev HMR）就丢，已开的独立窗口「失联」，同一篇能被再开一份。
**方案**：账本落到 **localStorage**（同 origin 共享）或 Rust `app.manage` 状态；主窗口启动时清空残留（窗口在重启后都不存在）。
**成本**：~1 小时（含「启动清残留」+ 互斥守卫改读持久化账本）。
**验收**：主窗口 reload 后，仍开着的独立窗口能被识别（再点那篇 ⇒ 提示），关闭后能销账。

### 2.4 P2：会话恢复（hot exit）缺失（C）

**现状**：自动保存 800 ms、关窗落盘；**进程崩溃 / HMR 全量重载**丢最近一次未落盘输入。
**主流**：VS Code 把未保存缓冲区写 backup 目录，重启后还原。
**方案**：localStorage 存「dirty 快照」（path + content + 时间，上限 1 篇或 8 KB），启动时若有残留 ⇒ 提示「上次未保存的改动，恢复 / 丢弃」。
**成本**：~2 小时（含提示 UI 与测试）。**验收**：输入后 200 ms 内强杀进程 → 重启出现恢复提示；丢弃后不残留。

### 2.5 P3：其它（记录，不排期）

- 大库性能：文件树 / 卡片流是否要虚拟滚动（@tanstack/react-virtual）——先量，不提前引入。
- 窗口居中 / 多显示器：官方 `positioner` 插件可居中；只在用户抱怨时做。
- 插件状态改用官方 `store` 插件：会失去「随插件目录走」的语义，不换。

## 3 明确不建议采纳（写清理由，避免反复讨论）

| 候选 | 为什么不用 |
|---|---|
| 文件监听换 Tauri fs 插件 | 我们已经用 notify（Rust 标准），且需要「轮询兜底 + 事件名统一」 |
| 原子写换 `atomic-write-file` | 自研只剩 30 行，已处理 Windows rename 语义与 `.zn-bak` 回退 |
| 搜索换 Tantivy / FTS5 | 库规模百篇级；引入索引库 = 新依赖 + 新故障面 |
| 自动合并换 CRDT | 单机笔记无并发端；三方合并已够，CRDT 会改数据模型 |
| 剪贴板换官方插件 | 不支持富文本/图片粘贴，我们要自己处理 paste 事件 |
| 文件关联换 CLI 插件 | 只解析一个 `.md` 参数，替换收益为负 |
| 插件宿主搬进程 | 架构级成本，当前收益不匹配（见 §2.1 方案 B） |

## 4 执行顺序（等批准）

1. **P1-a** 笔记窗口跳过插件加载（~20 行，收益最大：副作用与启动成本）
2. **P1-b** 接 `window-state` 插件（~30 分钟）
3. **P2-a** 账本持久化（~1 小时）
4. **P2-b** 会话恢复（~2 小时，看是否需要）

每项单独 rev、单独提交、verify 五步全过 + 实测证据（沿用现有纪律）。
