## 0 三层结构

```
┌──────────────── 插件层（功能全在这）────────────────┐
│  灵感流 · Git 同步 · AI · 画布 · 标签 · 回收站 …      │
└──────────────────────┬──────────────────────────────┘
                       │  ← 只有这 10 个原语（本契约）
┌──────────────────────┴──────────────────────────────┐
│  内核 headless 核心：库 / 文件 / 文档 / 索引 / 事件   │
└──────────────────────┬──────────────────────────────┘
┌──────────────────────┴──────────────────────────────┐
│  默认壳：文件树 + 编辑器(CM6) + 设置页 + 命令面板     │
└─────────────────────────────────────────────────────┘
```

**术语**：**库**＝一个本地文件夹（里面全是 `.md`）｜**笔记**＝库里一个 `.md` 文件｜**插件**＝一个含 `manifest.json` + 入口脚本的目录｜**原语**＝内核暴露给插件的 API。

**ID 规则**：笔记 ID ＝ **库内相对路径**（`notes/2026-10-11/灵感.md`）。v0.2 引入独立 ID（满足「移动后引用不变」）。

**插件来源（2026-10-17 rev94 / rev110 起三种；2026-10-18 rev173.5 起**只剩全局一处**）**：

| 来源 | 路径 | 说明 |
|---|---|---|
| `global` | `<应用数据目录>/.zn/plugins/<id>/` | **唯一位置**：所有笔记库共用；切库不掉 |
| ~~`vault`~~ | ~~`<库>/.zn/plugins/<id>/`~~ | ⚠️ **rev173.5 取消**：用户「取消库内插件这种形式，所有插件都是全局的」。旧副本由 `__znMigratePlugins()` 搬进全局根，库内目录不再扫描 |
| `builtin` | 随应用包分发，启动时写入**全局根** | 安卓等用户不方便拷目录的场景（`src/kernel/builtin-plugins.ts`） |

`builtin` 只是**分发方式**，不是第四种插件形态 —— 写进盘之后与普通插件完全一样（可覆盖、可卸载）。

### 1.1 `fs` —— 文件读写（**所有写入必须原子**）

```ts
interface FsApi {
  vaultPath(): string;
  listNotes(dir?: string): Promise<NoteMeta[]>;      // 递归列 `.md` **与只读文档**（pdf/epub/…），
                                                     // 跳过 .zn/ 私有目录 —— 靠 `kind` 区分两类，见下
  listDirs(): Promise<string[]>;                     // 递归列**目录**（含空目录，跳过 .zn/.git/
                                                     // node_modules/.obsidian）—— 文件树显示**空文件夹**
                                                     // 的唯一依据：listNotes 反推不出空目录
  readText(path: string): Promise<string>;           // 库内相对路径
  writeText(path: string, content: string): Promise<void>; // 临时文件 + rename，失败不破坏原文件
  createNote(path: string, content?: string): Promise<void>;
  rename(from: string, to: string): Promise<void>;   // 只能改名（文件）
  mkdir(path: string): Promise<void>;                // 多级目录一次建（幂等）
  move(from: string, to: string): Promise<void>;      // **能搬整个目录树**；`to` 是已存在目录 ⇒ 移入其中
  copy(from: string, to: string): Promise<void>;      // 同语义的**递归复制**；跳过 .zn 等私有/忽略目录
  delete(path: string): Promise<string>;             // 移入 .zn/trash/，返回回收站内相对路径（供撤销）
  exists(path: string): Promise<boolean>;
  listTrash(): Promise<TrashEntry[]>;                 // 回收站列表（**新旧两种格式都认**，最近删的在最前）
  restoreTrash(id: string): Promise<string>;          // 恢复，返回落点；原位置有同名项 ⇒ 拒绝，不覆盖
  purgeTrash(id: string): Promise<void>;              // **真删除**一项（不可撤销 —— UI 必须二次确认）
  emptyTrash(): Promise<number>;                      // 清空回收站，返回清掉的条目数
  watch(cb: (e: FsChange) => void): Disposable;      // 含外部编辑器改动（桌面 notify watcher / 移动端 3 秒轮询）
}
type NoteMeta = { path: string; id: string; title: string; mtime: number; size: number;
                  frontmatter: Record<string, unknown>;
                  /**
                   * `note` = Markdown 笔记（内核可编辑，走编辑器）；
                   * `doc`  = **只读文档**（pdf / epub / mobi / azw3 / fb2 / cbz / txt）。
                   *
                   * 2026-10-13 加（文档阅读器插件）：此前 `list_notes` 在 Rust 侧硬过滤只收 `.md`
                   * ⇒ **库里放了 PDF 也根本看不见**，插件连"能发现它"的机会都没有。
                   * 现在两类都进文件树；但**只有 `note` 进索引、只有 `note` 走 `openNote`**，
                   * `doc` 交给 `core.openDocument` 派发（见 §2.1.1）。
                   * 文档的 `title` = **去掉扩展名的文件名**（类型由前端挂的徽章显示），
                   * `frontmatter` 恒为 `null`（二进制不解析）。
                   */
                  kind: 'note' | 'doc' };
type TrashEntry = { id: string; name: string; deletedAt: number; isDir: boolean; size: number;
                    originalPath: string | null };   // 旧格式没记原路径 ⇒ null（恢复只能落库根）
type FsChange  = { kind: 'create'|'modify'|'delete'|'rename'; path: string };
```

> `watch` 的返回值**由宿主自动登记**（§2.7 接管协议）—— 不接返回值也不会在卸载后继续收通知。
> 实现（rev173.59）：桌面由 Rust `notify` watcher 推 `zn://fs-change`（**只报库内 `.md` / `.markdown`**；`rename` 拆成 delete(旧) + create(新)；120ms 合并；1.5 秒内自己写过的路径不回响）；移动端 `/storage/emulated/0` 是 FUSE 挂载、inotify 漏报，退回 3 秒轮询。
> ⚠️ **纪律**：轮询只能在「事件通道真的起来」之后停（`watch_vault` 返回成功）。2026-10-20 rev173.59 之前是 `listen` 一成功就 `stopPoll()`，而 Rust 从没发过该事件 ⇒ 外部改动完全不刷新。

**硬保证**：① 写入原子（temp + rename）② 失败绝不返回"已保存" ③ 磁盘上的 `.md` 是唯一真源，外部改动会被 `watch` 捕获。

### 1.2 `doc` —— 当前文档 / 选区

```ts
interface DocApi {
  active(): NoteDoc | null;
  open(path: string): Promise<void>;
  close(path?: string): void;
  save(path?: string): Promise<void>;
  selection(): { from: number; to: number; text: string } | null;
  replaceSelection(text: string): void;              // 只作用于**用户当前选区**
  insertAtCursor(text: string): void;
  /**
   * 按**偏移**插入。`cursorOffset` = 插入后光标距插入内容开头几个字符（缺省 = 末尾）。
   * 两个非它不可的场景（2026-10-12 加，为 Markdown 快捷输入栏）：
   *   ① 行首标记（`# ` 标题 / `- ` 列表 / `> ` 引用）必须落在**行首** ——
   *      光标停在行中时 `insertAtCursor` 会把标记插进句子中间；
   *   ② 成对标记（`**粗体**`）希望光标落在**两个标记中间**，接着打字就是标记内容。
   * 偏移越界不抛错（夹进 `[0, len]`），编辑动作尽力而为。
   */
  insertAt(pos: number, text: string, cursorOffset?: number): void;
  /**
   * 按**区间**替换正文（`text === ''` 即删除该区间）。
   * `from` / `to` 顺序颠倒自动交换；两端夹进 `[0, len]`（与 `insertAt` 同一套宽容策略）。
   *
   * 为什么需要它：`insertAt` **只能插**、`replaceSelection` 只认用户选区 ——
   * 结构化编辑（导图 ⇄ 大纲双向回写、表格单元格改写、任务勾选回写）要的是
   * "**改掉任意一段已知区间**"，插件从 `active().content` 解析出位置后直接换掉，
   * 不必依赖用户光标在哪。
   *
   * 2026-10-13 加（缺口 U3a，见 `docs/archive/插件UI承载能力-2026-10-13.md`）。
   */
  replaceRange(from: number, to: number, text: string, cursorOffset?: number): void;
  /**
   * 订阅文档生命周期事件。**2026-10-13 起是真事件**（缺口 U3b）——
   * 在此之前它是 `on: () => ({ dispose(){} })` 的**空桩**：不报错、不警告，
   * 插件订阅了永远收不到（"静默失效比报错危险"的典型）。
   *
   *   · `open` / `save` / `close` —— 每次动作各触发一次，payload 带该文档快照；
   *   · `change` —— **trailing 去抖 200ms**（每次击键都回调会打爆插件；
   *     低于自动保存的 800ms ⇒ 顺序稳定：插件**先**看到 change、**后**看到 save）；
   *     去抖窗口内切笔记/关笔记时**先兑现挂起的 change 再播 open/close**，不会乱序；
   *   · 单个订阅者抛错被逐个隔离（不影响其它订阅者，也不打断编辑）。
   *
   * 约定（**2026-10-13 rev49 起**）：返回值由**宿主自动登记**，卸载时统一 dispose
   * —— 插件不需要自己 `push`（§2.7 接管协议规矩①）。
   *
   * ⚠️ **已知边界**：`replaceRange` / `insertAt` 都作用于**挂载中的编辑器实例**。
   * 主区被插件面板（`location: 'main'|'sidebar'`，二者都渲染在主区）占满时编辑器已卸载，
   * 此时调用是**静默 no-op** —— 要改内容请用 `command.execute` 从编辑器可见的上下文触发。
   */
  on(ev: DocEvent, cb: (d: NoteDoc) => void): Disposable;
}
type DocEvent = 'open'|'change'|'save'|'close';
type NoteDoc = { path: string; content: string; frontmatter: Record<string, unknown>; dirty: boolean };
```

> **U3a/U3b 的验收方式（2026-10-13，可复跑）**：`examples/doc-edit-probe/`（临时夹具插件，
> junction 到测试库即可）注册三条命令 + 一个侧栏面板，把事件记到 `window.__docProbeLog`；
> 用 `tools/cdp.mjs` 走 CDP 驱动命令面板，**以磁盘笔记为真源**断言：

> ② 中间区间替换后与旧文的**共同前缀 37 / 共同后缀 22** ⇒ 只有 3 个字符被改，其余一字未动；

> 关笔记 `close` 带正确 path 与内容长度。

### 1.3 `index` —— 可删可重建的索引（内存子串索引）

> **实现说明**：原计划用 SQLite FTS5，实测后改成**纯内存子串索引**（零第三方依赖）：
> 中文没有词边界，FTS5 的 tokenizer 对"中文子串"查询本来就要靠 LIKE/trigram 兜底；
> 而 `String.prototype.indexOf` 是原生实现，3 MB 语料全扫是毫秒级。
> 取舍详见 `src/kernel/index-api.ts` 文件头。

```ts
interface IndexApi {
  /**
   * 多关键词 AND + 字段过滤（v0.2 补全，rev173.47 起 UI 有出口）：
   *  · `opts.tag` —— 只返回带该标签的笔记（大小写不敏感）；
   *  · `opts.dir` —— 只返回该目录（含子目录）下的笔记；
   *  · `opts.regex` —— `q` 整个当**正则表达式**（不切词；忽略大小写；`^`/`$` 按行匹配）。
   *    语法错误 ⇒ 返回空表，不抛错（调用方自己提示）。
   *  `q` 为空时，带 `tag`/`dir` 也算合法查询（"列出这个标签下的全部笔记"）。
   */
  query(q: string, opts?: { limit?: number; dir?: string; tag?: string; regex?: boolean }): Promise<SearchHit[]>;
  upsert(path: string, text: string): Promise<void>;
  remove(path: string): Promise<void>;
  rebuild(): Promise<{ count: number; ms: number }>;   // 删库重建后关系可恢复
  /** 标签统计（按**笔记数**降序；同一篇里出现多次只算一次）—— 规格 §2.3 的「标签聚合查看」用它 */
  tags(): Promise<{ tag: string; count: number }[]>;
  /** 取一个**独立分区**（互不可见）—— 规格 §2.6 的「按密级分索引」靠它 */
  scoped(partition: string): IndexApi;
}
type SearchHit = { path: string; title: string; excerpt: string; score: number };
```

**标签从哪来**（宿主自己抽，插件不用管）：frontmatter 的 `tags: [a, b]`、
多行 `tags:` + `- a`、中文键 `标签: a, b`，以及正文里的 `#标签`（与 §2.6 的编辑
器标记同一约定）。注意 **Rust 侧的 `parse_frontmatter` 只认单行 `key: value`**，
多行标签数组会被它跳过 —— 所以前端从**全文**另抽一遍（这也是为什么标签能力放在前端）。

要求：多关键词 **AND**、中文子串兜底、特殊字符不崩（对齐 F7）。
字段过滤（`tag` / `dir`）与正则（`regex`）都**可与关键词组合**；正则模式的摘要在原文上切窗口，
高亮哨兵（`\u0002` / `\u0003`）与关键词模式一致 —— UI 用同一个 `splitExcerpt` 渲染。

**分区（`scoped`）**：分区之间**互不可见** —— 各自的文档表、各自的 pending、各自的 rebuild。
这是「机密/绝密只用本地索引、公开才可云索引」的地基：不隔离的话，
一条机密笔记的正文会被公开搜索直接命中。名字是**绝对的**（不做层级嵌套）；
同名分区共享同一份索引，前置插件与消费者可以约好往同一个分区写。

⚠️ 分区**只隔离可见性、不改变数据源**：`rebuild()` 照样扫全库，只是写进自己那份。
**要按密级/标签筛，由插件决定 upsert 什么** —— "哪些笔记算机密"是业务策略，
不该由内核替它判断。

示例：`examples/index-scope/`（同一个关键词：默认分区 **0 条**、机密分区 **1 条**）。

### 1.4 `event` —— 事件总线

```ts
interface EventApi {
  on(topic: string, cb: (payload: unknown) => void): Disposable;
  emit(topic: string, payload: unknown): void;       // 插件间通信用
}
```

> `on` 的返回值**由宿主自动登记**（§2.7 接管协议）—— 不接返回值也不会在卸载后残留。

**内核固定事件**（不改名）：

| topic | payload | 何时派发（rev173.40 起真的派发） |
|---|---|---|
| `app:ready` | `{ vault }` | 应用级，**只发一次**：首代插件加载完成之后（更早注册的监听才收得到） |
| `vault:open` | `{ vault }` | 每代插件加载完成（启动 / 重扫 / 切库） |
| `note:created` | `{ path }` | `fs.createNote` 成功 |
| `note:saved` | `{ path }` | `fs.writeText` 成功（应用写盘；只处理 `.md`） |
| `note:renamed` | `{ from, to }` | `fs.rename` / `fs.move` 成功 |
| `note:deleted` | `{ path, trashId }` | `fs.delete` 成功（`trashId` 供撤销恢复）；`fs.emptyTrash` 发 `{ path: '', trashId: '*', count }` |
| `note:changed` | `{ path, kind: 'create'\|'modify'\|'delete'\|'rename' }` | `fs.watch` 看到磁盘变化。**语义 = 磁盘内容变了**：外部程序改文件会发；本机保存的 watch 回响**也可能**紧接着 `note:saved` 再发一次 ⇒ 订阅方按幂等处理 |
| `index:rebuilt` | `{ count, ms, partition }` | 某个分区 `rebuild()` 成功（pending 回放之后；失败不派发） |
| `app:quit` | — | ❌ **未派发**（应用退出在 Rust 侧，前端没有可靠收尾点） |

> 恢复回收站条目：`fs.restoreTrash` 成功发 `note:created`，payload 多一个 `restored: true`。
> 服务注册表事件：`service:available` / `service:gone`（`{ name, pluginId }`）。
> 派发点集中在 `src/kernel/fs-events.ts`（写路径）与 `src/kernel/kernel.ts`（索引/服务）；
> 订阅方抛错只记日志，不影响其它订阅者（`event.ts` 逐个 try/catch）。

## 2 扩展面六原语（`command` / `view` / `store` / `host` / `service` / `editor`）

### 2.1 `command` —— 命令 / 快捷键 / 命令面板

```ts
interface CommandApi {
  register(cmd: {
    id: string;                    // 必须带插件前缀：inspiration-flow.capture
    title: string;                 // 中文可
    keybinding?: string;           // "Mod+Shift+K"
    when?: string;                 // "editorFocus && !mobile"
    run: (...args: unknown[]) => unknown;
  }): Disposable;
  /** 只绑定实现（元数据由 manifest.contributes.commands 静态声明）—— 懒激活插件用它 */
  bind(id: string, run: (...args: unknown[]) => unknown): Disposable;
  execute(id: string, ...args: unknown[]): Promise<unknown>;
  list(): { id: string; title: string }[];
}
```

### 2.1.1 插件可以**接管内核行为**

内核自己的命令（`core.newNote` / `core.save` / `core.pickVault` …）用 `register` 登记；
插件用 **`bind('core.newNote', run)`** 就能**覆盖它的实现** —— `bind` 对已存在的 id
只换 `run`、不动元数据（title / keybinding 保持内核的）。

> 这是「插件能改内核行为」的**唯一**入口。所以宿主界面上所有入口
> （菜单项 / 首页按钮 / Ctrl+N / 快速切换里输名字）**一律走命令、不直接调函数** ——
> 直接调函数的话插件永远接不上。规格 §2.2 的「'笔记'目录下只能在当天时间目录新建」
> 就靠这个接管点实现（示例插件 `daily-note` 已于 2026-10-19 按「测试插件不留在功能」移除，
> 接管点本身不变）。

⚠️ **隐含顺序要求**：内核先 `register`、插件后 `bind`。宿主的两个 effect 恰好是
这个顺序（内核命令注册在前、插件加载在后），所以插件的 `bind` 是"覆盖实现"，
不会撞 `命令 id 重复`。

**懒激活**（见 §3.1）：写了 `activationEvents` 的插件由宿主**静态登记元数据**
（`declare`），命令被点时才激活插件、再由它 `bind` 补实现。

#### 接管的**还原**语义（2026-10-13 rev49 修）

`bind` 覆盖一条已存在的命令时，宿主**先记下被覆盖的实现**，`dispose` 时**放回去**：

```
内核 register(core.newNote, 内核实现)
  → 插件 bind(core.newNote, 插件实现)     期间：命令表不变，实现归属 = plugin:<id>
  → 插件卸载 ⇒ dispose                     之后：实现归属 = core（**内核实现被放回**）
```

**此前这里是 `delete run`** —— 卸载后 `core.newNote` 还在命令表里，但**没有实现**：
执行抛「尚未绑定实现，且没有可用的激活器」⇒ 菜单项 / 首页按钮 / `Ctrl+N` /
快速切换四个入口**一起废掉**（原先用 `examples/daily-note` 复现；该示例已于 2026-10-19 移除）。命令表本身看起来
毫无变化，"四个入口突然都不工作"要等用户去点才发现 —— 典型的静默失效。

嵌套接管也成立：A 先 bind、B 后 bind，则 B dispose 还原 A、A dispose 再还原内核。

**可判定的判据**（`node tools/verify-takeover.mjs`，自动跑）：
卸载插件后 `window.__znKernelAudit().commands` 里 `core.newNote.impl` 必须是 `'core'`，
**不能是 `null`**（`null` = 有元数据、没实现）。该值取自实现的归属标记（`plugin:<id>` / `core`）。

#### `core.openDocument`：只读文档的派发点（2026-10-13 加）

内核**只认识"这是一份只读文档"**（`NoteMeta.kind === 'doc'`），**不认识 pdf / epub** ——
怎么渲染完全是插件的事。所以内核只登记一条命令 + 一个**默认实现**：

```

  → 插件 bind('core.openDocument', run)  // 接管：渲染阅读器
  → 插件卸载                              // 自动还原成默认实现（与上面同一套 bind 语义）
```

文件树里点 `kind === 'doc'` 的条目就走这条命令（`App.tsx` 的 `onOpen`），
所以**没有插件时也不会静默**：用户会看到那句 toast，而不是"点了没反应"。

**已落地实现**：`examples/doc-reader/`（pdf.js 自绘 + foliate-js 多格式），

`window.__znKernelAudit().commands` 里 `core.openDocument.impl` 应为 `plugin:doc-reader`，
卸载后回到 `core`。

### 2.1.2 内核自带的 Markdown 标记（`core.mark.*`，2026-10-12 收进内核）

内核自带 **12 条格式动作**命令，覆盖 Markdown 最常用的标记：

| 类 | 命令 | 键位 | 行为 |
|---|---|---|---|
| **成对** | `core.mark.bold` / `.italic` / `.code` / `.strike` | `Mod+B` / `Mod+I` / `Mod+E` / `Mod+Shift+X` | 有选中 → 包住选中文字；无选中 → 插一对空标记、**光标落中间** |

⇒ 同一套语法内核管一半、插件管一半。收进来之后 `**` / `# ` 这些字面量**只在一处出现**

**两处入口，桌面与移动端各一个**（用户 2026-10-12 定）：
- **移动端** —— 手机键盘正上方那条快捷栏（`editor-toolbar`）
- **桌面端** —— 编辑器右键菜单的「标记」子菜单（桌面**只有**这一处入口；
  顶部提示条与底部工具栏都**不做**）

**插件仍然可以参与**：
- **接管**某一条的实现 —— `command.bind('core.mark.bold', run)`（同 §2.1.1 的规矩）
- 或者只**调用**它 —— `command.execute('core.mark.bold')`

**六种挂载位置的真实承载**（2026-10-13 实测补齐 —— 此前文档与实现不一致，插件作者会踩）：

| `location` | 实际渲染在哪 | 能否与编辑器**同屏** |
|---|---|---|
| `sidebar` | **主区** —— 右侧栏已取消 ⇒ 与 `main` 同路（`App.tsx` 的 `pagePanel` 分流） | ❌ 会顶掉编辑器 |
| `main` | 主区（占满时编辑器卸载） | ❌ |
| `statusbar` | 内核状态栏（一行） | ✅（但只有一行） |
| `modal` | Dialog 弹窗 | ✅ |
| `editor-toolbar` / `editor-topbar` | **编辑器底部工具条 / 顶部提示条** | ✅ **只有这两个是"贴着编辑器"的** |

⚠️ 结论：插件要**与编辑器同屏**只有 `editor-topbar` / `editor-toolbar` 两条路；
要**改笔记内容**（`doc.replaceRange` / `insertAt` 作用于挂载中的编辑器实例）也只能走它们 ——
主区面板占满时编辑器已卸载，那些调用会**静默 no-op**。

**`openWindow` 的语义与实测结论**（rev50 一次做完才写下来的，别再踩）：

| 项 | 结论 |
|---|---|
| 窗口内容 | 新窗口是**新的 webview**（自己的 JS 上下文）：它加载同一 URL + `?pluginWindow=<panelId>`，**重新跑一遍插件加载**，然后**只渲染那一个面板**（无侧栏 / 无编辑器） |
| label 约定 | 内核生成，**一律 `plugin-<sanitized panelId>-<n>`**（`.` 等非法字符换 `-`）。`capabilities/default.json` 的 `windows` 用 glob **`plugin-*`** 覆盖它们 |
| 权限（**rev50 新增**） | `core:webview:allow-create-webview-window`（能开窗口）+ `core:window:allow-destroy`（能立即销毁）。**用户裁决「完全放行」**：插件窗口与主窗口权限一致，不做按窗口分级 |
| 关闭：三键走 `destroy` | **机制**（读 `@tauri-apps/api/window.js` + E1/E2 对照实验确认）：`Window.close()` **只发 `tauri://close-requested` 事件，自己不销毁窗口**；真正销毁由**监听器里的 `destroy()`** 完成 —— API 的 `onCloseRequested()` 包装里写着 `if (!evt.isPreventDefault()) await this.destroy()`。所以：**窗口里一个 close 监听器都没有时，`close()` 返回 ok 但窗口不关**（不是死锁，是没人调 destroy）。内核三键直接 `destroy()`（用户点的"关"不必再走一遍请求） |
| 窗口模式的 close 监听器 | 插件窗口没有"未保存内容"要兜底，但**必须有一个 close 监听器**，否则插件作者写 `getCurrentWindow().close()` 会静默失效。内核因此给窗口模式注册了一个极简监听器（什么都不做 ⇒ 不 preventDefault ⇒ API 层 destroy） |
| `host.saveFile` 等 | 窗口模式下同样可用（权限一致）；但窗口里没有编辑器上下文，`fs`/`doc` 只对"库"有效 |
| 平台 | 桌面可用；**Android 多窗口未实测**（`platforms` 里想跟移动端共用就得自己兜住失败） |

> ② `image.src` 指向**库内文件**时必须先过 `host.assetUrl(rel)`（相对路径直接塞 `<img>` 必然 404）；
>    `http(s):` / `data:` / `blob:` 原样传即可。
> ③ `list.items` **强烈建议给 `key`**（`{ key, node }`）：不带 key 时宿主只能用下标做 React key，
>    增删一项会让后面所有行错位（受控输入尤其明显）。旧写法（裸 UINode）仍兼容。
>
> ⚠️ **`html` 节点的风险**：宿主用 `dangerouslySetInnerHTML` 直投，插件（或它从 CDN 拉的库，
> 如 katex / mermaid）返回什么就渲染什么。v0.1 无沙箱、插件都是本机可信代码，故接受此取舍；
> **装第三方插件前请先读它的源码**。只想要代码块或纯文本时请用 `code` / `text`，别用它。
>
> 参考实现：`examples/ui-kit/` —— 把每一种节点都渲染一遍，既是示例也是渲染器的回归清单。
>
> ④ **WebView 逃生口的页面必须是"独立 origin"的资源**（`http(s):` 页面）。
>    两条真机踩出来的硬限制（2026-10-12）：
>    · `data:` / `srcdoc` / `blob:` 的 iframe **会继承宿主 CSP**，而 Tauri 编译时会往 `script-src`
>      注入打包资源的 `sha256`；按 CSP 规范「源列表里一旦有 hash，`'unsafe-inline'` 就被忽略」
>      ⇒ 那些页面里的内联脚本**一律被拦**（logcat 原话：`'unsafe-inline' is ignored if either a
>      hash or nonce value is present`）。
>    · Tauri 的 asset 协议（`host.assetUrl`）在 **Android 上不服务 `.html`**：
>      实测 `http://asset.localhost/…/page.html` → `net::ERR_INVALID_RESPONSE`（把 scope 放宽到
>      `/storage/**` 也一样）。
>    所以演示页由一台局域网静态服务器提供（`examples/webview-demo/`）。iframe 用
>    `sandbox="allow-scripts"`（**无** `allow-same-origin`）⇒ 页面拿不到宿主的 DOM / 存储 / IPC；
>    主题令牌由宿主 `postMessage` 送达并随主题变化重发（见 §2.2 的 `registerWebView`）。

```ts
  dispose?(): void | Promise<void>;
}
export interface PluginContext {
  fs: FsApi; doc: DocApi; index: IndexApi; event: EventApi;
  command: CommandApi; view: ViewApi; store: StoreApi; host: HostApi;
  service: ServiceApi;            // §2.5 插件互调 / 前置插件
  editor: EditorApi;              // §2.6 编辑器行内标记（[[引用]] / #标签 那类）
  pluginId: string;
  /**
   * 插件自己的资源账（§2.7）。**多数情况下不用手动 push**：
   * `command.register/bind` · `view.registerPanel/registerWebView` · `event.on` ·

   * 自改宿主 DOM ⇒ `host.onRollback`。剩下的（自己的 interval / window 监听…）才要手动 push。

```

### 2.5 `service` —— 插件互调 / **前置插件**

```ts
interface ServiceApi {
  /** 提供一项服务。「前置插件」就是靠它 —— 名字建议带命名空间：`katex` / `git.commit` */
  provide<T>(name: string, factory: () => T | Promise<T>, opts?: { version?: string }): Disposable;
  /** 取服务（异步）。**没有就返回 null** —— 软依赖，不抛错、不阻塞加载 */
  consume<T = unknown>(name: string): Promise<T | null>;
  /** 当前已登记的服务（诊断面板/调试用） */
  list(): { name: string; pluginId: string; version?: string; loaded: boolean }[];
}
```

**为什么需要它**：`event` 是 fire-and-forget —— 没有返回值，也没有"对方在不在"。
「AI 插件调用 Git 插件的提交能力」这类需求，用事件只能靠全局变量 hack。

**「前置插件」是什么**：把**依赖环境本身**做成插件。内核只维护一张
`名字 → 懒工厂` 的表，**完全不认识** katex / mermaid / pdf / git 这些具体依赖 ——
于是"换一个公式渲染器"就是换一个插件，内核一行都不用改。

**三条刻意设计**：

| 设计 | 怎么做 | 为什么 |
|---|---|---|
| **懒工厂** | `provide` 只登记闭包；第一次 `consume` 才执行，结果缓存复用 | **按需激活**：没人用的前置插件，一次 import、一次网络请求都不会发生 |
| **软依赖** | `consume` 拿不到返回 `null`；不做拓扑排序、不拦加载 | 硬依赖会导致"一个前置装错版本，整个应用起不来"（VS Code `extensionDependencies` / SilverBullet `redirect` 同此取舍） |
| **工厂抛错不外抛** | 错误只写插件日志，`consume` 得到 `null` | 一个前置插件坏了，不该拖垮依赖它的插件 |

**加载顺序不保证**：晚到的消费者监听 `service:available`（负载 `{ name, pluginId }`）
补挂；提供者卸载时内核广播 `service:gone`，并**强制回收**它提供的服务
（不依赖插件自己 dispose —— 见 `Kernel.releaseServices`）。

**manifest 声明**：`dependencies: string[]`（只用于提示"缺前置"，不参与调度）。

**示例**：`examples/dep-katex/`（提供 katex，懒加载 CDN）·
`examples/dep-consumer/`（软依赖 + 降级显示 + 等事件补挂）。

### 2.6 `editor` —— 编辑器标记 / 行首按钮 / 逐行 class / 折叠

**四类能力**：
· `addMark(rule)` —— 给**区间**加样式/点击（`[[引用]]`、`#标签` 那类）；
· `addLineAction(rule)` —— 在**某一行的左外侧**放一个可点小按钮（**2026-10-13 rev54 新增**）；
· `addLineClass(rule)` —— 给**整行**加 class（**rev78 新增**，大纲竖线用）；
· `addFold(rule)` —— 行**折叠 / 展开**（**rev80 新增**，rev81 换成 CM6 官方 `codeFolding` 状态机）。

`addLineAction` 的内核实现走 CM6 的 **Widget decoration**（`Decoration.widget({ side: -1 })`，
同 [官方 Decoration Example](https://codemirror.net/examples/decoration/) 给布尔值加可点 checkbox 的做法）：

- 按钮是**视图元素**：不进文档、不占偏移 ⇒ Markdown 源保持原样；
- `ignoreEvent()` **必须**返回 `false`，否则编辑器把自己的事件处理吃掉，按钮点不动；
- 装饰集改用 `Decoration.set(ranges, true)`（交给 CM6 排序）—— 零宽 widget 与区间 mark 混排时，
  手写"严格升序"+ `RangeSetBuilder` 容易出错；
- 点击时命令收到 payload **`{ line, from }`**（`line` 从 0 起；`from` 是文档偏移）；
- ⚠️ **边界**（rev65 起第一条已被 `filter` 解决）：
  · 正则只能按**单行**决定"哪些行是候选"。凡是要看**整篇**的条件（典型：**这个标题下面到底
    有没有列表**），用 `filter`（见下）—— 宿主在渲染每个候选行时回调它，返回 false 的行不画按钮。
  · 按钮是**视图元素**，不进文档、不占偏移 ⇒ 不会污染 Markdown 源。

```ts
type EditorMarkRule = {
  id: string;
  pattern: string;              // 正则源（字符串）—— 宿主自动补 g
  flags?: string;
  className?: 'link' | 'tag' | 'code' | 'highlight' | 'muted';
  onClick?: string;             // 点击时执行的命令 id（payload: { text, from }）
  title?: string;
};

interface EditorApi {
  addMark(rule: EditorMarkRule): Disposable;
  /** 行首动作按钮（rev54）：payload = { line, from } */
  addLineAction(rule: EditorLineAction): Disposable;
  /** 逐行 class（rev78）：`classAt` 返回 null 表示该行不加 */
  addLineClass(rule: EditorLineClassRule): Disposable;
  /** 折叠规则（rev80/81）：`foldEndAt` 给折点、`initialFolded` 恢复、`onToggle` 写回 */
  addFold(rule: EditorFoldRule): Disposable;
  /** 切换某行折叠（`line` 从 0 起），返回「这一行能不能折」 */
  toggleFold(line: number): boolean;
  /** 查某行当前是否折叠（读 CM6 的状态，不是插件自己记的那份） */
  foldAt(line: number): boolean;
  /** 重新问一遍各规则的 `initialFolded` 并应用（异步读盘后用，rev81） */
  restoreFolds(): void;
  /** DOM 元素 → 行号（0 起）；换算不出给 null（插件自己事件委托时用） */
  lineAtElement(el: Element): number | null;
  list(): { id: string; pluginId: string }[];
}

type EditorLineClassRule = {
  id: string;
  /** 逐行问：返回 class 名或 null（同步、会被逐行调用 ⇒ 请按整篇缓存） */
  classAt: (ctx: { doc: string; line: number; text: string }) => string | null;
};

type EditorFoldRule = {
  id: string;
  /** 逐行问：能折时返回**结束行号（0 起，含）**，不能折返回 null */
  foldEndAt: (ctx: { doc: string; line: number; text: string }) => number | null;
  /** 挂载时这一行要不要折起来；`restoreFolds()` 会再问一遍 */
  initialFolded: (ctx: { doc: string; line: number; text: string }) => boolean;
  /** 折叠态变化时回调（插件在这里写盘） */
  onToggle?: (ctx: { text: string; folded: boolean }) => void;
};

type EditorLineAction = {
  id: string;
  pattern: string;              // 正则源；按行匹配请自己带 m（^ / $ 才按行生效）
  flags?: string;
  /**
   * 跨行条件的最后一道关（**rev65 新增**）：正则只看得见字节，而像"这个标题下面
   * 到底有没有列表"这类条件要看整篇 ⇒ 给一个谓词，返回 false 的行**不画按钮**
   * （不传＝行为与以前完全一样）。
   * `line` 与 onClick 的 payload **同口径（0 起）**。它是**同步**的且会被**逐行**调用，
   * 插件侧请自行缓存"按整篇解析一次"的结果（否则一篇 500 行的笔记要解析 500 次）。
   */
  filter?: (ctx: { doc: string; line: number; text: string }) => boolean;
  label: string;                // 按钮文字（短：1–3 字符或 emoji）
  title?: string;
  onClick: string;              // 点击时的命令 id（payload: { line, from }）
  className?: 'accent' | 'muted';
};
```

**它解决什么**：`[[文件名]]` 引用与跳转、`#标签` 着色、`==高亮==` 这类
**编辑器里的行内增强**。此前插件完全够不到编辑器内部（只有 `doc` 的读写与选区），
规格 §2.2 的"`[[文件名]]` 笔记引用与跳转"因此做不出来。

**为什么不让插件直接给 CM6 的 `Extension`**：
① 它是宿主依赖里的**类实例**，而插件代码是字符串（将来还要进 Worker / iframe 沙箱）—— 塞不进来；
② 一旦暴露，插件就能把编辑器改成任意样子 ⇒ 声明式主路又被绕过（§7 一直在防这件事）。
所以插件只交**可序列化规则**（正则字符串 + 语义档位 + 命令 id），
翻译成装饰器、把点击换算成文档偏移，这两件事留在宿主。

**边界（如实标注）**：

- 规则在**编辑器挂载 / 切换笔记**时被读取 ⇒ 插件要在 `apply()` 里登记；
  之后新增的规则得等下次打开笔记才可见
- **重叠匹配先到先得**：前一条规则吃掉的区间，后面的规则不再着色
- 只做**行内标记**，不改变编辑行为（不能拦截输入、不能换语言、不能加 gutter）
- 正则每次文档变化重扫全文 —— KB 级文本是微秒级（与 `index` 同一取舍，不做增量）

**示例**：`examples/editor-marks/`（`[[笔记名]]` 可点跳转 + `#标签` 着色）。

### 2.7 **接管协议**（原则 3 的地基 · 2026-10-13 rev49）

背景：原则 2 允许插件接管内核（覆盖行为、占掉主区、自绘界面），原则 3 又要求
**覆盖可以、不得破坏、关掉插件内核还能用**。这两条要在实现上对得上，就得把
"接管"变成**有账可查、可自动验收**的东西 —— 这就是接管协议：

| # | 规矩 | 落在哪 |
|---|---|---|
| ① | 内核给出的**每条注册/接管入口必须返回 `Disposable`**，且由**宿主自动登记**（不指望插件记得 `push`） | `plugin-host.ts` 的 `scopedCommand` / `scopedView` / `scopedEvent` / `scopedFs` / `scopedDoc` / `scopedHost` |
| ② | 接管**必须可还原**：`command.bind` 覆盖已有实现时先记下原实现，dispose 时放回（§2.1.1） | `command.ts` 的 `bind`/`dispose` |
| ③ | 插件自绘 / 自改宿主 DOM ⇒ 用 **`host.onRollback(fn)`** 登记。**登记过 ⇒ 内核负责还原；没登记 ⇒ 自己负责**（内核不拦、也不管 —— 原则 4） | `host.onRollback` + `ctx.subscriptions` |
| ④ | 还原要**可判定**：`window.__znKernelAudit()` 给一致读快照，`tools/verify-takeover.mjs` 自动比对 | `kernel.audit()` · `tools/verify-takeover.mjs` |

**宿主管到哪一步（受管清单）**

| 资源 | 谁负责回收 |
|---|---|
| `command.register` / `bind` | 宿主自动登记 |
| `view.registerPanel` / `registerWebView` / `openWindow`（§2.2）/ `overrideShell`（§2.8） | 宿主自动登记 |
| `event.on` · `fs.watch` · `doc.on` | 宿主自动登记（**2026-10-13 起**，此前要插件自己 push） |
| `service.provide` · `editor.addMark` | 宿主**强制**回收（`releaseServices` / `releaseEditorMarks`） |
| 插件注入的 `<style>`（`manifest.styles`） | 宿主自动登记 |
| **自改宿主 DOM / 全局变量 / document 级监听** | `host.onRollback` 登记的 ⇒ 宿主代调；**没登记 ⇒ 插件自己** |
| 自己的 `setInterval` / `window.addEventListener` … | 插件自己 push 进 `subscriptions` |

⚠️ **边界诚实**（原则 4）：这不是沙箱。插件与宿主同上下文，可以直接改 DOM、
直连 IPC、写库外文件（实测见 `docs/架构原则-2026-10-13.md` §2）—— 协议只保证
**愿意登记的部分**能被还原。没登记的破坏，靠 §4.5 的**内核自愈**（快照 + `修复内核.cmd`）兜。

**验收判据**（`node tools/verify-takeover.mjs`，全自动，不碰用户鼠标）：

```
基线快照 → junction 进插件 → UI「重新扫描」→ 插件在时快照
         → 删 junction → 「重新扫描」→ 卸载后快照 → 逐条比对
```

11 项判据：插件确实加载 · 接管生效 · 订阅自动登记 · 命令表逐字回基线 ·
**接管还原到内核实现（`impl='core'`，不是 `null`）** · 订阅表回基线 · 面板 / 服务 /
编辑器规则 / 插件样式回基线 · 登记过的 DOM 改动已还原；外加一条**边界确认**：
未登记的 DOM 改动如期残留（证明内核确实只管登记过的）。
夹具 `examples/takeover-probe/`（**`verify-takeover.mjs` 的配套输入，保留作可复跑证据**）。

### 2.8 **整窗接管**（`view.overrideShell` · U2 · 2026-10-13 rev51）

原则 2 说插件"可以覆盖内核效果、可把内核搁在一边"—— 到这一节才算真的能**搁在一边**：
插件把内核 UI 整个请下场，自己在窗口里画。

```ts
interface ViewApi {
  overrideShell(spec: {
    /** 在宿主给的容器上画界面（直接用 DOM）。返回 Disposable 可选：释放时先调它，再清空容器 */
    mount: (el: HTMLElement, ctx: {
      pluginId: string; vault: string; platform: 'windows' | 'android' | 'other'
    }) => void | Disposable;
  }): Disposable;   // dispose = 释放接管，内核 UI 立刻回来
}
```

| 项 | 语义 |
|---|---|
| 生命周期 | `mount(el, ctx)` **只调用一次**；`dispose()` 先调插件返回的清理、**再**清空容器（顺序不能反） |
| 归属 | **同一时刻只允许一个接管者**；第二个插件来接管会**抛明确错误**（不是静默顶掉前者 —— 那样两边都不知道发生了什么） |
| 自动登记 | 返回值由宿主收进 `subscriptions` ⇒ **卸载插件即释放**（原则 3） |
| 窗口模式 | 接管的是"那个窗口的**内容区**"：标题条与关闭按钮**保留**（否则窗口关不掉） |
| 审计读数 | `window.__znKernelAudit().shell` = 接管者插件 id（`null` = 内核 UI 正常） |
| **内核逃生口** | 接管期间右下角有一颗小按钮（`Ctrl+Alt+Z` 同效）⇒ **强制释放接管**。它是"回到内核"的保底通道，插件怎么画都盖不住（`z-index:100`） |
| 风格 | 内核提供 `--zn-*` 令牌与 `.zn-ui-*` 类；用户已裁决**不强制**风格一致 |

**两条硬事实（实测，2026-10-13）**

1. **接管期间内核 UI 全部不在渲染树里** —— 连「插件管理」页都点不到。所以：
   · 内核**必须**有逃生口（否则插件不给退出入口、或崩在半路，用户只能重启应用）；
   · 逃生口释放时走的是 `ShellMount` 的 cleanup ⇒ 插件 `mount` 返回的 `dispose` **仍会被调用**
     （它能把句柄清掉，于是"再接管"不会撞自己的旧句柄）。
2. **插件义务：不要在 `onStartup` 里自动接管。** 否则一旦接管出问题，重启后**又**自动接管 ——
   用户连插件管理页都进不去。接管应当由用户动作（命令 / 按钮）触发。

**验收**：`node tools/verify-shell.mjs` → **12/12**（装插件 / 接管生效 / 内核 UI 让位 / 审计读数 /
插件按钮释放 / 逃生口按钮在 / 逃生口释放 / 插件收到释放 / 再接管 / 卸载后命令表回基线 / 无残留容器）。
示例 `examples/shell-demo/`；截图 `_shots/shell-takeover.png` · `_shots/shell-released.png`。

**加载规则**：① `apiVersion` 与内核不匹配 → 拒绝加载并给出人话原因 ② capability 只是**自述**（§4）：未知取值只**警告**、不拦截 ③ 插件抛异常 → 只卸载该插件，内核继续跑 ④ `entry` 与 `styles` 至少要有一个 ⑤ **平台声明与当前平台不符 → 跳过加载**（见下；这是正常跳过，不是错误）。

⇒ 主题；id 带 `demo` / `probe` / `hello` ⇒ 示例与探针；其余按 `reader` / `theme` / `editor` 关键词猜，
猜不出归工具（推断实现在 `src/lib/plugin-category.ts`）。它**只影响展示**：
加载、安装路径（`.zn/plugins/<id>/`）、权限都不看这个字段。
已安装的旧插件可以用 `node scripts/plugin-category-backfill.mjs <插件根>` 一次性补齐。

### 3.0 平台声明（`platforms`）

插件声明自己能在哪些平台跑 —— **只有两档；「双端」就是两个都写**：

| 写法 | 含义 |
|---|---|
| `["desktop"]` | 仅桌面（Windows / macOS / Linux） |
| `["android"]` | 仅移动端 |
| `["desktop", "android"]` | 双端 |
| 字段整个不写 | 全平台（向后兼容：老插件一个都不用改） |

宿主把 `host.platform`（`windows` / `android` / `other`）归一成这两档词汇 ——
**`other`（macOS / Linux 桌面）算 `desktop`**：桌面就是桌面，不该因为不是 Windows 就被判"不适用"。

对不上的插件**不加载**：命令与面板都不登记（**懒激活的也一样** —— 否则命令面板里会列出一条永远跑不通的桌面命令）；
插件管理页把它显示成「不适用 · 仅桌面端 / 仅移动端」、开关禁用，**并且不进错误横幅** ——
把桌面专属插件拷到手机上是很正常的操作，那不是错误。

取值写错（如 `"windwos"`）会**拒载并报错**、并列出合法取值，不再静默失效。

示例：`examples/platform-locked/`（声明 `["android"]`，桌面端据此整个跳过它）。

### 3.1 懒激活（`activationEvents`）

**不写这个字段 ⇒ 老行为**：库一打开就 `apply()`（现有插件零影响）。
**写了 ⇒ 分两步走**：

```
① 宿主只读 manifest：把 contributes.commands 静态登记进命令表
   ⇒ 命令面板/快捷键**不用加载插件**就能列出它
② 用户真的触发那条命令 ⇒ 宿主发现它没有实现 ⇒ 激活该插件 ⇒ apply()
   ⇒ 插件用 **bind(id, run)** 补上实现（不是 register！）
```

| 触发条件 | 含义 |
|---|---|
| 不写 / `onStartup` / `onVaultOpen` | 库打开即激活（旧行为） |
| `onCommand:<命令 id>` | **那条命令被执行时**才激活 |
| `onView:<面板 id>` | 面板被打开时激活（v0.1 只登记类型，宿主暂按启动处理） |

**为什么必须用 `bind` 而不是 `register`**：`register` 会连同元数据一起登记，
而元数据已经被静态声明占了 ⇒ **id 冲突**、插件加载失败。
`bind` 只补实现，元数据保持不动。

**示例**：`examples/lazy-demo/` —— 它的 `apply()` 里有一句 `host.log`，
打开命令面板时日志里没有、点过命令后才出现，这就是懒激活的直接证据。

### 3.1 入口形态（宿主按内容嗅探，四种都吃）

插件生态里的入口写法不止一种，宿主**不要求作者改代码**，按源码内容自动判断：

| 形态 | 判定依据 | 典型来源 |
|---|---|---|
| **ESM** | 有静态 `import` / `export` | 契约标准写法 |
| **CommonJS** | 出现 `module.exports` 或 `exports.x` | Lumina-Note：`module.exports = function (api) {}` |
| **全局注册** | 出现 `registerPlugin(` | Yank Note：`window.registerPlugin({name, register})` |
| **纯样式** | 没有 `entry`，只有 `styles` | 主题类插件不必写 JS |

导出形状也做归一，四种都认：`export default { apply }` · `export function apply` ·
`module.exports = function` · `registerPlugin({ register })`。

### 3.2 多文件插件（`files`）

```json
{ "entry": "index.js", "files": ["lib/greet.js", "lib/counter.js"] }
```

`files` 里声明的文件会被宿主一并读出，与入口一起装进一个**极简的 CommonJS 运行时**
（约 40 行），`require('./lib/x.js')` 因此可用 —— v0.1 的「只能单文件」限制解除。

解析规则：相对 `require` 的基准是**当前文件所在目录**；按 `spec` → `spec + '.js'` →
`spec + '/index.js'` 依次试探；找不到时报明确错误并提示去 `manifest.files` 里声明。

> ⚠️ **只有 CommonJS 的 `require` 能被解析**。ESM 的相对导入在 Blob 里没有 base 目录，
> 需要打包器才能展开 —— 不在 v0.1 范围内。多文件插件请按 CJS 写，或自行打成单文件 ESM。

### 3.3 纯样式插件

只声明 `styles` 即可（`capabilities` 可为空数组）：宿主把 CSS 注入 `<head>`，
卸载时整块移除。改的是内核既有的 `--zn-*` token，因此不必碰任何组件。
参考实现：`examples/theme-sepia/`。

### 3.4 单文件插件包（`.znp`，2026-10-18 rev119）

一个 JSON 文件，扩展名 `.znp`：

```json
{
  "znp": 1,
  "manifest": {
    "id": "demo", "name": "演示", "version": "1.0.0", "apiVersion": "^0.2.0",
    "entry": "index.js", "capabilities": ["fs:read"],
    "sha256": "<入口文件的 SHA-256 小写 hex>"
  },
  "files": { "index.js": "…源码…", "outline.css": "…" }
}
```

- **安装**：插件管理页「安装插件包（.znp）…」→ 选文件 → 确认框列出它**自称要的能力** + 是否带 `sha256`
  → `install_znp` 解包到**全局插件根** `<应用数据目录>/.zn/plugins/<id>/`（覆盖写同名文件，不删旧文件；
  rev173.5 起不再装进库内）。
- **完整性**：`manifest.sha256` = **入口文件**的 SHA-256。有值 ⇒ 加载前比对，不符**拒载**并说清哪段不符；
  没有 ⇒ 管理页标「未签名」。⚠️ 只覆盖入口一个文件 —— 是**完整性提示**，不是签名。
- **签名**（rev173.77）：插件目录里有 `signature.json` 时**必须验签通过才加载**，否则拒载并报原因。
  ```json
  { "alg": "ed25519", "keyId": "<信任根里的 id>", "sig": "<base64，64 字节>" }
  ```
  签名载荷由宿主**重算**（不信文件里的其它字段）：
  `zn-plugin-v1|<manifest.id>|<manifest.version>|<入口文件 sha256>`
  ⇒ 改入口 / 改 id / 改版本都让签名失效；改 README、加附件不受影响。
  信任根：`<应用数据目录>/.zn/trusted-keys.json`，形状
  `{ "keys": [{ "keyId": "…", "publicKey": "<base64，32 字节 raw Ed25519 公钥>" }] }`。
  验签在 Rust（`verify_plugin_signature`，`ed25519-dalek`）—— 旧 Android WebView 不一定有
  Web Crypto 的 Ed25519，放宿主端才能保证桌面 / 手机结论一致。
  工具：`node scripts/keygen.mjs`（生成密钥对）· `node scripts/sign.mjs <插件目录> <私钥.pem>`（写 signature.json）。
  **没有 `signature.json` = 未签名，照常加载**（本地自用插件不必签；分发才需要）。
- **为什么不是 zip**：Rust 侧没有 zip 依赖；插件包 99% 是文本，JSON 可读可 diff。
  二进制资源要 base64（目前没有插件带二进制）。
- **路径安全**：包内每个文件路径都过 `plugin_file()` 白名单（禁 `..`、禁绝对路径）。

## 4 capability 清单（v0.1 → **2026-10-13 起只是「自述」**）

> ## ⛔ 本节的性质在 2026-10-13 变了：**capability 不再是门**
>
> 用户重定原则（原话与逐条落地见 **`docs/架构原则-2026-10-13.md`**，冲突时以它为准）：
> 「**插件的权限完全由插件控制，内核不提供为插件提供任何安全保证**」。
>
> 同日的落地（详见该文档 §4.1）：

> - 设置页那一块改成**只读展示**：「网络与进程（自述）」
>
> ⇒ 下表**只描述"自述"的语义**（插件告诉用户"我要什么"），**不描述任何拦截**。

### 4.1 授权通道（`net` / `proc`）—— **2026-10-13 已移除**

原文（保留作历史）：记录落 `<私有根>/.zn/permissions.json`，设置页逐插件开关，
`loadPlugin()` 里查不到记录就**拒载**，且 fail-closed（文件坏了按"全部未授权"处理）。

**为什么删**：这套机制兑现的从来不是隔离，而是"**知情与承诺**" ——
而同样的知情**只用一行只读展示就能达成**（设置页列出声明者），却省掉了
「插件明明能用却加载不了」的摩擦，以及**为一道路径 ③ 就能绕过的门持续写防御逻辑**的成本。
裁决依据是 §2 里那六条实测（直连 IPC / 写库外 / 裸 `fetch` / 读任意文件 / 改 DOM / 卸载不还原）。

### 4.2 那条边界的**真实强度**（历史记录，结论仍然成立）

> ⚠️ **它从来不是隔离。** 进程内插件与宿主跑在**同一个 JS 上下文**里，至少有三条路
> 完全不经过 `permissions.json`：
>
> | # | 绕过路径 | 为什么拦不住 |
> |---|---|---|
> | ① | `globalThis.fetch` / `XMLHttpRequest` / `WebSocket` | 宿主从不碰这些 API，没有可拦截的咽喉点 |
> | ② | ESM 静态 `import 'https://…'` | 模块解析发生在 WebView 内部，宿主不参与（`examples/cdn-import` 走的正是这条） |
> | ③ | `invoke('write_note', {…})` | Rust 侧所有 `#[tauri::command]` 经 Tauri IPC 全局可达，绕过 `ctx.fs` 的裁剪 |
>
> **2026-10-13 用夹具又实测补了三条**（`examples/raw-ipc-probe/`）：
> ④ `invoke('write_absolute')` 能写**库外**任何路径 · ⑤ `convertFileSrc` + `fetch` 能
> **读**任意本地文件（实测读到 `C:/Windows/win.ini`）· ⑥ 能直接改宿主 DOM 且**卸载不还原**。
>
> ⇒ 结论升级：不只是「capability 不是边界」，而是**「内核不提供任何安全保证」**
>（原则 4 的原话）。因此 `fs:write` / `doc:write` 的裁剪一并删除 —— 路径 ③ 一样绕得过去。

> 📌 **2026-10-12 更正（本节初版写错了归因，已改）**
>
> **先说错误**：本节初版写「白名单外 `fetch(example.com)` 被 **CSP** 拦掉」——**归因错了**。
> 当时只看插件侧报的 `TypeError: Failed to fetch`，而**这个错误 CORS 与 CSP 都会产生**，
> 从插件侧根本分不出来。查 `adb logcat` 才看到真相：
>
> ```
> Access to fetch at 'https://www.baidu.com/' from origin 'http://tauri.localhost'
> has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present…
> ```
>
> ⇒ 那次是 **CORS**，不是 CSP。**教训**：分辨这两者**只能看 logcat** ——
> CORS 打印 `blocked by CORS policy`，CSP 打印 `Refused to connect … Content Security Policy directive`。
>
> **实测（`examples/net-demo/` 三个按钮，2026-10-12）**：
>
> | 靶子 | 过几关 | 结果 |
> |---|---|---|
> | ① `https://esm.sh/…`（**有** CORS 头） | CORS ✅ + CSP ✅ | **HTTP 200** |
> | ② `https://www.baidu.com/`（**无** CORS 头） | CORS ❌ | 被拦；logcat 明写 `blocked by CORS policy` |
> | ③ `https://registry.npmmirror.com/vue/latest`（**有** CORS 头，且**原本不在** CSP 白名单里） | 两关都过 | **HTTP 200（7184 字节）** |
>
> ③ 是用户 2026-10-12 裁决「**放宽** `connect-src`」之后的复测（现配置
> `'self' ipc: http://ipc.localhost https: http: ws: wss:`）；证据 `_shots/csp-12…15*.png`。
>
> **结论（上表要改读法）**：
> · `connect-src` 白名单确实能收窄出口，但对插件作者来说，**第一道真正会撞上的墙是 CORS** ——
>   目标服务必须回 `Access-Control-Allow-Origin`（WebDAV 服务器、自建 AI 代理大多要手动配这一条）。
> · 用户已裁决：把出口交回给 ⑧ 的**逐插件授权 + 知情承诺**，不再逐域名维护白名单。
> · ⚠️ **未验证项（诚实标注）**：白名单期是否真的拦过某次 `fetch`，本轮**没有回测**
>   （当时那次失败已证明是 CORS）。所以「CSP 拦网络」这句话在 Android 上**目前只有间接证据**，
>   别当铁律引用。
> · 仍然成立：路径 ②（ESM 静态 `import`）受 `script-src` 约束；路径 ③（`invoke` 任意 Rust 命令）
>   **完全不受 CSP 约束** —— **真正的咽喉点始终在 Tauri IPC，不在 WebView**。

> ⚠️ **仍然没有沙箱**（与 4.2 同一件事的另一面）：一个 `while(true)` 会卡死整个应用。
> ~~沙箱（Worker + 内存/时长上限）排在 v0.2。~~ **2026-10-21 明确放弃**：Worker / 子进程插件宿主
> **不做**（`decisions/D-001` accepted，用户裁决），兜底是原生看门狗（心跳 5 s 超时 ⇒ `exit(101)` ⇒ 下次启动禁用该插件 ⇒ 一键恢复）。
> **装插件前先问自己：这个插件是谁写的。**

   缺了第一件（主题令牌），WebView 里的插件会写死颜色 —— 兜底路必然破坏「风格统一」。

> **调研给的一条反直觉结论**（值得记住）："声明式 schema 由宿主渲染"在六家成熟项目里**没有对等先例**
> （最接近的只有 VS Code `contributes.views` 与 SilverBullet `codeWidget`）。
> 风险：一旦 `UINode` 表达力不够，插件会集体转投 WebView，主路被架空。
> ⇒ 对策：**第一批真插件（灵感流）必须用 `UINode` 写完**，不许用 WebView 绕过 —— 这是对主路的压力测试。
