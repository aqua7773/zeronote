## §1 四条原则（用户原话，2026-10-13）

| # | 原话 | 落地含义 |
|---|---|---|
| **1** | 「内核负责的事情就是没有任何插件运行时还是一个普通的笔记应用」 | 内核壳自足 —— 零插件也要能开库、编辑、保存、搜索、管理文件 |
| **2** | 「插件可以有很强的能力，权限等同于内核，可以覆盖掉内核的效果，可以完全修改成另一个应用，把内核搁在一边」 | 插件**不是**受限扩展，是**同权限接管者**；可以整块替换内核 UI |
| **3** | 「插件可以覆盖掉内核的实现，但是不能对内核造成破坏，也就是关掉插件之后内核还能用」 | 接管必须**可还原**；卸载 = 回到原则 1 的裸机状态 |
| **4** | 「插件的权限完全由插件控制，内核不提供为插件提供任何安全保证」 | 内核**不做权限判定**、不承诺隔离；`capabilities` 不再是门 |

### §1.2 用户当场的两处裁决

| 议题 | 裁决 |
|---|---|
| 权限门拆到哪一步 | **全部拆掉** —— `net`/`proc` 不再默认拒载、未知 capability 不再拒载、`fs`/`doc` 的 capability 裁剪放开；`capabilities` **降级为自述**（插件页展示"它要什么" + UI 挂载位合法性校验）；设置页「网络访问」区块改为只读展示 |
| 「把内核搁在一边」做到哪层 | **真窗口 + 主壳接管点，分两步** —— ① U1：插件用 Tauri 真窗口开自己的界面（可拖 / 全屏 / 多开）；② 加「壳接管点」：插件能整块替换主区渲染，内核 UI 让位 |
| `platforms` 门 | **保留** —— 它是"桌面插件别装到手机上"的实用门，不是安全边界，与原则 4 不冲突 |

### §1.3 原则 5（2026-10-13 追加）：**修复优先于防护**

> 原话：「那就全部放开，内核完全不设防，也不提供任何安全保障，插件想做什么全凭自觉，
> **内核只需要提供一个修复的方式，在插件进行不可逆修改后，从备份的内核重新构建就行**」

| 含义 | 落地 |
|---|---|
| 内核**不做**任何防护 | §4.1 拆门不是妥协，**就是设计**；不要把 §2 的绕过当成漏洞去补 |
| 内核**要做**一条修复路径 | §4.5：快照 + 一键「从备份重新构建」 |
| 「全凭自觉」 | 插件作者的义务；§2.1 实测出的还原缺口**就此定性为可接受代价**，代价由修复机制覆盖 |

⇒ 上一轮我提的「信任层」不再只是约定，而是**信任层 + 兜底**：插件可以乱来，内核保证你能回到已知 good。

### §1.4 数据安全与备份来源（同日追加说明）

- **内核不提供安装插件后的数据安全保证** —— 库里的 `.md`（以及任何用户数据）**不在保护范围内**：
  插件能真删（`purge_trash`）、能整库重写，用户自担。
  **⇒ 原 §6 待决 2 就此结清：原则 3 的「不得破坏」只指内核可用性，与数据无关。**
- **备份放本地**（`_kernel-snapshots/`）。
- **将来开放第三方使用时，恢复改为从 GitHub 拉备份** —— 内核本来就在 git 仓库里，
  恢复即「从远端取已知 good 的 tag/commit → 还原 → 重建」，不必依赖本机残留的快照。

## §2 实测：capability 表本来就不是边界

> 夹具 `examples/raw-ipc-probe/`（一次性探针，manifest **只声明** `["command","view:sidebar"]`
> —— **没有** `net`、**没有**任何 `fs` 写权限）。结果写在 `window.__rawProbe`，CDP 直读。

| # | 测什么 | 实测结果 | 结论 |
|---|---|---|---|
| ① | `window.__TAURI_INTERNALS__.invoke` | `function` | 插件与宿主同上下文，直连 IPC 的入口就在手边 |
| ② | 不经 `fs` 原语，直连 IPC 读 `list_plugins` | `["docprobe","outline-map","raw-ipc-probe"]` | 原语表**不是**唯一通路 |
| ③ | 直连 IPC **写库外路径**（`write_absolute`） | 成功；磁盘实测 `_tmp-test/raw-ipc-outside.txt` 真被写出 | `fs` 原语"只收库内相对路径"的约束**被绕过** |
| ④ | 裸 `fetch('https://esm.sh/')`，manifest **无** `net` | `HTTP 200` | `net` 的默认拒载**被绕过** |
| ⑤ | 直接改内核 DOM（状态栏） | 改成红条纹，**插件未还原** | 见 §3 第 3 条缺口 |
| ⑥ | `convertFileSrc('C:/Windows/win.ini')` + `fetch` | `HTTP 200 len 92` —— **真读到文件内容** | **任意路径可读**：`assetProtocol.scope` 是 `["**"]`（全盘）＋ CSP 放宽后 `connect-src` 含 `http:` |

**复跑方式**（dev 在跑、CDP 端口在）：

```powershell
cd ZeroNote
# 把探针 link 进测试库，再 reload 页面
New-Item -ItemType Junction -Path "_tmp-vault-tb\.zn\plugins\raw-ipc-probe" -Target "$PWD\examples\raw-ipc-probe"
node tools/cdp.mjs eval "location.reload()" wait 5000 eval "JSON.stringify(window.__rawProbe)"
```

**这印证了代码里早就写下的话**（`src/components/Settings.tsx:213-217`）：
「这不是隔离，是一条可绕过的边界……裸 `fetch`、ESM 静态 `import`、直接 `invoke()` 三条路都不经过这张表」。
⇒ 原则 4 = **把这条既存事实正式承认**，而不是补一道假墙。

### §2.1 卸载还原的实测（原则 3 的缺口）

`togglePlugin` → `setReloadToken` 只重跑 effect、**不刷新页面**（`src/App.tsx:1968-1976`），
因此能在同一次页面生命周期里观察卸载行为：

```
重扫前：状态栏 backgroundImage = "repeating-linear-gradient(45deg, rgb(239,68,68) … rgb(127,29,29) 12px)"
重扫后：document.body.innerText.includes('raw-ipc-probe') === false   ← 插件确实卸了
        状态栏 backgroundImage 仍是那条红条纹                          ← 没还原
```

**结论**：内核的「卸载即净」只回收**内核记账的资源**（命令 / 面板 / 样式 / 服务 / 编辑器标记，
见 `src/kernel/plugin-host.ts:585-598` 与 `App.tsx:1747-1758`）。
插件自己伸手改的宿主 DOM **不在账上** —— 除非插件作者在 `dispose()` 里自己写回去。

> ✅ **2026-10-13 rev49 已补**：现在有了第三条路 —— `host.onRollback(fn)` 登记
> （登记过的内核代调，没登记的自己负责），且**命令 / 面板 / 订阅**的自动登记也补齐了。
> 落地与判据见 §4.2 与契约 §2.7。

证据：`_shots/raw-probe-01.png`（插件在时的红条纹）、`_shots/raw-probe-02-unloaded-but-dirty.png`（卸载后仍脏）。

### §2.2 Tauri 侧的硬边界（唯一不由 ZeroNote 说了算的地方）

`src-tauri/capabilities/default.json`：`windows: ["main"]`，permissions =
`core:default` · `dialog:default` · `statusbar:default` · `core:app:allow-exit` ·
`core:window:default` / `allow-start-dragging` / `allow-minimize` / `allow-toggle-maximize` / `allow-close`。

**插件已经能**（无需内核做任何事）：系统路径查询、原生菜单、事件系统、**退出应用**、窗口控制、
系统级文件/目录选择对话框（`dialog:default` ⟹ 能挑任意目录、拿到路径，再配 asset 读 / `write_absolute` 写）。

**插件还不能**（Tauri 侧**强制**拒绝，不是内核的纸面门）：

| 不能做什么 | 根因 |
|---|---|
| 开新窗口 / 新 webview | 缺 `core:webview:allow-create-webview-window` —— **U1 要动的就是这里** |
| 执行系统命令 | 未装 shell 插件 |
| 删除 / 移动库外文件 | 内核没提供该命令（`write_absolute` 只能**写**） |

⇒ 这三条是「插件权限」里**唯一需要内核放行**的部分；其余能力插件早已自行具备。

### §4.2 接管协议 + 还原验收（原则 3 的地基）—— ✅ **2026-10-13 已实现（rev49）**

原方案：

- **规矩**：内核提供的**每一条"接管"入口必须返回 `Disposable`**，由宿主自动登记进 `subscriptions`；
  卸载时逐个 dispose ⇒ 内核侧回到基线。
- **插件自绘/自改宿主 DOM**：内核**不拦**（原则 4），但提供登记点
  （建议 `ctx.host.onRollback(fn)` 或 `ctx.view.takeover(el, mount)` 形式）——
  **登记过的内核负责还原，没登记的自己负责**。契约里写成插件作者的义务。
- **验收判据**（可自动化，用 CDP）：卸载插件后
  ① 内核 DOM 与基线快照一致（关键节点属性/样式）② 命令表回到基线
  ③ 事件订阅表清空 ④ 三条基线（`tsc` 0 / `oxlint` 4 / `cargo test`）不变。

**落地结果**（契约 §2.7 是权威版本）：

- 采纳 **`ctx.host.onRollback(fn)`**（没走 `view.takeover(el, mount)`：U2 主壳接管点（§4.4）
  才是它的自然归宿，现在提前造一个"局部挂载点"会和 U2 打架）。
- 自动登记扩到 **`event.on` / `fs.watch` / `doc.on`**（此前契约要求插件自己 push，
  实测没人推 —— 与当初 `command`/`view` 同一个坑）。
- **顺带修掉一个真缺口**：`command.bind` 覆盖内核命令后，`dispose` 只 `delete run` ⇒
  卸载插件把 `core.newNote` 变成"有元数据没实现"（四个入口一起废、命令表看不出变化）。
  现在先记原实现、dispose 放回；契约 §2.1.1 记了这条。
- 验收脚本 **`tools/verify-takeover.mjs`**（11 项判据 + 1 项边界确认）；
  读取口是 `window.__znKernelAudit()`（命令归属 / 订阅表 / 面板 / 服务 / 编辑器规则 / 插件样式）。
  命令归属靠实现上的 `__znImplTag` 标记区分 `core` / `plugin:<id>` / `null`
  —— **`null` 就是"接管没还原"**（对照实验：临时改回旧行为 ⇒ 判据精确报 9/11）。

### §4.4 U2 主壳接管点（中）

- 契约草案：`view.overrideShell(spec: { mount: (el: HTMLElement, ctx) => void | Disposable }): Disposable`
- 语义：插件接管**主区/整窗渲染**，内核 UI 让位；dispose 后内核 UI 复原
- 风格一致性：内核提供 `--zn-*` token 与 `.zn-ui-*` class，靠插件自觉（用户已接受"放弃声明式唯一主路"）

### §4.5 内核自愈：快照 + 一键「从备份重新构建」（原则 5）—— **2026-10-13 已实现并演练**

**用法**（零依赖，`node` 直跑；**不依赖应用本体**）：

```powershell
node scripts/kernel-snapshot.mjs --reason "说明"                # 建快照
node scripts/kernel-restore.mjs --list                          # 列快照
node scripts/kernel-restore.mjs --latest --dry-run              # 只看会改什么
node scripts/kernel-restore.mjs --latest [--build] [--prune]    # 恢复（可选重新构建 / 删多余文件）
修复内核.cmd                                                    # 双击 = 交互模式（应用起不来时唯一的路）
```

| 项 | 实现 |
|---|---|
| **快照什么** | **白名单**定义内核边界 —— `scripts/kernel-snapshot.mjs` 的 `KERNEL_PATHS` **就是"内核边界"的可执行定义**：`src/` · `src-tauri/{src,capabilities,plugins,icons}` · `Cargo.{toml,lock}` · `build.rs` · `tauri.conf.json` · `package.json` · `pnpm-lock.yaml` · `patches/`（**重建必需**）· `scripts/`＋`tools/`（**含自愈脚本自己**：脚本被改坏也得能修回来）· `docs/` · 各配置文件。**不含** `node_modules/`、cargo target、`dist/`、`src-tauri/gen/`、`_shots/`、`_tmp-*`、`examples/`、**库数据** |
| **存哪** | `<repo>/_kernel-snapshots/<YYYYMMDD-HHmmss>/`（`files/` ＋ `manifest.json`：文件清单 + SHA256 + 构建命令 + git HEAD/branch/dirty）。**已加进 `.gitignore`**（内容与仓库重复）；**异地恢复走 GitHub 取已知 good 的 tag/commit** |
| **实测量级** | **701 个文件 / 5.32 MB**（本机基线） |
| **四条设计规矩** | ① **恢复前先验备份自己**（逐文件 SHA256；不符 ⇒ **拒绝恢复** —— 拿坏备份覆盖好代码比不恢复更糟）② **恢复前先把当前状态另存**为 pre-restore 快照（修错了能退回来）③ **默认不删**快照外文件（要删显式 `--prune`）④ 恢复后**复核**到逐字节一致 |
| **演练证据**（2026-10-13 真跑） | 四种坏法一次打进去：内容被追加垃圾 / 整个文件被写成非法 JSON / 文件被删 / 多出垃圾文件 ⇒ `--dry-run` 准确报「3 改动 + 1 多余」⇒ 恢复后**独立复核**（不采信脚本自报）：行数复位 671、JSON 合法、缺失文件补回、垃圾被 `--prune` 删掉、**0 处差异**；另验 **坏快照被拒绝**（退出码 1，源文件未被触碰） |
| **构建** | `--build` 跑 manifest 里记的 `buildCommands`（`pnpm install --frozen-lockfile` → `pnpm tauri build --no-bundle`）；未设 `CARGO_TARGET_DIR` 会警告（本机铁律：Rust 产物外移，否则 D8050） |

**三条诚实边界**（写进契约，别让人误以为这是防护）：

1. **防意外，不防恶意** —— 插件有全盘读写（§2 实测），备份文件同样能被写坏、被扫到。这套机制的价值是「改错了 / 误删了 / 写坏了」一键回到已知 good，**不是**「恶意插件挡得住」。
2. **不含用户数据** —— 库里的 `.md` 不在快照内（插件能真删）。要不要给库也做快照/版本化，是**另一个决定**（见 §6）。
3. **「重新构建」要工具链**（Rust + pnpm，本机有）。要免工具链就得额外备份**已构建产物**（`zeronote.exe` + `dist/`）。**建议两者都做**：产物优先（秒级、免工具链），源码快照兜底（能重建）。
