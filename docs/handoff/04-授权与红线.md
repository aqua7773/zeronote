## 2 八条硬约束

1. **capability / 安全模型变更** → 先拿用户对「具体方案」的同意（方向同意 ≠ 方案同意）
2. **每批交付**：`verify.ps1` 全过 ＋ 实测证据 ＋ 提交 ＋ `HANDOFF.md` 新 rev
3. **手机截图走** `adb shell screencap`；CDP `shot` 抓不到 WebView 里的 canvas
4. **内核保持薄**；**静默失效比报错危险**（看数字，不只看 "ok"）
5. **GUI 验收用 `gentle_*`**；截图按窗口 rect 向内缩 ~10px
6. **动手前先查现成**（`docs/开发约定.md` §0.5）；改代码 / 重构前先读该文档
7. **安卓测试机只跑已装的 dev 包**，不重新编译 / 安装；**不装 release 包**
8. **测试 / 验收产生的插件不留在「功能」里**：探针 / 夹具 / 演示只放 `examples/` 或临时目录，用完即删；改 `examples/` 后必须让页面 reload 再重扫

## 3 验收三级门（不分级不算完）

| 门 | 内容 | 谁做 |
|---|---|---|
| **G1 自动化** | `pwsh -File scripts\verify.ps1` 全绿 | AI |
| **G2 自验** | 桌面 dev 或真机 debug 亲手走一遍，截图落 `_shots/` | AI |
| **G3 用户验收** | 用户人眼确认 | 用户 |

**三条全过才能提「发版」**。只过 G1 就提发版 = 违规 —— 0.9.29 就是只过 G1、没验包体积，把 121 MB 的 universal 发了出去。

> **双端验收前置（2026-11-06 用户拍板，硬约束）**：发版前，**除非本次改动确实只涉及单端**（须在 HANDOFF 段写明「仅桌面」或「仅 Android」，且另一端的二进制与资源未变），否则**必须双端验收通过** —— 桌面 G2 + 手机真机 G2，再走 G3。
> ⛔ **禁止把「发版」当作获取手机新包的手段**：Rust / 原生改动先 `android-dev.cmd` 重编 dev 包，在真机上验过再发版。新包 ≠ 必须先发版。

## 4 破坏性操作

1. 确认无引用（`grep`）
2. 确认有备份或可重获
3. 确认不是回退入口 —— `*-backups\`、`_dsh\backup\`、`_logs\` **永不删**
4. 说清删的是什么、为什么能删

删链接用 `[System.IO.Directory]::Delete($路径, $false)`，**绝不用 `Remove-Item -Recurse`**（会删掉链接目标里的真实文件）。

**绝不自行重启桌面端 / 客户端** —— 会终止当前会话，一律交用户手动做。

## 5 Windows 特定

- `.ps1` 存 **UTF-8 with BOM**，执行显式 `-ExecutionPolicy Bypass`
- 别用 `$env:ProgramFiles` / `$env:SystemDrive`（受限环境里可能是 null），用 `[Environment]::GetFolderPath('ProgramFiles')`
- 环境变量在进程启动时快照：本会话读不到新写的用户变量，用 `[Environment]::GetEnvironmentVariable('X','User')`
