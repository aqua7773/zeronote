## 1 技术前提（已验证 / 待验证）

| 项 | 结论 | 依据 |
|---|---|---|
| 外部模型 API 可直连 | ✅ **DeepSeek 允许 CORS**（预检回 `access-control-allow-origin: http://tauri.localhost`） | 2026-10-27 `curl -X OPTIONS` 实测 |
| OpenAI 预检 | ❌ 本机直连失败（`exit 1`，大概率要代理） | 同上；不影响主路径，走降级 |
| 流式 SSE | ✅ DeepSeek 可行（浏览器 `fetch` + `ReadableStream`）；其它厂商失败时 **降级 `net.fetch` 非流式** | 契约 §2.6.1 `net.fetch` 无流式，只能整段返回 |
| 跨插件命令 | ✅ 可用（第二版才用） | `plugin-host.ts:371-393` |
| 防递归 | ✅ 插件写盘发 `note:changed`，不触发 `note:saved` | `contract.ts:100-105` |
| Key 存储 | ✅ `tauri-plugin-keyring-store` 已在依赖里 | `Cargo.toml:47` |
| 定时器 | ⚠️ `setInterval` 可用；Android 前台外会停 ⇒ 打开时补做 | `ROADMAP.md` §5 裁决 |
| 插件重载 | ⚠️ interval / 事件必须进 `ctx.subscriptions`，否则重载泄漏 | 契约 §2.7 接管协议 |

### rev173.201 · 任务系统（约 7 h）✅ 已落地（2026-10-27）

**交付**

### rev173.202 · 定时触发 + 执行模式（约 5 h）✅ 已落地（2026-10-27）

**交付**
- 定时触发：每天 HH:MM / 每周几（不做 cron 全语法）
- 桌面：`setInterval` 每分钟检查；启动补做
- Android：打开 app 时补做未跑的
- 执行模式：创建任务时 AI 自选「固定步骤」或「现场判断」；步数上限 4
- 失败：记错误、标红、下次重试

**验收**
- 建一条「每天 23:00 小结」→ 桌面到点跑（改系统时间或改任务时间为 +1 分钟实测）
- 关掉 app 再打开 → 补做一次并记「补做」
- 复杂任务超 4 步 → 停止并记「超过步数上限」
- `verify.ps1` 全过

**测试**：时间判断、补做去重、步数上限

## 3 关键设计（开工前定）

| 项 | 决定 |
|---|---|
| 插件形态 | 纯 JS，`examples/ai-plugin/`，走市场不预装 |
| 文件结构 | `index.js`（装配）/ `llm.js`（模型调用）/ `tools.js`（工具表与执行）/ `tasks.js`（任务调度）/ `panel.js`（渲染） |
| 面板 | `registerPanel({ location: 'main' })`，`render` 返回 UINode；对话流用 `mount`？（开工时确认 UINode 是否支持流式刷新，否则改 `mount` DOM） |
| 工具协议 | 每个工具：`{ name, description, parameters(JSON Schema), run(args, ctx) }`；模型侧用 OpenAI tools 格式 |
| 会话模型 | 对话 = 消息数组（system + user/assistant/tool），裁剪到 20 条；任务运行 = 单轮 + 最多 4 步工具循环 |
| 并发 | 任务执行串行队列（一次一个，避免同篇笔记被两个任务同时改） |
| 错误 | 全部转成中文可读错误 + 原始 status/body 折叠 |

## 4 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 部分服务商不允许 CORS | 中 | `net.fetch` 非流式降级；界面标注 |
| 工具循环失控（模型反复调同一工具） | 中 | 步数上限 4 + 相同工具相同参数去重 |
| 插件重载泄漏 interval / 事件 | 高 | 全部进 `ctx.subscriptions`；重载后检查任务不重复跑 |
| store 存不下大量对话历史 | 低 | 历史只留最近 N 条；任务记录只留 10 |
| Android 定时不准 | 确定 | 补做机制 + 界面写明「打开时补做」 |
| 分类准确率不达预期 | 中 | rev202 抽样验收；不达标就改指令模板而不是改代码 |
| 面板流式渲染性能 | 低 | 按 30–60 ms 批量刷新，不逐字重排 |
