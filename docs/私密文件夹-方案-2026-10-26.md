## 0 一句话结论

做成 **一个纯 JS 插件 `private-notes`（`examples/private-notes/`）+ 内核一处 40 行通用钩子**：

- 私密笔记的**整棵树在 `.zn/private/`** —— 内核的 `list_notes` / `list_dirs` / 回收站本来就跳过 `.` 开头的目录 ⇒ 文件树、全局搜索、标签、反链、时间流**天然看不见**，不需要在内核里加任何"排除私密"的分支。
- **每篇笔记一个密文文件** + **一份加密索引**（标题也进密文）⇒ 文件名是随机 id，磁盘上不泄漏标题。
- 编辑**走内核 MarkdownEditor**（预览 / 工具栏 / 撤销 / 全局替换全部照用），靠内核新增的 `doc.registerCodec()` 在"读盘后 / 写盘前"各做一次转换。**内核不认识加密**，只认识"这个路径的内容要过某个转换器"。
- 同步：`vault.json` **按环拆成两个文件**（否则两台设备各改一个环的密码会互相覆盖）+ 四个同步插件把 `.zn/private/` 当**目录树**递归搬。

## 3 要拍板的三个决策

### D1 加密粒度

| 选项 | 做法 | 代价 |
|---|---|---|
| **A（推荐）每篇一密文** | `.zn/private/notes/<id>.zn`（每篇一个）+ `.zn/private/index.zn`（加密的标题/时间表） | 列表要先解一次索引；打开要解一篇。**同步单元 = 一篇**，双端各改不同笔记不冲突 |
| B 整文件夹一个密文 | `.zn/private/private.zn`（打包所有笔记） | 实现最省事；但**同步永远是整包**（双端必冲突）· 每改一个字要重打整包 · 100 篇时列表要全解 |

### D2 编辑怎么接内核（**最关键**）

| 选项 | 做法 | 代价 |
|---|---|---|
| **A（推荐）内核加 `doc.registerCodec()`** | 内核在 `openNote` 读盘后 / `saveNow` 写盘前各问一次"有没有转换器"（约 40 行，`useDocSession` + `App.saveNow` + 外部重载 + 三方合并的 base）。**内核不认识加密**，只认识路径 → 转换器 | 契约新增 1 个方法（第 12 个原语边缘）；需在契约文档登记 |
| B 插件自绘编辑器 | 面板里 textarea / 自渲染 Markdown | 零内核改动；但**没有预览、没有工具栏、没有撤销栈**，与普通笔记体验割裂 |
| C 临时明文落盘 | 解密写到 `.zn/private/.open/<id>.md` → 内核编辑器正常打开 → 关闭/锁定时删除 | 零内核改动、体验完整；但**明文在磁盘上存在过**（崩溃/断电会残留，只能靠启动清理兜底） |

> D2-A 的 40 行是"通用钩子"，不是"给私密文件夹开的后门"：导图 / 加密 / 压缩 / 任意容器格式都能用同一个钩子。

### D3 同步怎么拆（**无分叉，仅确认**）

1. `vault.json` → `vault.notes.json` + `vault.secrets.json`（每环一个文件、各自一个同步单元）。不拆的话，A 改 notes 密码 + B 改 secrets 密码 = 必冲突 = **一边的重包裹丢失，那台设备直接解不开**。
2. 四个同步插件（webdav / s3 / git / folder）的私密段从"固定清单"改成"清单 + `.zn/private/` 目录树递归"，并补**本地删除传播**（现状只有 `remote-deleted`，没有 `local-deleted`）。
3. 备份插件把 `.zn/private/` 整棵密文树随包（与 `_secret/` 同规格）。

## 4 推荐设计（假设 D1=A、D2=A）

### 4.1 磁盘布局

```
<库>/.zn/private/
  index.zn               # 加密 JSON：{ v:1, notes:[{id,title,createdAt,updatedAt}],
                         #              trash:[{id,title,deletedAt}] }
  notes/<id>.zn          # 每篇一个密文（正文 = markdown，可含 frontmatter）
  trash/<id>.zn          # 回收站里的密文（标题仍在 index.zn 的 trash 段）
```

- `<id>` = 16 位 base36（单调时间 + 随机），**不含标题** —— 磁盘上看不出有几篇、叫什么。
- 密文格式复用 `security` 的 `zn1.<nonce>.<ct>`（base64url），AAD = `notes|notes|data`（环 `notes` · 容器 `notes`）。
- **索引与正文的密文可互换解密**（同一容器同一 AAD）⇒ 解密后做**明文内校验**：索引解出来必须是 `{v:1,...}`，正文解出来必须是字符串；不匹配就拒绝，不落盘。
- 文件名用 id 而不是标题 ⇒ 标题泄漏只剩"篇数"。

### 4.2 编辑链路

```
打开：doc.open('.zn/private/notes/<id>.zn')
  → 内核 readText → 命中 codec → codec.decode(raw) = crypto.decryptText({ring:'notes', container:'notes'})
  → 明文进 MarkdownEditor（预览 / 工具栏 / 撤销 / 全局替换全部照用）
保存：编辑器内容 → codec.encode(text) = crypto.encrypt(...) → writeText
```

内核改动点（4 处，全部是"取内容/写内容"的必经点）：

1. `contract.ts` — `DocApi.registerCodec({ id, match(path), decode(raw, path), encode(plain, path) })`
2. `useDocSession.openNote` — `text = codec ? await codec.decode(text, path) : text`
3. `App.saveNow` — 写盘前 `encoded = codec ? await codec.encode(content, path) : content`
4. `App.reloadActiveFromDisk` / 三方合并的 base — 同样过 decode，保证 base 是明文

**未解锁时的行为**：`decode` 抛「私密文件夹已锁定」→ 打开失败给提示，不写坏文件（内核写盘前先 encode，encode 抛错就整次保存失败，原子写不会留下半截）。

### 4.3 面板（独立入口）

- `view.registerPanel({ id:'private.panel', location:'sidebar'|'main', ... })`，与 `secrets` 同一套形态。
- **未解锁**：只画建立/解锁表单（主密码 + 恢复码指引），不列任何标题。
- **已解锁**：列表（标题 / 更新时间）+ 搜索框 + 「回收站」tab + 「新建」按钮。
- 点一条 ⇒ `doc.open(...)`；锁定后若当前文档是私密笔记 ⇒ **先保存再关**（避免丢改动）。
- 空闲 3 分钟（`notes` 环已有）⇒ `security` 锁环 → 本插件收到 → 关文档 + 遮罩 + 清内存索引。

### 4.4 独立搜索

- 解锁后：`listFiles('.zn/private/notes')` → 逐篇 `decryptText` → 明文缓存进内存（100 篇 × 20 KB ≈ 2 MB，实测解密约 1 ms/篇）。
- 搜索 = 内存里对明文做子串匹配（与内核搜索同一套多关键词 AND 语义，代码可抄 `index-api.ts` 的纯函数）。
- 锁定 = 清缓存。**不落盘任何明文索引**（内核 `index.scoped('private')` 不用 —— 它虽然只在内存，但 reload 后要重建，而重建必须再解密一遍；直接用插件自己的缓存更简单）。

### 4.5 回收站

- 删除 = 从 `notes/<id>.zn` 移到 `trash/<id>.zn`（密文搬家，不解密）+ `index.zn` 里记 `deletedAt`。
- 面板「回收站」tab：恢复（搬回 + 清 `deletedAt`）· 彻底删除（`purge_private`）。
- **保留期**：与全局回收站一致（先看现状是几天，实现时对齐）。

### 4.6 同步

- `vault.json` 按环拆（D3-1）。迁移：读到旧 `vault.json` ⇒ 拆成两个新文件 + 旧文件留一份 `.bak`；`security` 优先读新文件、回落旧文件。
- 私密目录：manifest 里新增 `privateTree: { "<rel>": { fp, at } }`，四分支与现有 `syncPrivate` 完全同构（两边一致 / 只远端变 / 只本地变 / 双端变），**双端变 = 保留本机副本 + 取远端**（密文无法合并）。
- 删除传播：新增 `local-deleted`（baseline 有、本地没了、远端还在 ⇒ 删远端）。

## 6 诚实边界（写清，别让人以为这是防护）

1. **不是沙箱**：插件与宿主同上下文（`D-001`），同进程内的恶意代码能读内存里的明文。
2. **加密保护的是"文件被拿走"**：磁盘上是密文；但**解锁期间**编辑器里、撤销栈里、面板缓存里都是明文。
3. **文件名不泄漏标题，但泄漏篇数**（`notes/` 下有几个文件）。
4. **索引与正文同容器**：密文互换能解开（明文内校验会拒绝，但这不是密码学隔离）。若要强隔离，得让 `security` 支持"一环多容器"（约 30 行），列为后续加固。
5. **内存清零是"尽力"**（同安全方案 §6）：JS 字符串与 GC 副本不可控。
6. **插件卸载 = 私密笔记留在磁盘上**（密文），重新装回来输主密码即可解 —— 与密码库同一规则。
