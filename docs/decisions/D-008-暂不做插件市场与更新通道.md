# D-008 暂不做插件市场 / 更新通道

> 状态：**pending** ｜日期：2026-10-21 ｜重议条件：要给别人分发插件（不止本机），或插件数 > 10、手动拷文件夹成为负担
>
> ⚠️ **2026-10-25（rev173.140）重议条件已满足**：预装插件 **13 个 > 10**，且用户开始问「市场要怎么做」。
> **决策本身仍是 pending**（做不做、做到哪一层未拍板），但已有一份可行性调研：
> [`docs/插件市场-调研-2026-10-25.md`](../插件市场-调研-2026-10-25.md) —— 结论是「静态索引 + 一键装」约 1.5 天，
> 不需要服务端；**先决条件是信任根预置与签名覆盖到多文件**（本文 §7 三个拍板点）。
> 本文下面的论证仍成立，只有「唯一用户就是作者 ⇒ 无需求」这一条要按新情况重估。

## 背景

0.3.0 之后主线只剩两项：Worker / 子进程插件宿主、插件市场 / 更新通道。
2026-10-21 用户裁决：**两项一起降级，不排期**（宿主隔离那一侧更彻底 —— 用户当天明确「放弃」，见 [D-001](D-001-无插件沙箱.md) 的追加确认；契约 §6 的 v0.2 行只是原先没跟着改）。

插件分发在 rev173.77 之后的现状：

| 已有 | 在哪 |
|---|---|
| `.znp` 单文件安装 + `manifest.sha256` 完整性校验 | rev119 |
| **Ed25519 真签名**：`signature.json` + 信任根 `.zn/trusted-keys.json`，有签名必须验过否则拒载 | rev173.77 · `scripts/keygen.mjs` / `scripts/sign.mjs` |
| 插件页三态（已签名 / 已校验 / 未签名） | rev173.77 |
| 装卸方式：文件夹放进 `<应用数据目录>/.zn/plugins/<id>/` → 「重新扫描」 | rev173.5 |

签名解决的是「**是谁发的**」，没有解决「**从哪找新版**」。

## 决定

- **不做插件市场**：没有远端索引、没有站内浏览、没有一键安装。
- **不做更新通道**：没有版本检查、没有静默升级、没有自动回滚。

插件分发继续走「本地文件夹 / `.znp` 文件 + 手动放」，升级继续是「删旧目录 → 放新目录 → 重扫」。

## 理由（一手来源）

- **自用定位**：唯一用户就是作者，插件源码就在 `examples/` 里，"找新版"这个需求不存在（与 [D-002](D-002-不做云同步.md) 同一条理由的延伸）。
- **市场必须先有信任根分发**：信任根现在是手工放 `trusted-keys.json`。做市场就要先回答"信任根从哪来"，否则等于用一条未验证的通道去分发已验证的包 —— 签名白做。
- **更新通道是新的故障面**：静默升级 = 在用户不知情时替换可执行 JS。本项目的模型是插件代码能读任意文件、能 `invoke` 任意命令（契约 §4.2 六条实测），换代码的后果比普通应用大得多。
- **契约原本就挂在"未做"**：`docs/内核契约-v0.2.md` §7 第 4 条，本次改为指向本决策。

## 代价与边界

- **没有发现入口**：装新插件得你自己知道名字、自己拿目录。
- **没有版本提示**：旧插件不会自己说"有新版"；桌面与手机之间的插件同步仍然只能手动 `adb push`。
- **不影响已做的部分**：签名验签、`.znp` 安装、完整性校验全部保留 —— 将来要在它们上面接市场，是**加一层**而不是重做。
- **什么时候会疼**：插件数超过 10 个，或开始给第二个人用。真到那一天，先做的应该是**信任根发放**，不是市场 UI。
