## 1 需求原文（判据，逐条摘）

### §6.1 标签

- 标签由 AI 自动打；新标签直接创建
- 标签默认不在笔记列表中显示，**打开笔记后显示**
- **点击标签后跳转到「所有带这个标签的笔记」列表**
- 该列表可以包含私密笔记，但私密笔记只显示标题

### §7 计划与打卡

- §7.1：打卡按钮 / 提醒设置 / 打卡日历 / 频率设置四块
- §7.2 频率：每天 · 每周固定星期几 · 每月固定日期 · 每隔 N 天；**一天多个提醒**；点通知打开对应计划笔记
- §7.3 打卡：一天可多次、上限用户自定；一天内至少一次 = 当天完成；**连续天数按「应打卡日」算**（非打卡日跳过不中断）；
  同时展示连续 / 累计；日历显示当天是否完成与次数；可手动补打卡，**只能改最近 7 天**

### §11 历史版本

- **每次关闭笔记时，若本次有修改才生成**一个版本；没修改不生成
- 分层精简：最近 7 天保留每次 · 8–30 天每天留最后一个 · 30 天以上每周一个 · 超过 1 年每月一个
- 支持回滚
- 支持差异对比：任选两个版本，也可以选当前版本；增删改高亮

| 通知 | `host.notify(msg, level)` | `contract.ts:553` |

### 2.2 四条硬约束（方案必须绕开）

1. **没有独立侧栏**：`sidebar` 与 `main` 一样**渲染在主区**（`contract.ts:393-400` 的原话）⇒ 面板一开就顶掉编辑器。
   要"同屏"只能用 `editor-topbar` / `editor-toolbar`（很窄），或 `view.openWindow`（桌面，Android 未实测）。
2. **`ViewCtx` 只有 `{ pluginId, state }`**（`contract.ts:384`）—— 面板拿不到"当前打开哪篇"，必须自己 `doc.active()`。
3. **没有定时器原语**：`host.notify` 是即时通知。要做提醒只能插件自己 `setInterval` ⇒ **App 不在就不提醒**。
4. **`core.panel.<id>` 命令不能传参**：内核只做 `setMainView(p.id)`（`src/App.tsx:1926-1933`）⇒ 插件要用
   `store.set('xxx.target', …)` → `command.execute('core.panel.xxx')` → 面板渲染时读 store 的方式传上下文。

## 3 同类产品怎么做

| 项 | 参考 | 关键做法 | 来源 |
|---|---|---|---|
| 历史版本 | **VS Code Local History**（1.66 首发） | 每次保存加一条 entry、**存完整内容**；可对比 / 恢复 / 删除；默认 **50 条/篇**、单文件上限 **256 KB**、**10 秒合并窗口**（连续改动并进上一条） | [VS Code 1.66 发布说明](https://code.visualstudio.com/updates/v1_66)（已读正文） |
| 分层保留 | 本项目需求 §11 | 7 天每次 → 8–30 天每天一条 → 30 天以上每周 → 1 年每月 | `docs/requirements/current.md` §11 |
| 标签面板 | Obsidian Tag pane | 全库标签列表（可按名 / 按频次排序）、点击筛选 | [Obsidian Tags](https://obsidian.md/zh/help/tags)（页面为 SPA，**本次未取到正文**，只确认功能存在） |
| 反向链接 | Obsidian Backlinks | "Linked mentions" 列表 + 每条带上下文片段，可折叠、可展开搜索 | [Obsidian 反向链接](https://obsidian.md/zh/help/plugins/backlinks)（同上，未取到正文） |
| 提醒 | Obsidian Reminder（第三方） | 日期/时间写在笔记里或弹窗设置，到点弹系统通知 | [Reminder-Toast](https://github.com/kebbrokk/reminder-toast)（仓库 README） |

**两条结论**：

- VS Code 的「保存即一条 + 合并窗口 + 条数上限」证明**高频快照是可行的**；但它 50 条/篇对 Markdown 笔记偏多，
  本项目按需求 §11 的分层规则做，存储量更低。
- 反向链接的本质是**反向索引**（谁引用了我）。本项目没有持久化索引，只能按需扫 —— 所以**必须限制规模**
  （见 §4.2 的成本估算）。

## 4 方案

### 4.0 探针：`[[ ]]` 的点击到底归谁（0.5 h，先做）

`examples/editor-marks/index.js` 自己的注释（第 66–69 行）说：

> atomic 编辑器**自己认识 `[[x]]`** 并用 replace/widget 类装饰渲染它（黄底 + 外链图标）；CM6 里那类装饰
> **优先级高于 mark 装饰**，所以叠加不上去、点击也轮不到我们。

也就是说：**`editor.addMark` 注册的 `wikilink` 规则很可能从来没被点中过**。这决定双链能不能按"点链接跳转"实现。

**探针步骤**（不写产品代码）：

1. 把 `examples/editor-marks/` 拷进 `<应用数据目录>/.zn/plugins/`，插件页「重新扫描」
2. 打开一篇写着 `[[另一篇]]` 的笔记
3. 用 CDP 真实点击那个链接，看是否出现 `editor-marks.open-ref` 的 notify

**三种结果与对应方案**：

| 结果 | 含义 | 双链怎么做 |
|---|---|---|
| A. 弹了 notify | 点击能到插件 | 直接做（最省事） |
| B. 没弹、但 atomic 自己跳转/打开 | atomic 接管了点击 | 不重复实现；只在 `#标签` 上做跳转，`[[ ]]` 保持 atomic 行为（若它已能跳） |
| C. 完全无响应 | 谁都接不住 | 走键盘路：命令 `backlinks.open-at-cursor`（读 `doc.active()` + `selection()` 解析光标处的 `[[ ]]`）+ 快捷键；`addMark` 只负责着色 |

> ⚠️ 不许"猜"——探针结果要写进卡面再开工。若结果是 C，需求 §2.2 的"点击跳转"要退化成"快捷键跳转"，
> 这属于**对需求的偏离**，必须先问用户。

#### ✅ 已跑：2026-10-23（rev173.94）→ **结果 B**

环境：桌面 dev（CDP 9222）· 测试库 `_tmp-vault-tb` · 把 `examples/editor-marks` 拷进全局插件目录 ·
新建 `双链验收.md`（含 `[[标签验收-周报]]` 与 `#工作`）· 探完已删插件（硬约束 8）。

| 点击位置 | 读数 | 归谁 |
|---|---|---|
| `[[…]]` 的**链接文字**（`.cm-atomic-link`） | 插件 `open-ref` **未被调用**（审计计数不变）· 目标笔记打开、标签条 +1 | **内核**（`MarkdownEditor.tsx:505-520` 的 document 捕获监听 → `useDocSession.openWikiLink`） |
| `[[…]]` 的 **`[` 方括号**（mark 区、链接文字外） | 插件 `open-ref` **被调用**，但 `payload.text = "[标签验收-周报]"`（**单方括号** —— atomic 把 `[[` / `]]` 拆成 widget，点击提取只含单个 `[` `]`）⇒ 示例的解析必然失配 | 插件，但 payload 不可靠 |
| `#工作` | `editor-marks.goto-tag` 被调用（审计 +1） | **插件**（与本文原判断一致） |
| 删掉插件后点链接文字 | 仍能打开目标笔记 | 再次证明正向跳转**不依赖插件** |

DOM 证据：atomic 把 `[[x]]` 渲染成 `.cm-atomic-link`（黄底 + 外链图标），插件的 `.zn-mark-link`
只能**包在外围**；截图 `_shots/a0-probe-wikilink.png`（本地证据，不入库）。

**对 A2 双链的影响（写死，别再猜）**：

1. **正向「点 `[[ ]]` 跳转」不用做** —— 内核 2026-10-18（P2-2）已实现，且删插件后仍可用。
   需求 §2.2 的"点击跳转"**没有偏离**，本文 §5 第 5 条（探针 C 要先停下问）不触发。
2. A2 的正经内容是**反向链接**（谁引用了我）；"未命中提示"内核也已做（`openWikiLink` 的 toast）。
3. 若将来要让插件在 `[[ ]]` 上做别的交互（悬停预览、右键进反链）：**不要用 `payload.text`**
   （单方括号陷阱），用 `payload.from` 偏移 + `doc.active().content` 自己解析。
4. 插件的 `addMark` 对 `[[ ]]` 只剩**着色价值**（与 atomic 渲染叠加，不抢点击）。

### 4.1 标签面板 `tag-panel`（4 h）

> ✅ **已实现：2026-10-23（rev173.93）** —— `examples/tag-panel/`（主区面板，全库标签浏览）。
> ✅ **rev173.96 补上用户 22:57 要的那条交互**：笔记里点**正文 `#标签`** → `modal` 浮层 →
> 点一篇在**独立窗口**打开（本节原来只写了主区面板那一半）。见 `HANDOFF.md` rev173.96。

**需求对照**：§6.1「点击标签 → 所有带这个标签的笔记列表」；标签默认不在列表显示（本条属编辑器行为，不在本卡）。

**数据源**：`index.tags()` 拿 `{tag, count}[]`；选中后 `index.query('', { tag })` 拿 `SearchHit[]`。

**UI 形态**：`location: 'main'`（接受顶掉编辑器；不做侧栏，理由见 §2.2 第 1 条）。

```
stack
├─ row: text('标签') + badge(总数) + button('重建索引')
├─ input(bind='filter', placeholder='筛选标签…')
├─ list  ← 标签行：[badge(篇数)] link(点击 → 选中)
└─ 选中后：
   ├─ divider
   └─ list  ← 该标签下的笔记：[link(标题)] text(token 摘要)
```

**状态**：`ctx.state.selectedTag` / `ctx.state.filter`，用 `view.setState` 存 —— 切换面板回来还在。

**刷新**：`index.tags()` 结果缓存 30 s；监听 `note:saved` / `note:deleted` / `index:rebuilt` 置脏。

**入口**：`core.panel.tag-panel.board`（内核自动注册）+ 命令 `tag-panel.open`（命令面板可搜）。

**边界**：

- 索引必须先 `rebuild()` 过，否则 `tags()` 是空的（`tag-demo` 的注释就写了这点）⇒ 面板首次打开时若为空，自动 rebuild 一次并显示进度
- 私密笔记"只显示标题"属 B 档加密，本卡不做

**成本**：4 h（含单测：`tags()` 排序 / 筛选 / 空态）。

### 4.2 双链 / 反向链接 `backlinks`（1 天，依赖探针结果）

> ✅ **已实现：2026-10-23（rev173.95）** —— `examples/backlinks/`，与下面的方案一致，差异见段末。
>
> **正向（`[[ ]]` → 打开笔记）**：按 §4.0 结果落地。

**反向（谁引用了我）**：

- 算法：对当前笔记标题 `T`，遍历全库 `.md`，找 `[[T]]` / `[[T|显示名]]`
- 成本：`fs.listNotes()` + 每篇 `fs.readText` = O(N) 次读盘。**实测库 4 篇 → 忽略不计**；
  上千篇时会明显卡（每次开面板都扫）。
- 折中（第一版就用）：**只扫「最近 30 天修改过」的笔记** + 缓存结果到 `store`（键 = 笔记 path + mtime）。
  第二版若要全库，再考虑让内核加"反链索引"（那要改契约，另议）。

**UI 形态**：`location: 'modal'`（不顶掉编辑器，点了才出现），渲染：

```
stack
├─ row: text('反向链接 · ' + target) + badge(条数)
├─ list  ← 每行：link(来源标题) + text(匹配行上下文)
└─ 空态：text('还没有笔记引用它')
```

**传参**：`store.set('backlinks.target', title)` → `command.execute('core.panel.backlinks.show')`。

**入口**：

- 编辑器里右键/命令 `backlinks.show-for-current`（`doc.active()` 取标题）
- 若探针结果允许点击：`[[ ]]` 点击 → 先开来源（可选），再开反链面板

**风险**：

- `index.query('[[T]]')` 会**切词**（空格/标点），`[[` 可能被丢掉 ⇒ **不要依赖索引做反链**，用 `fs` 扫
- 标题重名（两篇都叫「周报」）⇒ 第一版按标题匹配并在 UI 标"可能有歧义"

**成本**：1 天（含探针落地、单测用假 fs）。

**✅ 实现与方案的三处差异（rev173.95）**：

1. **传参不用 `store`**：面板 `render` 读插件闭包里的视图数据（`modal` 面板不会开成独立窗口，
   没有"新 webview 重新加载插件"的问题）。少一次 `store` 读写。
2. **目标名同时试标题与文件名**：`[[标签验收-周报]]`（文件名）与 `[[本周进展]]`（标题）都算命中 ——
   实测两种写法在大纲/日记类笔记里都会出现。
3. **缓存键是 path + mtime，缓存内容是该篇抽出的全部引用**（不是按 target 缓存）——
   换目标不用重扫。文件名扫 <3 次 vs 每篇读盘 1 次，量级差别明显。
   另外顺手修了内核一处：`core.panel.<id>` 对 `location:'modal'` 的面板不再进标签条
   （否则关掉弹窗后留一个空壳标签，点它又弹一次）。

**没做的**：在来源笔记里定位到命中行（只展示上下文行）；`[[名字|显示名]]` 的"显示名"不参与匹配（只认目标）。

### 4.3 历史版本 `history`（1.5 天）

> ✅ **已实现：2026-10-24（rev173.99）** —— `examples/history/`。与下面方案的四处差异：
> ① 目录名用 **`hash32(path)`** 而不是 URL 编码（Windows 文件名不允许 `/`、`%` 太长）；
> ② **切换笔记不发 `close`**（`openNote` 直接换文档）⇒ 补 `doc.on('open')` 用 `change` 缓存的正文存上一篇；
> ③ `save` 兜底**首次不触发**（否则与 close 各存一份内容相同的快照 —— 实测踩到）；
> ④ 回滚**不用回收站**：先把当前存一份再写回（当前内容已经进历史，删盘反而更容易丢）。
> 另外内核补了两条 API：`fs.listFiles`（读私有目录清单）、`fs.purgePrivate`（只允许 `.zn/` 下真删）。

**触发**（照需求，不照 VS Code）：`doc.on('change')` 置 dirty → `doc.on('close')` 且 dirty ⇒ 存一份快照。
另外补一条兜底：`doc.on('save')` 时若距上次快照 > 10 分钟也存（防止"一直不关"导致没版本）。

**存储**：`<库>/.zn/history/<path 的 URL 编码>/<时间戳>.md`（`.zn` 不进索引、不进文件树）。

**分层精简**（需求 §11）：存完立刻 `prune()`：

| 年龄 | 保留 |
|---|---|
| ≤ 7 天 | 全部 |
| 8–30 天 | 每天最后一版 |
| 31 天–1 年 | 每周最后一版 |
| > 1 年 | 每月最后一版 |

**UI**：`modal` 面板 —— 时间线列表（时间 + 大小 + 与上一版的差异行数），点一条 = 预览/对比/回滚。

**回滚**：`fs.readText(当前)` → `fs.delete(当前)`（进回收站，可撤销）→ `fs.writeText(历史内容)`。

**差异对比**：行级 LCS（项目里 `src/lib/merge3.ts` 有行级合并，可复用切行逻辑但 diff 要新写）。
渲染用 `{ type: 'html' }` 输出 `<div class="zn-diff-add/…">`，**必须做 HTML 转义**（笔记正文来自用户输入）。

**边界**：

- 只对 `.md` 做；附件不进历史（`fs` 无二进制读）
- 关闭窗口时 `doc.on('close')` 会触发吗？—— `useDocIO` 有"关窗前落盘"，但事件顺序要实测（**列入验收**）
- 首版**不做**"任选两个历史版本对比"，只做「历史 vs 当前」（需求允许选当前版本）

**成本**：1.5 天（快照 4 h + 分层 2 h + diff 3 h + UI 3 h）。

### 4.4 提醒打卡 `habit`（2.5 天）

**数据放哪（要拍板，见 §5）**：推荐 `store`（结构化、不污染笔记），与 `accounting` 同一种做法。

计划模型：

```js
{ id, title, notePath, freq: 'daily'|'weekly'|'monthly'|'everyN',
  days: [1,3,5] /* weekly */, dayOfMonth: 15, n: 3, startDate: '2026-10-21',
  times: ['09:00','21:00'], targetPerDay: 1 }
```

打卡记录：`{ [planId]: { '2026-10-21': [ '08:12', '21:30' ] } }`（一天多次）。

**提醒**：`setInterval(30_000)` 比对 `times` 与当前 `HH:mm`；同一分钟用 `store` 记 `lastFired` 防重复；
到点 `host.notify`（桌面 toast、手机通知）。

**连续天数**（需求 §7.3 的关键）：从今天往回走，**只统计"应打卡日"**，遇到非打卡日跳过；某应打卡日无记录 ⇒ 连续中断。

**UI**：`main` 面板 —— 计划列表（每行：标题 + 今日打卡次数 + `button('打卡')`）+ 月历（`table` 7 列）。

**补打卡**：点日历某天 → 只允许最近 7 天（需求原话），超过就置灰。

**边界**：

- **App 不在 = 不提醒**（没有定时器原语，也没有 Android 前台服务）。这条必须写进插件说明，不能让用户以为是闹钟
- 手机后台冻结时 `setInterval` 也会停 ⇒ 只能"下次打开补提醒或不提醒"

**成本**：2.5 天（模型 + 面板 1 d、打卡与日历 1 d、连续算法 + 7 天补打卡 0.5 d）。
