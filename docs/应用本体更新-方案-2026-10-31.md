## 1. 一句话

桌面用官方 `tauri-plugin-updater`（签名校验 + 自动替换安装）；Android 自己下 APK 再交给
系统安装器。清单是仓库里的两个静态 JSON，客户端按镜像顺序取。

## 2. 为什么两端不能同一条路

官方 updater 的支持表（README，2026-10-31 核对 2.14.1）：

| 平台 | 支持 |
|---|---|
| Linux / Windows / macOS | ✓ |
| Android / iOS | **✗** |

桌面能「下载 → 校验 → 调安装器 → 自动重启」，是因为 Windows 的 NSIS / MSI 安装器支持
静默参数。Android 没有等价物：APK 必须由系统 PackageInstaller 安装（用户还要单独授权
「安装未知应用」），没有任何 API 能让应用自己替换自己。

所以：

* **桌面** = 官方插件（签名校验不可关闭，`bundle.createUpdaterArtifacts: true` 产出 `.sig`）；
* **Android** = `updates.rs` 里自己下（`net::download_client`，不设总超时，因为 APK 几十 MB）
  → sha256 核对 → `tauri-plugin-apk-install` 起 `ACTION_VIEW` + FileProvider。

## 3. 清单与镜像

| 文件 | 消费方 | 格式 |
|---|---|---|
| `update/latest.json` | 桌面 updater | Tauri static JSON（`platforms.windows-x86_64.{url,signature}`） |
| `update/android.json` | Android | `apk.{url,sha256,size}` |

**为什么自己挑镜像**：`endpoints` 的语义是「返回非 2xx 才试下一个」——
2026-10-27 真机实测 Android 上 `raw.githubusercontent.com` 是 **TLS 阶段被 RST**（6/6 失败），
属于网络错误，updater 会直接失败、不会换镜像。所以在 `updates.rs` 里按顺序 try：

1. `raw` —— 桌面本机 200、最实时
2. `ghproxy` —— 国内手机可达、发布即时
3. `jsDelivr gcore` / `testingcf` —— 手机可达，但 `@main` 有分钟级缓存（刚发版可能读到旧清单）

选中之后，桌面把 updater 的 endpoint 指到那一个（`install_desktop_update(mirrorId)`），
Android 用它拼下载地址并附带 ghproxy 变体。

## 4. 安全边界

* **桌面**：minisign 签名。公钥在 `tauri.conf.json` 的 `plugins.updater.pubkey`；
  私钥只在 `~/.tauri/zeronote.key`。**签名校验关不掉**。
  → 私钥丢了 = 老用户永远收不到自动更新。必须离线备份。
* **Android**：整包 sha256（清单里记、下载后逐字节核对，不符就删文件不安装）。
  它只防「下载被截断 / 被镜像篡改」，**不防清单本身被改**（清单在仓库里，等于信任仓库）。
  这条与插件市场同级别（`D-008` 的安全模型：信任仓库 = 信任作者）。
* 桌面安装会退出应用（Windows 安装器限制），前端不要指望 `Ok(())` 之后还能做 UI 收尾。

## 5. 用户可见行为

| 场景 | 行为 |
|---|---|
| 启动 | 24h 节流静默查一次；有新版只弹一句提示，**不下载不安装** |
| 设置 → 关于 → 更新 | 手动检查 / 版本说明 / 进度条 / 下载安装 |
| 桌面点「下载并安装」 | 下载 → 校验 → 安装器接管 → 自动重启 |
| 安卓点「下载安装包」 | 下载到缓存 → 「安装」→ 系统安装器；没授权时给「去授权」按钮 |
| 断网 / 清单 404 | 显示「拉取更新清单失败」+ 重试按钮；启动时静默不打扰 |

开关：`zn-app-update-auto`（默认开）。时间戳：`zn-app-update-last-check`。

## 6. 已知边界（明确没做）

1. **0.9.1 及更早的用户收不到这条通道** —— 0.9.1 的安装包没有 `.sig`，也没有 updater 插件。
   内置更新从**下一个版本**起才生效。老用户需要手动装一次新版。
2. **jsDelivr 缓存延迟**：刚发版后几分钟内，走 jsDelivr 的设备可能还看到旧清单。
   raw / ghproxy 优先，正常情况下无感。
3. **本机 dev 环境测不出「安装」**：`pnpm tauri dev` 的产物不是安装版，updater 会拒绝
   （没有安装目录）。真实验证要装一次 release 版再点检查。
4. **Android 12+ 的「安装未知应用」** 必须用户手动开；我们只能引导，不能代开。
5. **CI 不产出签名产物**：`verify.yml` 只跑测试。发版仍是本机 `scripts/build-release.mjs`
   （它自动带上密钥路径）。要上 GitHub Actions 发布，需要把私钥放进 repo secrets。
