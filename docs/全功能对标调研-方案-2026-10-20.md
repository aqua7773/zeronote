## 2 重点问题

### 2.1 P1：笔记窗口也加载插件（A）

**事实**：`App` 无条件调 `usePluginHost`（`src/App.tsx`）；其中会跑 `ensureBuiltinPlugins`（写盘检查）+ 扫描 + **对没有 `activationEvents` 的插件立即 `apply()`**（`usePluginHost.ts:250-269` 只让声明过的插件走懒激活）。内置 5 个里 4 个无 `activationEvents`、`accounting` 是 `onStartup` ⇒ **每个 `note-*` 窗口都会执行它们的代码**。

**对照**：VS Code 也是**每个窗口一个 extension host**（由 shared process 派生，[PR #133445](https://github.com/microsoft/vscode/pull/133445)；[Extension Host 文档](https://code.visualstudio.com/api/advanced-topics/extension-host) 讲的是 activationEvents 懒激活，不是多窗口共享）。所以「每窗口一份宿主」本身不落后；落后的是「笔记窗口根本不需要插件却照样加载」。

**方案 A（推荐，低成本）**：笔记窗口跳过 `usePluginHost`（加 `noteWindowPath` 判断）。编辑器 / Markdown / 搜索在内核，不依赖插件；插件窗口（`plugin-*`）保持加载。
**成本**：~20 行 + 回归（窗口内渲染、粘贴图片、`[[链接]]`）。
**验收**：拆出窗口后插件列表为空、编辑/保存正常、主窗口插件不受影响。

**方案 B（不推荐现在做）**：宿主搬到 Rust / 独立进程。架构级成本。

### 2.2 P1：窗口位置 / 尺寸不持久化（A，仅桌面）

- 官方 `window-state` 平台支持：Linux/Windows/macOS ✓，**Android/iOS ✗**（[docs.rs](https://docs.rs/crate/tauri-plugin-window-state/2.0.1)）。本项目含安卓 ⇒ 必须 `cfg` 分流，并确认安卓构建不受影响。
- `note-*` 窗口恢复策略三选一：同一位置 / 一律居中 / 不恢复——先定再写。
- 成本：~30 分钟（含权限与安卓回归）。

### 2.3 P2：占用账本在主窗口内存（A）

`noteWindowsRef`（`App.tsx:543`）在主窗口 JS 内存；主窗口 reload（dev HMR）就丢，已开的独立窗口「失联」，同一篇能再开一份。
**方案**：账本落 localStorage（同 origin 共享）或 Rust `app.manage`；启动时清残留。
**成本**：~1 小时（含互斥守卫改读持久化账本）。

### 2.4 P2：会话恢复（hot exit）缺失（C）

自动保存 800ms、关窗落盘；**进程崩溃 / HMR 全量重载**丢最近一次未落盘输入。
**方案**：localStorage 存 dirty 快照（path + content + 时间，上限 1 篇 / 8 KB），启动时提示恢复/丢弃。
**成本**：~2 小时（含提示 UI 与测试）。

### 2.5 P0：文件监听 emitter 缺失（A · 故障优先）

- `src/kernel/fs.ts:86-101`：`listen('zn://fs-change')` 成功即 `stopPoll()`；但 `src-tauri` 里**没有该事件的 emitter**（`grep 'zn://'` 只命中 `zn:open-file`），`Cargo.lock` 里也没有 `notify` crate。
- 结果：外部改动（别的编辑器改文件、网盘同步）**可能完全不触发**刷新；轮询兜底也被关掉。
- **方案**：二选一 —— ① Rust 侧补文件监听并发 `zn://fs-change`（新增 notify 依赖，`cargo test` 验证）；② 前端改成「先轮询，收到首条真实事件再停」。
- **验收**：外部改文件 → 文件树/索引在 3 秒内更新；关掉事件通道时轮询仍生效。

### 2.6 其它（记录，不排期）

- 大库：文件树 / 卡片流虚拟滚动（@tanstack/react-virtual）——先量再说（性能基线本轮按用户要求暂缓）。
- 窗口居中 / 多显示器：`positioner` 插件，用户抱怨再做。

## 3 明确不建议采纳

| 候选 | 为什么不用 |
|---|---|
| 文件监听换 Tauri fs 插件 | 当前的问题不是「用错库」，是**没有 emitter**；先修 §2.5。修复后再评估是否引入 notify crate |
| 原子写换 `atomic-write-file` | 自研只剩 30 行，已处理 Windows rename 语义与 `.zn-bak` 回退 |
| 搜索换 Tantivy / FTS5 | 千篇级；中文子串查询本来要 trigram/LIKE 兜底；引入索引库 = 新依赖 + 新故障面（`decisions/D-003`） |
| 自动合并换 CRDT | 单机无并发端；三方合并已够，CRDT 会改数据模型 |
| 剪贴板换官方插件 | 不支持富文本/图片粘贴，我们要自己处理 paste 事件 |
| 文件关联换 CLI 插件 | 只解析 7 类扩展名，替换收益为负 |
| 插件宿主搬进程 | 架构级成本；VS Code 也每窗口一个 host（`decisions/D-005`） |
| 做云同步 | 无服务器/账号是定位；冲突语义未定（`decisions/D-002`） |
