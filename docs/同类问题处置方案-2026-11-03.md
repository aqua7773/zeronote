## P1 · 路径跨端双份 + 对拍测试 ✅ 已落地（2026-11-03）

**现状**
- 主程序唯一实现：`src/lib/insert-image.ts#linkCandidates`（笔记目录 → 库根；前导 `/` 只按库根）。
- 插件第二份：`examples/import-export/index.js#refLocations`（同口径重写，注释自称「候选只在这里定义一次」）。
- `tests/import-export.test.ts` 已同时 import 两端，**但没有任何一组「同输入 → 同输出」的对照断言**。
- `docs/共享逻辑.md` 要求「跨端两份必须有同输入同输出的测试」，`signingPayload` 有（`tests/signing-parity.test.ts`），路径候选没有。

**方案**
1. 新建 `tests/path-parity.test.ts`，对拍 `linkCandidates(rel, note)` 与
   `refLocations(target, note, platform, root).map(x => x.rel)`，覆盖矩阵：
   子目录笔记 · 库根笔记 · 前导 `/` · `./` 前缀 · 反斜杠 · `..` 越界 · `<>` 尖括号 · URL · Windows 绝对路径 · Android `/storage/...`
2. 对拍前先跑一次，把**不等**的输入记进文档（预期：`..` 越界、Android 绝对路径会不等）。
3. 不等的分两类处置：
   - 属于「插件需要、主程序不需要」的分支（URL / 库外绝对路径）→ 测试里显式排除并写明理由；
   - 属于**真口径差**（Android 绝对路径）→ 修主程序 `resolveImageAbsPaths`：加与 `isLocalAbsPath` 同级的平台绝对路径前置判断（`/^(?:\/storage|\/sdcard|\/data|\/mnt)\//`）。
4. 两端顺序必须一致；任一侧改了顺序，这条测试先红。

**验收**
- `vitest` 全绿，新增用例 ≥10 组。
- 手工把一端顺序调反，测试必须红（防「测了个寂寞」）。

**不做**：不合并两份实现（插件是独立 JS，不能 import 主程序）；只锁「同输入同输出」。

**追问待核实**：Android 上正文里的 `/storage/...` 图片引用是否真实存在（`pathFromVaultRoot` 明确保留这类路径，`isLocalAbsPath` 也认；渲染侧没有同级判断）。存在 ⇒ 属于现存 bug，P1 第 3 步顺带修。

## P2 · 插件 `select` 受控值不播种 ✅ 已落地（2026-11-03）

**现状**（真人测试 10 #5 的根因）
- 契约的 `select` 显示值取 `ctx.state[bind]`；渲染前不播种 ⇒ 永远显示第一项，真实值在 store 里。
- 三套应对并存：
  - `examples/sync` —— 改按钮组（彻底，但只适用于枚举少且要显示的设置）；
  - `examples/backup/index.js#selectOptions` —— 把「当前档位排第一」（显示对了，值是假的）；
  - `examples/habit/index.js` —— `view.setState(bind, 真实值)` 播种（正确写法）；
  - `examples/ai/index.js` —— `select bind:'ai.provider'` 无播种，已配 Kimi 仍显示 DeepSeek。

**方案**
1. 契约 `docs/内核契约-v0.2.md` 的 `select` 条目补一句硬规则：
   「`bind` 的当前值必须由插件在 render 前 `view.setState` 播种；宿主不替插件猜。」
2. `examples/backup` 改回正序选项 + `setState` 播种，删掉 `selectOptions` 的排序 hack。
3. `examples/ai` 两处 provider select 改为按 `cfg.provider` 播种。
4. 加一条可复用的单测：渲染前不播种 ⇒ 断言「显示的当前值」等于 store 值（以 backup 为样本）。

**验收**
- 改备份间隔 → 重启 → 控件显示上次选的档位。
- AI 向导：已配 Kimi 重进 → select 显示 Kimi。

**不做**：不改内核 `select` 的取值机制（会动所有插件）；sync 的按钮组保持现状（它是显式设置项，按钮组更好）。

## P4 · 浮层拦截白名单 ✅ 已落地（2026-11-03）

**现状**
- `src/lib/swipe.ts` 的 `BLOCKING_OVERLAY_SELECTOR` 只认 4 个 class（图片预览 / 环形菜单 / 命令面板 / 对话框）。
- 注释自己写「新增遮罩时记得把 class 加进来」；全仓 `position: fixed` 18 处。
- 真人测试 3 #2 / #3 就是「看图时左右滑把侧栏拉出来」。

**方案**
1. 判定从「class 白名单」改成「`[data-overlay]` 属性存在即拦截」；现有 4 类加属性，新增层写属性即生效。
2. 过渡期保留原选择器（兼容未迁完的层）。
3. 加测试：往 DOM 插一个 `data-overlay` 元素 ⇒ `hasBlockingOverlay` 为真；插普通 `div` ⇒ 为假。

**验收**：新增任一全屏层（不写 class 白名单）后，看图时左右滑不再动抽屉。
