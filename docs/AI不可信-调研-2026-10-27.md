# AI「说自己做完了」不可信 —— 业界做法调研（2026-10-27）

> 状态：**调研（未拍板）** ｜首版 2026-10-27
> 触发：rev173.209–212 在真模型上抓到三个问题（见 §0），已做的 system 提示 / 历史带步骤只是止血
> 本文回答一件事：**别的项目怎么让 agent 的「完成」变成可验证的事实**，以及 `examples/ai/` 能抄哪几条
> 一手来源：Anthropic 工程博客、Claude Code 文档、OpenAI Agents SDK 文档、OpenHands SDK 文档、aider 文档、
> Cline 仓库 issue、arXiv 论文。URL 随文标注，均于 2026-10-27 抓取

## 0 先把问题说准

rev173.207–212 在**真模型**上暴露的三个症状（本地 mock 全部不报）：

| # | 症状 | 证据 |
|---|---|---|
| 1 | **谎称完成**：回复说「任务建好了 / 已停用」，但没调 `task_create` / `task_update` | 面板 0 个、`store.tasks` 空；rev173.209 一次谎称后模型自己调 `task_list` 更正 |
| 2 | **压缩后失忆**：历史压缩丢了工具步骤，模型只看到自己上轮的结论「0 条」，这轮就答「查过了，和上面一致」 | 强制它调工具也不调；rev173.212 修法是把 `✓/✗ name → 结果` 附进历史 |
| 3 | **编造 id**：引用一个已删除任务的旧 id | rev173.209 观察 |

三个症状的共同点：**模型在用文本叙述事实，而文本不是事实来源**。

---

## 1 一句话共识

所有被调研的方案都落在同一条线上：**「完成」不是模型说的话，是宿主能重放的事实**。
差别只在这条线卡在哪一层 —— 工具层（完成必须是一次调用）、宿主层（输出前校验）、还是上下文层（压缩不丢证据）。

---

## 2 六种具体机制（按「卡在哪一层」排）

### 2.1 让「完成」本身变成一次工具调用（Cline）

Cline 的 system prompt 规定：**每轮回复必须包含工具调用**，否则宿主直接回
`[ERROR] You did not use a tool in your previous response! Please retry with a tool use.`
（[cline/cline issue #735](https://github.com/cline/cline/issues/735)）。任务结束时必须调专用的
`attempt_completion` 工具，宿主据此判定这一轮结束。

- 好处：**「完成」从自由文本变成结构化事件**，宿主与 UI 都能看到
- 代价：模型会被迫为了「有话要说」而调用工具（Cline 用户抱怨过 `attempt_completion` 在 YOLO 模式下失效，
  [issue #7226](https://github.com/cline/cline/issues/7226)）—— 强制工具调用本身会制造噪声

### 2.2 终止要「携带证据」（学术：Evidence-Carrying Termination）

arXiv 2608.23623《[When May an Agent Stop? Evidence-Carrying Termination for Tool-Using LLMs](https://arxiv.org/abs/2608.23623)》
把问题形式化：agent 只有在**一份类型化证书**把每个答案声明绑定到**轨迹里有效、范围内的证据**，
并且**确定性重放能重建该值时**，才允许返回 `COMPLETE`。

实测数字（作者自报，48 合成任务 × 6 类工具、8 种故障）：

| 指标 | ECT | 被检查的 termination-critic |
|---|---|---|
| 不安全完成 | **0/288** | 252/288（87.5%！） |
| 无支撑的提前终止（held-out） | **0/66** | 40/66 |
| 有支撑的完成 | 97/132 | 92/132 |

结论直白：**光让模型「自己检查」没用（252/288 仍然乱报）；必须是外部可重放的证据**。
论文也自我限定：证明的是「记录轨迹里的支撑」，不是外部真值。

### 2.3 输出 guardrail：先不给用户看（OpenAI Agents SDK）

OpenAI Agents SDK 把校验分三层（[Guardrails 文档](https://openai.github.io/openai-agents-python/guardrails/)）：

- **input guardrail**：跑在最前面的 agent 上
- **output guardrail**：跑在**最终输出**上，tripwire 触发就**拒绝这份候选输出**（而不是发出去再补救）
- **tool guardrail**：每次 tool 调用前后都能拦/改

关键设计是「tripwire（绊线）」：不合格的输出**不会到达用户**，runner 只持久化已完成的工具项。

### 2.4 环境给 ground truth，模型自己不能是裁判（Anthropic）

《[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)》原文：

> During execution, it's crucial for the agents to gain **"ground truth" from the environment at each step**
> (such as tool call results or code execution) to assess its progress.

同一篇文章给的 **evaluator-optimizer** 模式：一个 LLM 生成，另一个 LLM 按明确标准评估并反馈，循环到过线 ——
即「生成者不给自己打分」。附录还讲 **poka-yoke（防呆）**：把工具参数设计成「想错都难错」（SWE-bench 上把相对路径
改成绝对路径后失误消失）。

### 2.5 压缩时别把证据一起压缩掉（OpenHands / Anthropic）

- **OpenHands**：`LLMSummarizingCondenser` 的构造参数就是 `keep_first` + `max_size`，
  即「前 N 个事件（system、首个用户消息）永远保留 + 最近消息原样 + 中间交给 LLM 摘要」
  （[Context Condenser 文档](https://docs.openhands.dev/sdk/guides/context-condenser.md)）。
  压缩按**事件**做，而 `tool_use` 与 `tool_result` 是成对事件 —— 所以他们的 issue 里专门盯
  「condensation 后留下孤儿 tool_result / tool_use」（[issue #4498](https://github.com/OpenHands/software-agent-sdk/issues/4498)）。
- **Anthropic**《[Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)》：
  Claude Code 的 compaction 保留「架构决策、未解的 bug、实现细节」，丢弃冗余工具输出，**并保留最近访问的 5 个文件**；
  同时警告「过度压缩会丢掉当时看不出重要、后来才关键的上下文」。最轻的压缩手段是 **tool result clearing**（只清结果、留调用）。
  另给一招 **structured note-taking**：把状态写进上下文之外（`NOTES.md` / todo 列表），跨压缩活着。

### 2.6 自动验证：不信「改好了」，看测试（aider）

aider 的 `--auto-lint` / `--auto-test`：每次 AI 编辑后自动跑 lint / test，
非零退出码就把输出回灌给模型让它修（[Linting and testing](https://aider.chat/docs/usage/lint-test.html)）。
即 **「完成」的判据是外部命令的退出码**，不是模型的自我评价。

## 3 对照表：三个症状 × 已有机制 × ZeroNote 现状

| 症状 | 业界机制 | `examples/ai/` 现状 |
|---|---|---|
| 谎称完成 | 完成=工具调用（Cline）· 输出 guardrail（OpenAI）· 自动测试（aider）· ECT 证书 | ❌ 只有 system 提示「说完成前必须真调过工具」；判据仍靠模型自觉 |
| 压缩失忆 | 事件级压缩 + keep_first（OpenHands）· 保留最近文件（Anthropic）· note-taking | ⚠️ rev173.212 已把 `✓/✗ name → 结果` 附进历史；但那仍是**模型自己写的摘要**，不是结构化 trace |
| 编造 id | 语义化 ID（Anthropic 工具指南）· ECT 的确定性重放 | ❌ 无校验；`task_list` 空也能说「建好了」 |
| （好的一面）不可逆操作 | OpenAI human-in-the-loop / tripwire | ✅ **已有**：`note_write` / `note_move` / `note_trash` 只出提案，用户点采用才落盘 |

一句话：**ZeroNote 已经做对了「不可逆操作要人确认」，缺的是「完成声明要证据」**。

## 4 给 `examples/ai/` 的候选（成本 / 收益 / 风险）

| # | 方案 | 做法 | 成本 | 收益 | 风险 |
|---|---|---|---|---|---|
| **A** | 完成即工具 | 新增 `report` 工具，模型声称完成时必须调用，参数列出本轮 `tool` + 要点；宿主校验这些工具本轮真的调过 | 小（1 工具 + 校验） | 中 —— 把完成变成结构化事件 | 模型仍可能不调；强制每轮都调会产生噪声（Cline 教训） |
| **B** | **宿主注入事实** | 工具循环结束后，宿主把本轮**真实发生**的操作作为一条 `tool`/`system` 消息追加：`本轮工具：task_create ✓ → id=…`；这段不受模型控制 | **小**（几十行） | **高** —— 模型写回复时看到的是事实而非自己的记忆 | 增加一点 token；要防止把大结果全塞进去 |
| **C** | 输出 guardrail | 回复落盘前用规则检查：含「已创建/已删除/已移动」但本轮无对应工具 ⇒ 追加提示或改写 | 中 | 高 | 规则会误判（模型在解释、引用历史时） |
| **D** | 压缩保结构 | 工具步骤永不进摘要：最近 N 轮完整保留，更早压成一行的「事件表」（`✓ task_create id=…`） | 小 | 中 —— 补 212 的粗糙实现 | 无 |
| **E** | id 校验 | 模型引用 `task-xxx` / 路径时宿主校验存在性，不存在就回一条 tool 消息「该 id 不存在」 | 中 | 中 | 要定义 id 形态（现在任务 id 是什么格式需先查） |
| **F** | **UI 事实条** | 面板里每条回复下方挂一行「本轮实际动作：✓ task_create · ✗ note_write（未授权）」，数据来自 trace 而非模型文本 | 小 | 高（人一眼看穿） | 无 |

**推荐组合：B + F + D**（都小、叠加起来覆盖三个症状），A 作为下一步可选（真正要「强制完成信号」时再加）。
C/E 留到有真实误报样本再说。

---

## 5 结论

1. **别指望提示词**：ECT 的 252/288 说明「让模型自己检查」基本无效；rev173.209 的对照也证明 system 措辞只能改善、不能保证。
2. **最便宜的一招是「宿主注入事实」**（B）：模型再编，也只能编它看到的东西。
3. **第二便宜的是「把事实摆在人眼前」**（F）：rev173.207 的教训「看面板数字与 store，别信回复原话」应该做成 UI，而不是留在交接卡里。
4. 真正要与 Cline / ECT 对齐，才需要 A（完成即工具）或 C（输出 guardrail）—— 那是「产品要对外承诺」时才付的成本。
