## 0 一句话

一个「管家」型 AI 插件：**一个对话框 + 一套工具 + 一个任务系统**。
功能不预置 —— 你在对话里描述想干什么，它落成任务；任务按触发条件自动跑（笔记保存 / 定时 / 手动）。分类只是任务的一个例子。

## 3 产品形态

### 3.1 三个部分

1. **对话面板**（主区标签）：输入 → 模型 → 调工具 → 结果；流式显示；步骤流；历史存插件数据
2. **任务面板**（独立面板）：任务列表 / 触发方式 / 启用开关 / 最近 10 次运行 / 立即跑一次 / 删除
3. **工具集**：插件提供给模型的全部能力（见 §3.3）

### 3.2 任务模型

| 项 | 定义 |
|---|---|
| 触发 | `note:saved`（笔记保存时）/ 定时（桌面可靠，Android 打开时补做）/ 手动 |
| 指令 | 用户自然语言描述，创建时 AI 可重述一遍让你确认 |
| 执行 | AI 自选模式：固定步骤（便宜稳定）或现场判断（灵活，上限 4 步） |
| 存储 | 插件 `store`：任务定义 + 最近 10 次运行记录 |
| 失败 | 记日志 + 任务上标红；不阻塞笔记保存 |

### 3.3 工具集（第一版：只碰笔记）

| 工具 | 作用 |
|---|---|
| `folder.list` / `folder.create` | 目录树、建文件夹 |
| `note.list` / `note.read` | 列/读笔记 |
| `note.create` / `note.write` | 新建、改写（改已有内容必须走预览确认） |
| `note.move` / `note.trash` | 移动、删除（不可逆 ⇒ 确认） |
| `tag.add` / `tag.remove` / `tag.list` | 标签 |
| `search.run` | 全文 / 标签搜索（复用内核索引） |
| `task.create` / `task.update` / `task.delete` / `task.list` / `task.run` | 任务管理 |

> ⚠️ **实现里的工具名用下划线**（rev173.205）：DeepSeek 要求 function name 匹配 `^[a-zA-Z0-9_-]+$`，
> 点号会被拒（`Invalid 'tools[5].function.name'`）⇒ 本表写的 `note.create` 落地为 `note_create`，其余同理。
>
> 第二版再加 `plugin.exec`（白名单调 `habit` 等）。工具层是唯一「写」的入口，对话与任务共用。
> ✅ **已落地（rev173.208）**：工具名 `plugin_exec`（`command` + `args`）；白名单在设置页逐条勾选、落 `store.allowedCommands`；
> 内核命令与 `ai.*` 永不开放；**自动任务同样受白名单限制**（用户 2026-10-27 拍板）。

1. **§5 计划识别写法作废**：原文「自动转为计划笔记，随后弹窗让用户填写频率、提醒、每日打卡次数上限」→ 改为对话追问；「提醒」字段 2026-10-23 已裁决不做（`docs/ROADMAP.md` §5）

## 5 技术前提（2026-10-27 核实，行号写作时）

| 事实 | 依据 |
|---|---|
| 插件可 fetch 外部 HTTPS 模型 API | `src-tauri/tauri.conf.json` CSP `connect-src` 含 `https: http:` |
| 插件能调任意命令（含其它插件） | `src/kernel/plugin-host.ts:371-393` —— `scopedCommand` 只包 `register`/`bind`，`execute` 透传 |
| 插件写盘不会触发自己的 `note:saved` | `src/kernel/contract.ts:100-105` —— 插件来源写盘发 `note:changed`（`origin:'plugin'`） |

| 主区面板 / 独立窗口面板可用 | `registerPanel({ location })` + `openWindow` |
| 定时器可用但不保证 | `setInterval` 在插件里可用；Android 无前台服务 ⇒ 定时只在桌面可靠 |
| 新建笔记默认落库根 | `src/App.tsx:1658-1677` —— `新笔记-HH-MM-SS.md`，无子目录 |
| 灵感流已搁置 | `src/builtin-plugins.ts:20` —— rev173.35（2026-10-19）不预装 |
| 第一版预期零内核改动 | 面板 / 事件 / 命令 / `fs` / `store` / 凭据管理器都在现有 API 内 |

## 6 第一版范围

**做**：
1. 对话面板（主区标签）：多轮、流式、步骤流、滑动窗口 20 条
2. 工具集（§3.3：笔记 / 目录 / 标签 / 搜索 / 任务管理）
3. 任务系统：事件 / 定时 / 手动三种触发；独立任务面板；最近 10 次运行记录
4. 模型接入：3–4 家预设 + 自定义兼容端点；Key 进 keyring；不设默认，首次选
5. 首次配置三步向导；不预置任务

**不做**：调其它插件（第二版）、复杂 UI（可视化任务编辑器）、系统级操作。

## 7 方案阶段要定的（不再是需求问题，是实现设计）

1. 定时任务的语法（自然语言解析成 cron？还是只支持「每天 HH:MM / 每周几」几种）
2. 「固定步骤」模式的任务定义格式
3. 工具参数 schema 怎么写（模型要知道每个工具收什么参数）
4. 请求超时 / 重试 / 限流策略
5. 上下文裁剪与 token 计费统计（Q37 的 token 数从哪来）
6. 对话与任务共用的模型调用层放哪（插件内模块）
7. 分类准确率怎么验收（抽样多少篇、什么算对）
