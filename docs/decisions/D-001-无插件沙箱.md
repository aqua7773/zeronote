# D-001 不引入插件沙箱

> 状态：**accepted** ｜日期：2026-10-13 ｜重议条件：要分发第三方插件 / 上架应用商店 / 插件目录不再受信任

## 背景

插件与宿主在同一个 JS 上下文（Blob 动态 import），`capability` 在 2026-10-13 rev48 起只是**自述**，不是门（契约 §4）。`while(true)` 能卡死整个应用，靠原生看门狗兜底。

## 决定

不做进程/Worker/WASM 沙箱，接受「本机可信代码」模型。

## 理由（一手来源）

- QuickJS/Worker 化要把 10 个原语全部改成 RPC 面，并处理中断语义（NoteGen 踩过「异步中断变 rejected promise」），成本数天级 —— `docs/插件能力盘点-2026-10-12.md` G1。
- 用户定位是自用，不装第三方来源的插件；为不存在的攻击面付架构成本不划算。
- 现有缓解：CSP 白名单拦「随手联网」、`net`/`proc` 授权记录、写盘走原子写 + 回收站。

## 代价与边界

插件能读任意文件、发网络请求（ESM import 受 CSP 约束，`invoke` 不受约束）；卡死靠看门狗闪退 + 下次启动禁用，不是隔离。
