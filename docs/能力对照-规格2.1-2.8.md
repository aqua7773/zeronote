| 要求 | 判定 | 靠什么 / 缺什么 |
|---|---|---|
| PDF | ✅ | jsPDF（CDN）→ `host.saveFile` |
| HTML | ✅ | marked（CDN）→ `saveFile` |

### ⚠️ 网络出口的真实约束（2026-10-12 更正 + 用户裁决）

**结论**：插件联网**第一道会撞上的墙是 CORS，不是 CSP**；而 CSP 已按用户裁决放宽。

| 关卡 | 现状 | 对插件作者意味着什么 |
|---|---|---|
| **CORS** | 由**目标服务**决定；WebView 的 origin 是 `http://tauri.localhost` | 要连的服务**必须**回 `Access-Control-Allow-Origin` —— WebDAV 服务器、自建 AI 代理通常要手动配这条 ⚠️ **最常见的拦路虎** |
| **CSP `connect-src`** | 用户 2026-10-12 裁决「放宽」⇒ 现为 `'self' ipc: http://ipc.localhost https: http: ws: wss:` | 任意域名都能连；出口不再逐域名管，交回给 ⑧ 的逐插件授权 + 知情承诺 |
| **`net` 授权** | ~~⑧ 的 `.zn/permissions.json`：未授权**拒载**~~ —— **2026-10-13 已整体下线**（rev66） | 声明了 `net` 的插件**不再需要任何人点头**就能联网（自述而已） |

**实测（`examples/net-demo/` 三个按钮，真机）**：

| 靶子 | 结果 |
|---|---|
| ① `esm.sh`（有 CORS） | HTTP 200 |
| ② `www.baidu.com`（**无** CORS 头） | 被拦；logcat 明写 `blocked by CORS policy` |
| ③ `registry.npmmirror.com`（有 CORS、**原本不在白名单**） | **HTTP 200（7184 字节）** ⇒ 放宽生效 |

⚠️ **踩坑记录**：②与③失败时插件侧报的都是同一句 `TypeError: Failed to fetch`，**分不出 CORS 与 CSP**，
必须看 `adb logcat`（CORS → `blocked by CORS policy`；CSP → `Refused to connect …`）。
本文件初版曾把 CORS 失败误写成 CSP 拦截，2026-10-12 已更正。
