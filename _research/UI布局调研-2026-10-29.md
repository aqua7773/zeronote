## 0 结论（1 分钟版）

**现状一句话**：外壳是「记事本」（标题栏 + 文件树 + 编辑器 + 状态栏），功能是「插件驱动」——但插件功能没有自己的位置，全部挤进两个隐藏入口：**☰ 右键/长按菜单**与**命令面板**。

**五个结构性问题**（详细诊断见 §2）：

| # | 问题 | 一句话证据 |
|---|---|---|
| 1 | 一级入口是隐藏手势 | ☰ 左键 = 侧栏开关；菜单只能右键 ☰ 或长按 500ms（`TitleBar.tsx:80-151`）；手机连应用菜单的「⋯」都去掉了（`App.tsx:3946-3948`） |
| 2 | 菜单成了功能仓库 | 菜单 10+ 项且随插件线性增长；`location: main` 的每个面板都进菜单（`App.tsx:3320-3333`） |
| 3 | 设置承担了「市场 + 插件管理 + 调试」 | 设置 4 个 tab（通用/附件/插件/关于），其中「插件」tab 里还有 已安装/发现/调试 三档（`Settings.tsx:311-404`、`PluginPanel.tsx:185-186`） |
| 4 | 状态栏被当作导航 | 「被引用 / 历史版本 / 🔒 安全」是插件注册的 `location: statusbar` 面板（`AppStatusBar.tsx:52-60`）；手机上它在最底一条，与「状态」语义混在一起 |
| 5 | 同一功能两套载体 | 「插件管理」既在 ☰ 菜单开主区页（`App.tsx:3319`），又在设置 → 插件 tab 里（`Settings.tsx:311-404`）；两处复用同一个 `PluginPanel`（含「发现」市场） |

**成熟产品的共同做法**（§3 取证）：**常驻的可见入口（图标栏 / 底部 tab / 侧栏快捷区）+ 命令面板兜底**，而不是「隐藏手势 + 长菜单」。功能越多，越要把入口**分组**（内容 / 搜索 / 工具 / 设置），而不是并列。

**建议方向**（方案文档展开，不在本文拍板）：桌面加一条**左侧图标栏（Activity Rail）**，侧栏变成**可切换视图容器**；手机加**底部 4 项导航**；「插件 / 市场 / 调试」从设置里拆出来成独立管理页；状态栏回归纯状态。
**约束**：图标栏 / 底部导航只放**内核能力**（笔记、搜索、时间流、插件中心、设置），插件功能走「插件固定区 / 插件中心」；**不启用任何插件时这些固定入口必须全部成立**（§1.8）。

### 1.8 零插件基线（代码路径推断，2026-10-30 补）

> 为什么单列：ZeroNote 的定位是「空内核」，**不启用任何插件**（或全部禁用、或启动自愈把插件禁掉）是必须成立的状态，不是边缘场景。
> 依据：禁用插件直接 `continue`，不注册面板与命令（`src/hooks/usePluginHost.ts:313`）；内置 9 个只是「启动时预装到全局插件根」，不是「强制启用」（`src/kernel/builtin-plugins.ts:93-125`、`docs/功能目录.md` §内置插件）。
> **未实测**：本轮没有真禁用全部插件后截图（会动用户当前插件状态）；以下为代码路径推断，方案落地时必须补一次实测。
> ⚠️ **更正（2026-10-30 · rev173.256）**：已在 B1 落地时补做实测 —— 18 个插件全部禁用 + reload 后，
> 图标栏 5 项 / 侧栏三视图 / 空态 / 插件管理页（18 个全未勾选）/ ☰ 菜单（无插件行）全部成立，

> 结论见 `HANDOFF.md` rev173.256。下表保留为代码路径口径（与实测一致）。

| 区域 | 零插件下保留（内核） | 零插件下消失（插件提供） |

**结论（事实）**：零插件下「内核壳」是完整的——文件树、编辑、搜索、回收站、时间流、设置、插件安装都还能用；但**「标签浏览 / 反链 / 历史 / 同步状态 / 导入导出」这些用户已习惯的入口会整块消失**。新布局若把这些入口写死进图标栏 / 底部导航，零插件时就会出现空壳或死按钮（约束落在方案 [`§1.3`](../docs/UI重布局-方案-2026-10-29.md)）。

> 附注：**标签数据在内核**（`index-api.ts:101` 的 `tagsOf()` 解析 frontmatter），但「标签浏览页」是插件 `tag-panel`。「未打标签 / 今天 / 最近」这类智能分区可以纯内核实现，不依赖 tag-panel。

> 每条 = 现象（事实 + 证据）→ 为什么是问题（判断/引用规范）→ 影响。

### D1（P0）一级入口是隐藏手势

- 事实：桌面 ☰ 左键 = 侧栏开关；菜单要**右键 ☰**（`TitleBar.tsx:129-145`）。手机更彻底：`showMenuButton` 从未传 `true`（全仓 grep 只有 `TitleBar.tsx` 内部定义），所以**手机上没有任何应用级菜单按钮**（卡片右上角的 `⋯` 只是卡片菜单），只能长按 ☰ 500ms（`TitleBar.tsx:80-106`）。
- 判断：违反「识别优于回忆」（Nielsen #6）。用户在手机上找不到「搜索 / 插件 / 设置」不是不会用，是没有入口可见。
- 影响：所有 `main` 面板、市场、插件管理、搜索在手机上都是「藏起来的二级功能」。

### D2（P0）菜单 = 功能仓库，随插件线性增长

- 事实：`menuItems` 直接 `panels.filter(...).map(...)`（`App.tsx:3320-3333`），每个 `location: main` 面板一行。当前内置 9 + 示例 42；手机真机截图（0.7.0）为「已安装 18」（`rev173252-phone-plugins.png`）。
- 判断：菜单是「最后的兜底」，不是「导航」。VS Code / Obsidian 的菜单只放少量高频动作，功能入口在视图容器里。
- 影响：插件越多，菜单越长、越难扫；新装一个插件就多一行，用户无法预期。

### D3（P0）设置承担了市场 + 插件管理 + 调试

- 事实：设置 4 tab（`Settings.tsx:25-31`）；「插件」tab 内有 已安装 / 发现 / 调试 三档（`PluginPanel.tsx:185-186`、`:312-352`），还有「核心能力接管」折叠区、插件日志、「安装 .znp」「启动检查更新」。
- 判断：「设置」应只放**偏好**；「装/卸/升/调」是**管理**，属于独立页面（Obsidian 的 Core/Community plugins 是设置的一级，但「市场 Browse」是其中明确的一节，且有独立入口 `Browse`）。
- 影响：用户找「市场」会先找「插件」，再找「设置」，再找 tab——三层。

### D4（P1）状态栏被当作导航

- 事实：反链 / 历史 / 安全把 `location: statusbar` 当按钮（`AppStatusBar.tsx:52-60`）；反链与历史**同时**注册了 modal 面板（manifest `location: modal`）。
- 判断：状态栏适合「当前状态 + 少量可点状态」（Obsidian 状态栏有字数、模式、同步状态），不适合当功能入口；手机底部一条尤其浪费。
- 影响：手机首屏底部 30px 被 3 个插件入口占住，且与「篇数」混排。

### D5（P1）同一功能两套载体

- 事实：「插件管理」= ☰ 菜单 → 主区页（`App.tsx:3319`）+ 设置 → 插件 tab（`Settings.tsx:311-404`），两处复用同一个 `PluginPanel`（主区页也传了 `onMarketInstall`，`App.tsx:4178`）。
- 判断：两份入口本身可接受（Obsidian 也是侧栏齿轮 + 命令面板），但**语义要一致**；现在一处叫「插件管理」、一处藏在「设置」里，而「装插件 / 逛市场」这件事没有一级入口。

### D6（P1）手机缺一级导航，抽屉只放文件树

- 事实：抽屉 = ZeroNote + ⚙ + 新建 + 文件树 + 回收站 + 库名（`AppSidebar.tsx:52-125`）。搜索 / 标签 / 插件 / 市场 / 设置全部不在抽屉里。
- 对照：Notion 手机底部常驻 `🏠 / 🔍 / 📥 / 📝`（[Notion: Workspaces on mobile](https://www.notion.com/help/workspaces-on-mobile)）；Obsidian 手机侧栏默认收起、Ribbon 在菜单里（[Obsidian: Ribbon](https://help.obsidian.md/ribbon)）。
- 影响：手机端「找东西」只能靠长按 ☰，一次 500ms，且没有视觉提示。

### D7（P1）时间流是「幽灵面板」

- 事实：默认打开（localStorage 默认非 `'0'`，`App.tsx:568-570`），只在 desktop + editor 显示（`:3704`），**没有可见开关**；开关入口是文件树右键与 ☰ 菜单（`:3593-3598`、`App.tsx:3985-3992`）。
- 判断：默认常驻的 300px 面板没有把手/标签，用户不知道它是什么、怎么关。
- 影响：首屏可用宽度被固定扣掉 300px；新用户以为「界面就这样」。

### D8（P2）空态有「开始动作」，但缺「回访入口」

- 事实：空态是 `AppEmptyState` 的**三态**（`AppEmptyState.tsx:41-96`）：无库 → 「选择笔记库」；空库 → 「新建第一条」；有笔记 → 「新建笔记」+ Markdown 速查（14 条）+ 键位提示。
- 判断：NN/g 空态三原则（状态 / 学习线索 / 直达路径）**已满足**；缺的是「最近笔记」这类回访入口（Notion 的 `🏠`、Bear 的 Today/Todo/Untagged 是同一作用）。注意：「标签浏览」是插件 `tag-panel`、「导入」是插件 `import-export`，零插件时这两个入口不该出现（见 §1.8）。
- 影响：首次打开可用；回访时若上次没留标签，只能从文件树重新找。

### D9（P2）标签条没有「新建」与溢出策略

- 事实：`tabs.length === 0` 整条不渲染（`TabBar.tsx:114-115`）；标签条只有标签 + ×，没有 `+`、没有下拉列表。
- 影响：新标签只能靠 `Ctrl+N` / 文件树 / 快速切换；标签多了只能横向滚动。

### D10（P2）独立笔记窗口过于「纯」

- 事实：`note-*` 窗口只有编辑器，无标签条、无侧栏（`App.tsx:3862-3930`，用户 2026-10-20 定「只要编辑窗口」）。
- 判断：这是**已拍板**的取舍，不是 bug；但「拖出后无法在窗口里切笔记」应通过「窗口内快速切换（`Ctrl+O`）」补足，而不是回复侧栏。
- 影响：多窗口工作流需要来回切主窗。

### D11（P2）零插件时插件管理页缺「推荐」

- 事实：把插件全部禁用后，插件管理页是空列表 + 「安装插件包（.znp）」，市场仍在「发现」档可用（`PluginPanel.tsx:335-381`）；状态栏三个入口、菜单里所有面板项**整块消失**（§1.8）。
- 判断：零插件是 ZeroNote 的合法状态（空内核定位），不是错误状态。缺的不是「下一步」（市场能进），而是**推荐**——不知道装什么、哪些是官方内置。
- 影响：预装失败、启动自愈禁用插件、用户手动全禁用三种情况下，第一屏像「功能被删了」，且没有 3 条推荐引导。
- ⚠️ 这条直接约束新布局：**图标栏 / 底部导航不能把插件入口写死**，否则零插件时出现死按钮或空壳。

## 3 成熟产品调研（一手来源）

> 取证日期：2026-10-29。只写能指到来源的结构；拿不到正文的标「正文未取到」，不据此下结论。
>
> 证据分级：**强** = 官方帮助站 / 官方文档仓库原文可读；**中** = 官方页面存在但正文未取到，或仅有官方仓库目录 / 发行说明佐证；**弱** = 仅二手介绍（本表不使用弱证据下结论）。
> 覆盖：桌面 6 家（Obsidian / Notion / Bear / Craft / Logseq / 思源）+ 移动 5 家（Apple Notes / flomo / Notion / Obsidian / 思源）+ 4 条通用规范。

### 3.1 Obsidian（桌面）

**结论：左侧 Ribbon（图标工具栏）+ 左右两个侧栏（各承载插件面板 tab）+ 主区标签 + 命令面板；设置分 Options / Core plugins / Community plugins 三组。**

- Ribbon：在左侧栏内、**左侧栏收起时仍可见**；动作 = 库切换 / 帮助 / 设置，可拖拽排序、可隐藏；手机版 Ribbon 在「菜单」按钮里（长按/短按可配）。（[Obsidian: Ribbon](https://help.obsidian.md/ribbon)）
- 侧栏：左右两个，承载插件创建的 tab（文件浏览器、反链、出链）；桌面可把笔记拖进侧栏；手机/小平板侧栏默认收起，滑动 / 图标 / 命令面板打开。（[Obsidian: Sidebar](https://help.obsidian.md/sidebar)）
- 设置：三个一级组 —— **Options**（General / Editor / Files and links / Appearance / Hotkeys）、**Core plugins**、**Community plugins**（Browse 市场 / Installed / 更新 / Restricted mode）；每个插件行有齿轮直接开插件自己的设置页。（[Obsidian: Settings](https://help.obsidian.md/settings)）
- 多窗口：文件浏览器右键 / 标签右键 / 命令面板 / 拖到目标窗口，均可在新窗口打开；同库窗口互相关联，关闭库窗口会关掉它的 pop-out。（[Obsidian: Pop-out windows](https://help.obsidian.md/pop-out-windows)）
- 状态栏：Obsidian 有状态栏，用于显示字数 / 编辑模式等状态，不作为主要导航（[Obsidian: Status bar](https://help.obsidian.md/status-bar)，正文未取到）。

### 3.2 Notion（桌面 + 移动）

**结论：侧栏 = 功能入口区（Quick Find / Inbox / Settings）+ 内容区（Favorites / Workspace / Shared / Private）+ 资源区（Templates / Import / Trash）。**

- 侧栏顶部、内容之上依次是：Quick Find（`Ctrl/Cmd+P`）、Inbox、Settings；然后 Favorites、Workspace、Shared、Private；底部 Templates、Import、Trash。（[Notion: set up your sidebar](https://www.notion.com/help/guides/the-best-way-to-set-up-your-teams-sidebar-for-clear-organization)）
- 移动端底部导航常驻：`🏠`（Shared/Private/Favorites）、`🔍` 搜索、`📥` Inbox、`📝` 新建页；编辑器上方键盘工具栏含 `+` 块菜单、@、评论、图片、颜色等；页面右上 `•••` 放页面级操作（历史、导出、移动、锁定）。（[Notion: Workspaces on mobile](https://www.notion.com/help/workspaces-on-mobile)）
- 判断：Notion 的「功能入口放侧栏顶部、内容放下面」正是 ZeroNote 侧栏缺的一层。

### 3.3 Bear（macOS / iOS）

**结论：侧栏 = Notes 智能分区（Untagged / Todo / Today / Locked / Archive / Trash）+ Tags；搜索在笔记列表顶部；Quick Open 是独立面板。**

- Notes 分区固定六项；Tags 自动收集、可置顶；Archive 仅在用过归档后出现。（[Bear: About the Sidebar](https://bear.app/faq/about-the-sidebar-in-bear/)）
- 搜索：笔记列表顶部搜索图标（`Cmd+F`）；Quick Open（`Cmd+O`）可搜笔记 / `#tag` / `@location`，手机三指下滑唤起。（[Bear: How to search notes](https://bear.app/faq/how-to-search-notes-in-bear/)）
- 判断：ZeroNote 的文件树缺的正是「智能分区」这一层（今天 / 待办 / 未打标签 / 最近）。

### 3.4 Craft（macOS / iOS）

**结论：侧栏按 Space 组织；空间切换在左上；每日笔记 / 最近 / 收藏是侧栏一级。**

- 每个 Space 独立文档 / 文件夹 / 标签；左上角空间名打开切换器，找不到内容时先确认「在哪个 Space」。（[Craft: Navigation](https://support.craft.do/en/introduction/navigation)）
- 每日笔记是独立入口（[Craft: Daily notes](https://support.craft.do/zh-Hans/plan-and-do/daily-notes)）。
- 2024 年的 2.4.5 更新专门做了「侧栏与导航大改」（[Craft 2.4.5 更新说明](https://documents.craft.me/Ncqv1CbBha9JKq)），说明侧栏 IA 是这类产品的持续投入点。
- 证据强度：**中**（导航页正文只取到「空间切换」一节，侧栏其余结构未取到）。

### 3.5 Logseq（桌面）

- 结构：左侧栏 = Journals / Contents（页面与标签），右侧栏承载插件面板，底部有工具栏；命令面板是主要入口。
- 结论强度：**中**。本次只取到二手介绍（[It's FOSS: Journals and Contents](https://itsfoss.com/logseq-journals-contents/)），官方文档页 30s 超时未取到；不作为强证据。

### 3.6 思源 SiYuan（桌面 + 移动）

- 桌面结构：左中右三栏（文档树 / 编辑区 / 反链与大纲等 Dock），停靠栏（Dock）左右两侧各一排图标按钮；设置里分「外观 / 编辑器 / 导出 / 快捷键 / 关于」等。
- 移动端：官方仓库 `app/src/mobile` 下同时存在 `dock/`、`menu/`、`tabs/` 三套结构（[siyuan/app/src/mobile](https://github.com/siyuan-note/siyuan/tree/master/app/src/mobile)）；发行说明多次修复「dock bar 可见性」（[releases](https://github.com/siyuan-note/siyuan/releases)）；社区帖提到「插件挡住底部导航栏无法打开设置」（[ld246](https://ld246.com/article/1789232912727)），佐证移动端有底部导航且设置在同一区。
- 结论强度：**中**。官方指南站 `siyuan-cn.b3log.org` 当日 DNS 不可达；具体 tab 名称与点击路径**未查到一手来源**，只有仓库目录 + 发行说明 + 社区帖。

### 3.7 移动端横向（Notion / Obsidian / Bear / flomo / Apple Notes）

| 产品 | 一级导航 | 搜索入口 | 新建入口 | 设置入口 |

| Obsidian | 侧栏（默认折叠）+ 右下 Ribbon 菜单（仅非编辑态） | 侧栏 / 命令面板 | Ribbon / 命令 | 右下 Ribbon 齿轮 |

- flomo 手机：首屏是时间流 + 顶部「像聊天窗口一样」的常驻输入框；结构靠左侧抽屉（头像、笔记数/标签数/记录天数、热力图）；搜索在右上角放大镜，搜索页有「有图片 / 有音频 / 有链接 / 无标签 / 去年今日 / 自定范围」快捷筛选；标签不是独立页，在输入框下方 `#` 插入、标签列表中 `···` 管理。（[flomo: 快速记录](https://help.flomoapp.com/basic/quick-input.html)、[快捷搜索](https://help.flomoapp.com/advance/search.html)、[标签](https://help.flomoapp.com/basic/tag.html)、[热力图](https://help.flomoapp.com/advance/notes-graph.html)）

### 3.8 原则（可引用的一手规范）

- **识别优于回忆**：可见的选项优于要求用户记忆（Nielsen 十项启发式 #6 Recognition rather than recall，[NN/g](https://www.nngroup.com/articles/ten-usability-heuristics/)）。
- **命令面板是兜底，不是导航**：VS Code 的 Command Palette 与 Obsidian 的 Command Palette 都存在，但两者同时有常驻图标栏 / 侧栏，功能入口不依赖记忆键位（[VS Code: User Interface](https://code.visualstudio.com/docs/editing/getting-started/userinterface)；[Obsidian: Command palette](https://help.obsidian.md/plugins/command-palette)）。
- **移动端底部导航 ≤ 5 项**：Material 3 navigation bar 的建议是 3–5 个目的地（[M3: Navigation bar](https://m3.material.io/components/navigation-bar/guidelines)，正文未取到，按公开规范写）。
- **设置 = 偏好，管理 = 独立页**：Obsidian 把插件管理做成设置的一级组，但「市场 Browse」在组内有明确入口；Notion 把 Settings 放在侧栏功能区的同一层，而不是藏在二级 tab。

**VS Code（多视图宿主参照，证据强度：中）**：最左「活动栏（Activity Bar）」切换视图容器（Explorer / Search / Source Control / Run / Extensions），侧栏承载当前视图，底部状态栏，命令面板 `Ctrl+Shift+P` 兜底。官方 User Interface 页正文被站内导航截断，结构以官方截图与文档锚点为准（[VS Code: User Interface](https://code.visualstudio.com/docs/editing/getting-started/userinterface)）。它与 ZeroNote 的相似点是「插件扩展 + 命令面板 + 状态栏」，所以「活动栏」这条最值得抄。

### 3.10 可迁移结论（对 ZeroNote）

| # | 结论 | 证据强度 | 对 ZeroNote 的落点 |
|---|---|---|---|
| 1 | 常驻图标栏（Ribbon / Activity Bar）是「功能多但仍可见」的标准解 | **强**（Obsidian 官方 + VS Code） | 桌面左侧加 44–48px 图标栏：文件 / 搜索 / 标签 / 时间流 / 插件 / 设置 |
| 2 | 侧栏 = 可切换视图容器，不是「固定文件树」 | **强**（Obsidian Sidebar / VS Code Views） | 侧栏顶部加视图切换（或由图标栏驱动），文件树只是其中一视图 |
| 3 | 侧栏顶部放功能入口（搜索 / 收件箱 / 设置），下面才是内容 | **强**（Notion） | 侧栏头部：搜索框 + 收起按钮 + 设置；内容区：智能分区 + 文件树 |
| 4 | 智能分区（今天 / 待办 / 未打标签 / 归档 / 回收站）降低「找笔记」成本 | **强**（Bear） | 文件树上方加 3–5 个智能视图；数据已在内核索引里 |
| 5 | 手机必须有常驻底部导航（3–5 项） | **强**（Notion 移动 / M3 / M2） | 首页 / 搜索 / 新建 / 标签（或插件）+「更多」 |
| 6 | 移动端长按/滑动手势只做加速，不做唯一入口 | **强**（Bear/Notion/Obsidian 都把搜索放可见处；M7） | 保留长按 ＋/☰，但不再承担唯一入口 |
| 7 | 设置与「插件管理/市场」分层 | **中**（Obsidian 三组） | 设置（偏好）+ 插件中心（已安装/市场/调试）两个页面 |
| 8 | 状态栏只放状态，可点状态也不当主入口 | **中**（Obsidian/VS Code） | 状态栏保留字数/库/同步状态；插件入口移到图标栏或侧栏 |
| 9 | 空态是导航的一部分 | **中**（Notion/Bear/ZeroNote 空态对比） | 起始页加「最近 / 未打标签 / 打开库 / 帮助」；标签与导入只在插件启用时出现 |
| 10 | 多窗口入口应可发现（右键/拖拽之外给菜单项） | **中**（Obsidian pop-out 有 4 条路） | 标签右键已有；补「窗口」菜单与投放提示 |

## 4 对 ZeroNote 的架构约束（事实，方案不能违反）

1. **插件是功能单元**：面板 `location` 有 6 类（`main` / `sidebar` / `statusbar` / `modal` / `editor-toolbar` / `editor-topbar`），`sidebar` 与 `main` 当前都渲染到主区（`App.tsx:3671-3680`）——改布局时必须给 `sidebar` 一个真实载体，或明确废弃该值。
2. **内核只做四件事**：`.md 读写 / 编辑 / 本地存储 / 插件宿主`；搜索索引、标签、反链都在插件或内核半边（`docs/架构原则-2026-10-13.md`）。
3. **手机单窗口**：不用系统多窗口（`D-005`），所有「窗口」在手机上只能是整窗接管或全屏页。
4. **自绘标题栏 + 自动隐藏**：改标题栏区域等于改窗口拖动区（`data-tauri-drag-region`），要一起验。
5. **无账号 / 无服务端**：不引入「收件箱」这种需要推送模型的入口，除非本地实现。
