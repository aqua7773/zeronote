## 0 结论（1 分钟版）

方案在「入口可见性 / 信息架构 / 零插件」三条主线成立；用原则逐条核对后，**发现 6 个方案没覆盖的实际缺陷 + 6 个一致性/命名类改进**：

| 级别 | 编号 | 问题 | 依据 |
|---|---|---|---|
| **必修** | O1 | 状态栏可点小部件高 22px < 24（水平 gap 12px 达标，但目标本身不足） | WCAG 2.5.8（AA，24×24 或间距例外） |
| **必修** | O2 | 侧栏/时间流的分隔线**只能拖**，无键盘/单指替代 | WCAG 2.5.7（AA，拖拽必须有单指替代） |
| **必修** | O3 | 状态栏 / 手机底部导航可能完全遮住键盘焦点 | WCAG 2.4.11（AA，焦点不被作者内容完全遮挡） |
| **必修** | O4 | 设置 → 插件 → 插件中心 → 市场 → 详情 = 4 层披露 | NN/g：>2 层披露可用性通常很低 |
| 应做 | O5 | 插件页打开可能 >400ms 无反馈 | Doherty 阈值（<400ms 才感觉「即时」） |
| 应做 | O6 | 禁用插件 / 删除插件 / 恢复备份缺统一「撤销」 | NN/g #3 用户控制与自由、#5 错误预防 |
| 应做 | O7 | 「插件管理 / 插件中心 / 发现 / 市场」四种叫法 | NN/g #2 用用户的语言、#4 一致性 |
| 应做 | O8 | 新图标栏按钮无快捷键提示 | NN/g #7 灵活高效、#10 帮助 |
| 应做 | O9 | 手机底部导航贴系统手势区，且有拖拽目标 | WCAG 2.5.7 + Android 预测性返回 |
| 应做 | O10 | 空态缺「最近笔记」回访入口（三态与主行动已满足） | NN/g 空态三原则（状态/学习已达标，补回访路径） |
| 建议 | O11 | 桌面「⋯ = 更多操作」与手机「⋯ = 更多页」语义不同 | 内部一致性 |
| 建议 | O12 | 「设置」三处入口（图标栏/菜单/`Ctrl+,`）超出「1 主 + 2 加速」 | 方案 §4 自定规则 |

**一句话**：方案的「骨架」不用改；要补的是**可访问性硬指标（O1–O3）、披露层数（O4）、反馈时延（O5）、破坏性操作（O6）**。

## 3 优化点（可直接进批次）

### O1 状态栏可点小部件 < 24px（必修）

- 事实：`.zn-statusbar` 高 22px（`styles.css:1330`），`location: statusbar` 插件小部件是按钮时命中高度 ≤22；水平 `gap: 12px` 达标，但目标高度不足 24（垂直方向紧贴状态栏上下边）。
- 原则：WCAG 2.5.8 —— 目标至少 24×24，或 24px 圆与相邻目标不相交。
- 动作（B4）：状态栏改为**纯状态**；需要点击的状态（同步）用 ≥24 高的 chip 并给 8px 间距；反链/历史移到文档工具条（方案已有）。
- 验收：CDP 量 `getBoundingClientRect()`，所有状态栏内可点元素 ≥24×24 或有 ≥8px 间距。

### O2 分隔线只能拖（必修）

- 事实：`AppResizer.tsx:23-42` 只监听 `pointerdown/move/up`，`role="separator"` 但没有键盘处理；侧栏宽度、时间流宽度都是这套。
- 原则：WCAG 2.5.7 —— 拖拽操作必须有单指非拖拽替代；F108 明确把「只能拖」列为失败。
- 动作（B1）：分隔线补 ①方向键 ±8px、Home/End 到 220/420、②双击恢复默认宽度、③`aria-valuenow/min/max`；或退一步在设置里给「侧栏宽度」三档（窄/中/宽）。
- 验收：只用键盘能改宽度；`aria-valuenow` 随拖动/按键更新。

### O3 粘性底栏遮焦点（必修）

- 事实：状态栏 22px `flex: none` 在流内（不遮挡）；但手机底部导航若用 `position: fixed`（方案草图），编辑态键盘弹起时与工具栏叠加；设置页滚动到底时最后一行可能贴住底栏。
- 原则：WCAG 2.4.11 —— 焦点组件不得被作者内容完全遮挡；sticky footer 是 F110 典型失败。
- 动作（B2）：底部导航用 `position: sticky` 或给内容区 `padding-bottom: var(--zn-bottomnav-h)`；编辑态隐藏底部导航（方案已写「编辑态不回导航」，需明确）；`scroll-padding-bottom` 兜底。
- 验收：Tab 到底部最后一行，焦点矩形完整可见。

### O4 披露 4 层（必修）

- 事实：方案 §5 仍保留「设置 → 插件 → 打开插件中心」；插件中心内再「市场 → 详情」。
- 原则：NN/g 渐进披露 —— 超过 2 层通常低可用性；进阶路径要明显。
- 动作（B3）：设置里的「插件」组**只留「启动检查更新」开关 + 一行文字链接**，且这个链接与图标栏 🧩 等价；真正入口只保留图标栏（1 层到插件中心，2 层到市场，3 层到详情 = 详情页内不再套 tab）。
- 验收：从图标栏到「装一个包」≤2 次点击；从设置到插件中心 ≤1 次点击（链接）。

### O5 插件页首帧（应做）

- 事实：插件面板 `renderPanelSafe` 同步执行插件 `mount`；重插件（AI/导图）首帧可能 >400ms。
- 原则：Doherty 阈值 —— <400ms 才感觉即时；超过要给进度反馈。
- 动作（B1/B3）：打开工具页先渲染标签 + 内容骨架（`延迟 150ms 显示，<150ms 不闪`），>1s 显示「正在加载 <插件名>…」；失败走现有 `pluginError` 通道。
- 验收：AI 面板冷开录屏，首帧 <400ms 或骨架可见。

### O6 插件类破坏操作（应做）

- 事实：禁用插件会让已开面板消失；删除 `.znp`、恢复备份都不可撤销。
- 原则：NN/g #3/#5 —— 破坏操作要能退出/撤销，常见可逆操作不弹窗。
- 动作（B3/B6）：禁用插件 → toast「已禁用 X · 撤销」10 秒；删除插件 → 二次确认（文字说明影响）+ 进回收站（若可行）；恢复备份 → 先自动备份当前库。
- 验收：禁用后面板关闭且 toast 可撤销；删除弹确认。

### O7 命名统一（应做）

- 事实：菜单「插件管理」、设置 tab「插件」、面板内「发现」、文档「市场」。
- 原则：NN/g #2 用用户词、#4 内部一致。
- 动作（B3）：统一为 **插件中心**（页面名）/ **插件市场**（发现 tab 名）/ **已安装**（列表名）；代码 id 不变。
- 验收：全 UI 文案检索无「发现」；文档同步。

### O8 快捷键提示（应做）

- 事实：菜单项有 `hint`；新图标栏按钮只有 tooltip 名称。
- 原则：NN/g #7 灵活高效、#10 帮助。
- 动作（B1）：tooltip 写「笔记（Ctrl+1）」这类；至少给 `Ctrl+\`（侧栏）与 `Ctrl+,`（设置）。
- 验收：hover 1s 出现带快捷键的 tooltip。

### O9 手机底部导航与系统手势区（应做）

- 事实：方案底部导航 56px 贴底；Android 手势导航区约 24–32px。
- 原则：WCAG 2.5.7（拖拽不能是唯一方式）+ Android 预测性返回（系统手势区内不放拖拽目标）。
- 动作（B2）：`padding-bottom: env(safe-area-inset-bottom)`；底部导航只放点击目标，不放滑动/拖拽；侧滑返回与抽屉手势二选一（抽屉手势仅首页生效）。
- 验收：真机手势返回不误触底部导航；底部内容不被手势条遮挡。

### O10 空态缺「回访入口」（应做）

- 事实：现状空态已经是**三态三原则**（`AppEmptyState.tsx:41-96`：无库→选库、空库→新建第一条、有笔记→新建+速查+键位），**不缺直达动作**。缺的是「最近笔记 / 上次打开」这类回访入口。
- 原则：NN/g 空态三原则的「直达关键任务的路径」已满足；这里补的是 `Peak-End`/回访效率，不是补「直达」。
- 动作（B4）：空态在「新建」下方追加「最近打开的 3 篇」（内核 `recent.ts` 已有数据），零插件下也成立；「导入」仅在 `import-export` 启用时出现。
- 验收：禁用全部插件，空态有「新建 / 选择笔记库 / 最近 3 篇」；启用导入插件后多出「从文件导入」。

### O11 `⋯` 语义（建议）

- 事实：桌面上「⋯ = 当前文档更多操作」，手机方案「⋯ = 更多页（tab）」。
- 原则：内部一致性。
- 动作（B2）：手机底部第 4 项用「更多」文字 + 汉堡/网格图标，不用 `⋯`；`⋯` 只保留「当前对象更多操作」。
- 验收：文案/图标评审。

### O12 设置入口数量（建议）

- 事实：图标栏 ⚙、菜单「设置」、`Ctrl+,` = 3 个入口。
- 原则：方案 §4 自定「1 主 + 2 加速」；三个正好踩线，但菜单里的「设置」与图标栏重复且低频。
- 动作（B1）：菜单去掉「设置」项（保留 `Ctrl+,` 与图标栏）；或保留但标 `Ctrl+,`。
- 验收：入口矩阵与实现一致。
